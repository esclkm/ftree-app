# Правила приложения ftree — для любого дерева

Общее для всех деревьев, с которыми работает приложение: этажи данных, порядок работы, карточки, проверки, команда
`rodo`. Подключается из `CLAUDE.md` дерева строкой `@<путь к приложению>/tools/CLAUDE.app.md`; правила и ошибки
самого дерева, его решения и где лежат его документы — в его `CLAUDE.md`. Карта для человека — `START_HERE.md` дерева.

## Где что

| Этаж | Что | Править? |
|---|---|---|
| `1_sources/family/` · `found/` · `others_trees/` | оригиналы семьи · найденное Claude · чужие деревья | **нет** (кроме описей `00_ОПИСЬ_*.md`) |
| `1_sources/inbox/` | новое, не разобрано | да, потом разнести |
| `2_transcripts/` | текст источника слово в слово; документы людей; обработанные фото | только расшифровку |
| `3_research/tree/` | дерево: people, places, sources, events, biographies | да — по правилам |
| `3_research/<папка поиска>/` | поиск, запросы, находки, анкеты; заметки дерева к навыкам — `навыки/` (`rodo skill-notes <навык>`) | да |
| `4_outputs/` · `tools/` · `web/` | сайт и выдача · скрипты (пути — `tools/scripts/paths.py`) · код сайта | да |

Папка поиска — `tree.research_dir` в `ftree.toml`; корень и ветки рода — там же. Скрипт — одной командой `rodo <имя>`
из любой папки: имя через дефис (`rodo check-cards` = `tools/scripts/check_cards.py`, Python — `.venv` проекта), список —
`rodo list`. Нет `rodo` в PATH — `tools/rodo link`.

## Навыки — загрузить до работы

`biography` (биографии, линия жизни) · `dates` (даты, два календаря) · `card-rules` (карточка, факт, кандидаты,
слияние, документы) · `photos` · `site` (сайт, заметки с сайта) · `tree-maintenance` (проверки) · `person` / `dig`
(о человеке, следующий шаг) · `search-after-update` · `archive-*` (сайт архива — сначала его навык) · `metric-search` (найти человека в скачанных метриках) · `archive-belarus-graves` (где похоронен в Беларуси) · `social-search` (родня в соцсетях: ссылки, фото, даты) · `audio-interview` ·
`orchestration` (кто что делает: помощник, скрипт, `llm.py`; планы и журнал) · `shared-browser` (общий Chrome проекта:
своя вкладка у сессии, что по очереди) · `humanizer-ru` (текст для человека:
отчёт, биография, коммит, письмо, ответ владельцу дерева — без жаргона и канцелярита).

У навыка могут быть **заметки этого дерева** — что здесь уже искали, нашли и решили: `rodo skill-notes <навык>`.
Навык — метод; заметки — прочитать перед работой.

## Экономно (подробно — навык `orchestration`)

- Картинки и PDF — помощнику (`Agent`, haiku/sonnet, ответ до 20 строк) или скрипту. Браузер — `get_page_text`/`find`,
  снимок — уменьшенный. Вывод команд — `| head`.
- Распознавание — скриптом (`asr_pipeline`; `claude -p` только через `tools/scripts/llm.py`). Дважды
  одно не распознаём. Перевод, сверку аудио, черновики метрик и машинописи — GitHub Copilot (свой лимит):
  `llm.py … --model copilot:<модель>` (навык `orchestration`).
- Одна задача — одна сессия; ~150 тыс. токенов или ~150 шагов — записать сделанное и предложить новую.
- **Не искать дважды:** перед заходом на сайт архива — `searched.py frames <плёнка> <кадры>` / `query "<запрос>"` /
  `who "<имя>"`; после захода — `searched.py add …` (журнал `<папка поиска>/ИСКАЛИ_журнал.tsv`, его видит `known.py`);
  у строки — состояние: нашлось / пусто / частично / не дошло / закрыто / нет указателя (по значку итога или `--state`);
  «не дошло» — не ответ, куда вернуться — `searched.py open`.
- Абонемент архива — только качать; читать потом. Пароли, cookie, токены владельца дерева не спрашивать: вход — он сам.

## Порядок работы

**источник → расшифровка → факт в карточке → биография**

1. Новый файл — `1_sources/<family|found|others_trees>/…`, имя по содержанию `Кто_что_дата-№`.
2. Расшифровка — `2_transcripts/` (`archive-ocr`, `audio-interview`).
3. Факт — в карточку, одна строка — один факт с источником и уверенностью (`card-rules`).
4. Рассказ — в биографию `3_research/tree/biographies/<Имя карточки> — биография.md` (`biography`).
5. Потом — `tree-maintenance`.

Вопрос к дереву — `tree.py who|kin|find|place|src|mentions|gaps|targets` (вместо grep). Всё обновить — `update_all.py`.
На чём держится каждое звено (📄 документ / 👪 семья / 🗂 старое дерево / 🧮 вывод) — `proof.py ["<имя>"]`; сводка
`3_research/tree/_ДОКАЗАТЕЛЬСТВА.md` — пересобрать `proof.py --write` после правки связей (руками не править).
Чем подтверждены рождение, брак, смерть и рождения детей у предков (📄 запись / 📃 документ / 👪 / ✖) и где документа
нет — `coverage.py ["<имя>"]`; сводка `3_research/tree/_ДОКУМЕНТЫ_ПО_ЛЮДЯМ.md` (`--write`, собирает и `update_all.py`).
**Сверка со старым — до слов «нашлось», «новый», до новой карточки и до отчёта:** `known.py "<имя> <отчество>|<вариант>"` по
каждому человеку и факту — отчёты `findings/`, план, карточки, расшифровки. Было — писать «известно с <дата>, <файл>» и
дописать недостающее из старого; «нигде» — только тогда «новое». В отчёте — таблица «было раньше / новое сегодня».
Поменялись место, годы, работа, служба, родня — оценить поиск (`search-after-update`); что ещё искать —
`<папка поиска>/ПОИСК_ДАЛЬШЕ.md` (вход) → `ПОИСК_ОНЛАЙН` / `ПОИСК_ОФФЛАЙН` / `ПОИСК_СДЕЛАНО`. Те же задачи по архивам — `ПОИСК_ПО_АРХИВАМ` (собирает `search_by_place.py`, руками не править). Перед разговором с родственником или архивом — `dig`. Текст «# Заметки к
родословной — …» (или его PL / ES / EN вариант; правки с сайта) — разбирать по навыку `site`, как обычную правку.

## Правила дерева — ядро

- **Упоминание = карточка — только у звена.** Карточку получают те, кто в записи о нашем человеке или о прямом звене
  (родители, супруг, ребёнок); связь father/spouse — только по документу. Поручители и крёстные — строкой в факте этой
  записи. Записи о боковых ветках, пока звено не доказано, — только в отчёт: дети недоказанных родителей родства не
  докажут. Уровень `kinship` — не выше, чем у звена, через которое человек связан с нами. Чужие деревья — подсказка, не ветка.
- **Подозрение — полем** (`maybe_same`, `maybe_kin`; «нет» — `not_same`, `not_kin`), не фразой; **слияние** — только
  `merge_cards.py --why` с доказательством. Подробно — `card-rules`.
- **Номер важнее имени:** связь — `[[Имя]]` и `*_id` вместе. Ветки `lineage` руками не правим (`assign_lineage.py`).
- **Догадка — не факт:** `уверенность: низкая` и на чём держится; выведенная фамилия — `surname_inferred`. Отчества в
  карточки не вносим. Имена не «исправляем» — пишем, как сказано.
- **Правка владельца дерева — молча:** без «X исправил/сказал»; текст — будто ошибки не было. «X считает» — не правка, а
  мнение X (`по словам …`, уверенность низкая/средняя).
- **Происхождение источника** видно везде: `семья` > `найдено` > `чужое дерево` > `вывод проекта`.
- **Событие на двоих — у обоих сразу:** брак, развод, рождение ребёнка правим одной правкой у обеих сторон — карточки и линии жизни мужа и жены, родителя и ребёнка, с одной датой (`check_family_sync.py`, `--fix` — строка второму супругу).
- **Одна биография — один человек**, файл зовут как карточку. Даты — по GEDCOM (`dates`); две даты до 1918 с
  разницей 12–13 дней — сначала проверить стиль.
- PDF и HTML из .md не храним — собираем по просьбе, не коммитим.

## Нельзя

- Править или переименовывать оригиналы в `1_sources/` (кроме `inbox/` и описей; новое аудио сжимает `audio_watch.py`); трогать оригинал фото.
- Выдавать находку в интернете за семейный источник.

## Проверки — по нулям (пояснения — `tree-maintenance`; все разом, как на GitHub, — `tools/ci.sh`)

```bash
rodo check-tree; rodo check-cards; rodo check-links
rodo card-doctor --fix; rodo check-lifeline; rodo check-lifespan
rodo check-bio; rodo check-dates; rodo documents check
rodo myheritage-update lint; rodo check-search-plan; rodo check-family-logic
rodo check-family-sync; rodo check-names; rodo check-fact-places
rodo check-fact-dates   # отчёт: дата в линии жизни или событии без факта — решить по источнику
rodo test
```

**Сохранить и отправить — одной командой:** `tools/ship "текст" <свои файлы>` (без разбора вывода хуков: новые фото,
PDF, звук — в опись сами, в облако — в фоне после коммита; пишет «✅» или что сломалось). Новое аудио — просто скопировать
в `1_sources/family/audio`: распознает, сожмёт и отправит слежение (`audio_watch.py status`). Перед коммитом большой правки — `self-review`. Новый скрипт читает карточки через `tools/scripts/cards/`, то, что
видит посетитель, — через `site_data/`. Хуки git без ИИ: перед коммитом — ссылки на переименованное (`moves.py`,
`anchors.py`), ветки, «Рассказ»; перед push — все проверки, как на GitHub (`tools/githooks/pre-push`), и при push в master — сборка и выкладка сайта (если включено в `ftree.toml`); что отстало — в сводке при старте
(`sync.py`). Старый путь → где сейчас: `rodo moves where <путь>`.
