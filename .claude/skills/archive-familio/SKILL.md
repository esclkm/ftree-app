# Familio — люди наших деревень

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes archive-familio`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed archive-familio 2>/dev/null || rodo skill-notes --embed archive-familio 2>/dev/null || true`

**Что это.** Сайт, где к каждой деревне привязаны справочники разных лет (сколько дворов и жителей, волость, приход,
казённая или помещичья деревня) и люди: из оцифрованных списков и из деревьев других исследователей. Без входа видна
большая часть; ссылки на книги, сканы и цифры по деревням — после входа (вход — только Павел, сам).

**Главное правило — сначала API, потом браузер.** Не листать страницы по 12–20 записей. Запросы описаны в
github.com/dmalch/go-familio (`API.md`) — неофициальный клиент, разобранный по запросам самого сайта.

## Без входа — скриптом (`tools/scripts/familio.py`, без ИИ)

```bash
rodo familio places        # наши деревни → номера на Familio (по координатам карточек мест)
rodo familio add Подгай <uuid>   # деревня без координат — номер руками
rodo familio dump          # люди каждой деревни, одним запросом, пауза 3 с
rodo familio grep Гаркуша Заруба  # поиск по скачанному, без сайта
rodo familio trees         # чужие деревья в наших деревнях
```

- Выгрузки (имена тысяч чужих людей) — **вне git**: `$ARCHIVES_LOCAL/text/familio/settlements/`.
  Номера деревень — `1_sources/found/archives_online/familio/settlements.json`.
- Открытые запросы: `GET /api/v2/persons?settlement=<uuid>&itemsPerPage=300&page=N` (все люди деревни);
  `GET /api/v2/map/settlements/points?westLng=&southLat=&eastLng=&northLat=&title=` (деревни с координатами);
  страница записи `familio.org/catalogs/<catalogKey>/persons/<uuid>` — «Оригинальная запись» видна без входа.

## С входом Павла — только в браузере проекта, ключ не выносить

- Ключ входа (JWT) лежит в `__NEXT_DATA__` страницы (`"token":"eyJ…"`); запросы — `fetch` в самой странице с
  `Authorization: Bearer …`. **В файлы, команды и отчёты ключ не писать.**
- «Библиографическая ссылка» и «Скан» (viewer.rsl.ru — открывается из Польши) — на странице записи справочника.
- **«Совпадения»:** `POST /api/v2/users/<uuid Павла>/matches/get-by-filters?page=&itemsPerPage=` с телом
  `{"person":[],"user":[],"catalog":[],"date":[],"status":[],"minTotalScore":1,"maxTotalScore":99}` — все 7 полей
  обязательны. Подтверждать/отклонять — только по слову Павла: `POST …/matches/reject-by-ids` (так же
  `confirm-by-ids`, `undecide-by-ids` — вернуть), тело — **голый массив** uuid совпадений `["…","…"]` (не `{ids:…}` —
  400), ответ 204; партиями по 25 с паузой. Подробная запись справочника (губерния, уезд, волость) — в `__NEXT_DATA__`
  страницы `familio.org/catalogs/<key>/persons/<uuid>`: `catalogPerson.attributes.geography` или поля `record`
  (`region`, `district`, `volost`); у человека из дерева — `GET /api/v2/persons/<uuid>/events`. 250 записей с паузой
  4 с прошли без 403 (27.10.2026). **Ловушка:** у людей из метрик «фамилия» — имя отца, Familio достраивает отчество
  и сыплет тёзками по всей России; судить по месту и родне (`findings/_familio_совпадения_2026-10-27.md`).
- Запись в дерево Павла (люди, браки, события, источники) — через go-familio / terraform-provider-familio; **только по
  просьбе Павла**, сначала сравнить с нашим деревом.

## Дерево Павла на Familio ← наше дерево

Перенос нашего дерева на Familio (сколько правок, когда и что было — в заметках дерева). Порядок:

1. `rodo familio-sync fetch <папка>` — дерево Павла с Familio, открытые данные, без входа (~15 мин).
2. `rodo familio-sync plan <папка> --save-snapshot` — сравнение; пары берутся из слепка
   `3_research/tree_data/familio_match.json` (наша карточка → человек на Familio), угадываются только новые.
   Смотреть в `plan.json`: `year_conflicts`, `maybe_hidden`, `placeholders`, `extra_on_familio`. Пары руками — `overrides.json`.
3. Сжать план (номера вместо uuid) и передать в страницу Familio **текстом, частями, с sha256** — буфер обмена и локальный
   приёмник защита запрещает (ключ входа не выносить). Выполнить `tools/scripts/familio_apply.js`: сначала `{dry:true}`,
   потом `{limit:5}` и проверить на сайте, потом всё. Запись — только с разрешения Павла в чате.

### Уроки прошлых переносов (подробно, с датами и людьми — в заметках дерева)

- **Сжатие плана** — `familio_sync.py pack <папка>` (выкидывает заглушки). **`familio_apply.js` запускать во встроенном
  браузере приложения** (javascript_tool): Chrome проекта (`browser_cdp.mjs`) не выполняет код, где есть слово «token»,
  — защиту не обходить. Запуск без await (`window.__run = familioApply(…)`), ход — по `window.__fa.done`; состояние
  (`__fa.map`) сохранить в `<папка>/apply_state.json`. Список под входом грузится до ~60 с, а `javascript_tool` ждёт
  45 с — поэтому только без await. Список идёт медленно (~20 с на страницу): ждать, не повторять.
- **Без входа Familio отдаёт только часть дерева** (около половины; остальным — 403 на `/persons/<uuid>/events`), а
  после ~100 запросов подряд режет скрипт целиком (403, обрывы) — `fetch` без входа полного снимка не даёт.
- **Снимок — под входом, в странице** (встроенный браузер): список `/api/v3/persons` + `/api/v2/persons/<uuid>/events`
  и `/basic` с ключом из `__NEXT_DATA__`, пауза 0,7 с (~17 мин на 600 человек, при медленном сайте — до часа); скрытых
  (`privacyType: "invisible"`) не брать — `familio_apply.js` их не считает. Файл — `<a download>` (с согласия Павла) в
  `sync_<дата>/familio_tree.json`. **Скачать файл из встроенного браузера можно только настоящим щелчком:** `<a download>`
  из скрипта молча не срабатывает — поставить ссылку на страницу и нажать её (`computer left_click`).
- Под входом у участников событий видны номера и скрытых людей — перед `plan` такие `personUuid` (нет в списке)
  заменить на `null`, иначе `plan` падает (KeyError).
- **Список — не больше чем по 100** (с 30.10.2026 `itemsPerPage=300` → 400 «Invalid parameter»).
- **Люди, созданные прошлым переносом, которых нет в снимке:** план создаст их второй раз, а сверка списка («uh») не
  сойдётся. Перед запуском положить в страницу `window.__fa = {map: <map из прошлого apply_state>, done: {<номера строк
  плана про этих людей>: true}}`. План от старого снимка — минус всё, что уже сделано (`plan_full.json` прошлого
  переноса). Пары после записи — сразу в `familio_match.json`.
- **Рождение и смерть:** `familio_apply.js` смотрит события человека: есть — PUT с `X-Base-Version` (дата и место из
  плана, родители добавляются), нет — POST; новому человеку дата — сразу в теле создания. 400 на PUT (событие только
  что поменялось через другого участника) — перечитать `updatedAt` и повторить. Дату рождения сервер пишет в пустое
  рождение — второго не появляется. Пустое «рождение» без даты и родителей у нового человека из плана убрать.
- **Ловушка фамилии:** `names()` берёт первое русское «другое имя» карточки — план может поставить прежнюю фамилию
  рода или девичью вместо нашей; просмотреть и поправить руками в plan.json.
- **Люди без фамилии** («Остап (отец Ивана Остапова)») — создаём одним именем; заглушка — только если слово
  повторяется в скобках фамилией («Nowak (отец Jan Nowak)»). Человек только с фамилией — имя «?», фамилия как есть
  (`pack` такого не считает заглушкой; заглушка — «?» без фамилии). Карточка «только фамилия» не находит заглушку
  «(Фамилия) ?» на Familio, и план создаёт второго — пары руками в `overrides.json` (по родителям и супругу), имя
  оставить «?».
- Живым годы рождения не грузим (как на MyHeritage): дату рождения живым план ставит — убрать; у живых, уже стоящих на
  Familio, пустое «рождение» не создаём — будет дубль события.
- Двое на Familio, которых у нас слили в одного, — их брак и родители ждут слияния там; пропустить.
- После записи проверка без нового снимка: у затронутых людей не больше одного рождения и одной смерти.

После записи — `familio_sync.py fetch <новая папка>`, `plan` (должны остаться только заглушки) и `check <папка>` — связи: родители, дети, супруги, дубли рождения; заглушки «… ?» с прошлой выгрузки не трогаем. Лишнюю связь сравнение не убирает: правка события — `PUT /api/v2/persons/<uuid>/events/<uuid события>` с `X-Base-Version: <updatedAt>` и полным телом события (только с разрешения Павла).

Правила сравнения: имя — наше; то же имя иначе записанное (Kowalczyk/Ковальчик) не трогаем; фамилию по мужу, если она уже
есть на Familio, не трогаем; отчества с Familio оставляем; лишних не удаляем; «(Uss) ?»-заглушки не создаём.
Фото не переносятся (нужна загрузка файла в страницу — не сделано).

## Раздел «Архивные документы»

`familio.org/knowledge-base/archive` — не сканы, а каталог описаний (архив → фонд → опись → дело), заполняют
пользователи. Без входа: `GET /api/v2/organizations?itemsPerPage=1000` (256 архивов), `funds|registers|cases?organization=<uuid>`.
Что по своим местам уже смотрели и что там пусто — в заметках дерева. Перепроверять — не раньше чем через полгода.

## Рядом: genindex.ru — кто уже расписал источник (из vdov, CC BY 4.0) [В]
Указатель пользовательских индексов (любительские выписки справочников, списков, книг) с фильтром по региону, типу документа
и годам; открыт отовсюду, без входа. Дополняет Familio: там справочники, а здесь видно, какой именно источник кто-то уже
разнёс по персонам. Перед тем как читать книгу или выписывать список самим — посмотреть. Подробнее — `archive-gaso`
(раздел про сторонние указатели). У нас не проверялся.

## Ловушки

- **Поиск по фамилии на сайте нечёткий:** выдаёт созвучные («Ковальчук» → Ковальчик, Коваль). Точные — первыми.
- **Чужие деревья ставят людей не на ту точку:** на одноимённую деревню соседнего уезда, а приход в записи — другой.
  Деревню проверять по приходу и волости, не по точке.
- **Столбцы справочников мест слипаются в тексте страницы** (`17862129`) — читать по ячейкам (у каждой цифры свой
  элемент). Так один раз уже перепутали дворы деревни в справочнике.
- Год рождения у записи справочника Familio считает сам: год приговора минус возраст. В карточку — промежутком.
- Дерево Павла на Familio — сначала старая выгрузка (без дат у многих) → «Совпадений» мало и все слабые.
- **«Совпадения» сыплют тёзками,** пока у людей нет места: Familio даёт очки за место рождения (`detailedScore.birthPlace`),
  а у людей из метрик его нет; «фамилия» там — имя отца («Остапов» = сын Остапа). Такие пары отклонять пачкой.
  Мусор — 2–5 %; фильтр «Вероятность» от 10 % его отсекает.
- **Места рождения и смерти на Familio** (02.11.2026): `familio.py places --wide` ищет номера мест людей на Familio,
  в том числе городов; не нашлось по имени — печатает ближайшие точки, номер — руками через `add`. Городов США,
  Аргентины, Парагвая на Familio нет. Деревня бывает под старым или искажённым названием — искать и по нему. Пустое место в событии
  Familio — `settlement: {uuid: null}`, не `null`. Живым место рождения не ставим. Запись — во встроенном браузере:
  GET событий человека → PUT того же события с `settlement` и `X-Base-Version` (дата и участники — как были).
