# Чужие деревья на MyHeritage — как читать

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes archive-myheritage-trees`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed archive-myheritage-trees 2>/dev/null || rodo skill-notes --embed archive-myheritage-trees 2>/dev/null || true`

**Что это.** На MyHeritage у каждого нашего человека бывают «совпадения» (Smart Matches) — тот же человек в
чужом дереве. Совпадение показывает одного человека и его ближайших, а остальное дерево — на страницах профилей.
Всё читается **в Chrome проекта** (`browser_cdp.mjs`, порт 9333, Павел вошёл в MyHeritage), без правок на сайте.

**Чего не делать.** «Save to your tree» / «Extract info manually» / «Confirm» — это правки дерева Павла: только по его
«да» на каждое действие. Данные из чужого дерева идут **в карточки** (низкая уверенность, источник — карточка дерева
в `3_research/tree/sources/`), на сайт MyHeritage их потом выгружает `tools/mh push`. Связи father/spouse по чужому
дереву не ставим — строкой факта (`card-rules`).

## Шаг 1. Наши люди с совпадениями — одним запросом

Наш сайт — `<наш сайт>` (номер вида `OYYV…` из адреса нашего дерева на myheritage.com; он же — в заметках дерева), дерево 1. Из любой страницы myheritage.com (`browser_cdp.mjs eval`):
```js
(async()=>{const u="/FP/API/DiscoveryHub/fetch-matches-by-people.php?action=getResults&s=<наш сайт>&lang=EN&familyTreeId=&offset=0&count=20&filtersState%5BmatchType%5D=2&filtersState%5BmatchStatus%5D=2&filtersState%5BconfirmedByOthers%5D=0&filtersState%5BsortBy%5D=4&filtersState%5Bquery%5D=Kowalczyk&is_ignored=0";
 const j=await (await fetch(u,{credentials:"include"})).json(); return j.data.individualsWithMatches.map(i=>i.individualId+" "+i.fullName+" matches="+i.numberOfMatches).join("\n")})()
```
- `matchType`: 2 — Smart Matches (деревья), 1 — записи. `query` — фамилия или имя; пусто — все.
- `matchStatus` в этом запросе: 2 — все; на странице человека — 8 подтверждённые, 32 ждут, 64 новые, 16 отклонённые.
- `individualId` — номер нашего человека на сайте (он же в `snapshot.json` от `tools/mh pull`).

## Шаг 2. Совпадения одного человека → сайт и номер в чужом дереве

Страница: `/discovery-hub/<наш сайт>/matches-for-person/<наш номер>?matchType=2&matchStatus=8&confirmedByOthers=0`
(`matches-for-person-…` в старом виде даёт «Page not found»). Текст страницы — какие деревья и кто их ведёт.
Клик «Review match» → адрес `…/match-compare/I-<наш сайт>-1-<наш номер>-I-<чужой сайт>-<дерево>-<номер>`: здесь
сравнение полей (что «NEW INFO») и **сайт и номер человека в чужом дереве**.

## Шаг 3. Всё дерево вокруг — скриптом

```bash
rodo myheritage-tree <чужой сайт> <номер> --max 40 --depth 3 --out <scratchpad>/x.json
```
Открывает `/profile-<сайт>-<номер>/x` по очереди (8–14 с между профилями), ловит ответ
`web-family-graphql/profile_details_data` целиком и идёт по родне в ширину. Строка на человека: номер · имя · события
(дата, место, текст, источники) · родня (кто кем, годы, номер). Живые — «<Private>», без дат. 403/429/капча — стоп.
Список людей сайта (`/FP/individuals.php`) чужим не открывается; профили по номеру — открываются, если сайт
не закрыт целиком («You are not a member…» — нормально, данные видны).

## Слежка за всеми пересекающимися деревьями — `watch` (раз в месяц)

MyHeritage сам сообщает только о **новых совпадениях** (письмо, пометка «New», код 64). Правки в чужих деревьях —
новые даты, места, родня — он не показывает. Поэтому:
```bash
rodo myheritage-tree watch                       # ~час на 89 человек: список → записи → профили
rodo myheritage-compare [--ancestors]         # наши против их: что там иначе — Павлу на выбор
```
- `watch` — все наши люди с подтверждёнными совпадениями (API шага 1, `matchStatus=8`), для каждого — ответ
  `matches_for_person_fetch_entries` (чей сайт, кто ведёт, страна, номер, имя, даты, родня) и профиль в чужом
  дереве. Снимок — `3_research/tree_data/mh_web/others/<дата>.json` (в git не храним), сравнение с прошлым, отчёт
  `<папка поиска>/findings/_MyHeritage_чужие_деревья_<дата>.md`: новые совпадения, что добавилось или исчезло,
  новые деревья, список деревьев на учёте. Сводка при старте сессии (`sync.py`) напомнит, если снимку больше 30 дней.
- `myheritage_compare.py` — по последнему снимку: другое имя (уже известные написания — `aliases`, с поправкой на
  алфавит — не показывает), год и место рождения и смерти, прочие события, родня, которой у нас нет. Строки
  `- [ ]` — Павел отмечает, что брать (как галочки в «Extract info», но решение остаётся в карточке с источником).
- Скрипт работает **в своей вкладке** и закрывает её: в том же Chrome могут идти другие сессии.

## Шаг 4. В карточки

- Сверка со старым — `known.py` по каждому, кого берём.
- Карточка дерева-источника — `3_research/tree/sources/<Имя> Web Site (MyHeritage).md`: сайт, дерево, таблица
  «номер → кто → что в дереве», что не читали и почему.
- Другое написание имени — в `aliases` (так видят поиск по метрикам и `known.py`); факты — с «(по чужому дереву)»,
  номером профиля и `уверенность: низкая`. Документ сильнее чужого дерева — расхождение исправлять сразу.
- Совпадение «их X = наш Y» — строкой факта у Y: на чём держится и чем подтверждено.
- Боковые ветки чужого дерева (родня жены, их предки) — только в карточку источника, не карточками.

## Что ещё бывает у совпадения

У одного человека бывает несколько деревьев (например, дальней родни за границей и однофамильца-потомка).
Те же люди часто есть в общем дереве FamilySearch — там видно, кто внёс и **какие документы прикреплены**
(навык `archive-familysearch`): так к чужому дереву находятся, например, судовые списки.

## Поиск по базам документов и ИИ-помощник GAIA (проверено 31.10.2026)

- **Поиск по записям:** `research?formId=master&formMode=1&action=query&qname=Name+fn.<имя>+ln.<фамилия>&qevents-event1=Event+et.birth+ey.<год>&record_type=historical`;
  карточки результатов — `.record_card` (имя `.record_name_text`, база `.collection_name`, поля `.fields_list_item`).
  Без года выдача — чужие тёзки (чехи, австрийцы); своё отсеивать по родне и месту. Отчёт — `findings/_MyHeritage_поиск_<тема>_<дата>.md`.
- **Каталог:** баз по деревням и уездам Беларуси и Смоленщины, как метрики FamilySearch, у MyHeritage нет.
- **GAIA** (`/research/ai-research`, чат в iframe `agentic-research`): условия Павел принял 31.10. Вопрос — узкий: один
  человек, что известно, что именно найти. Ввод — `[contenteditable]` + `execCommand('insertText')`, отправка — `button[aria-label="Send message"]`
  (не любой элемент с этой подписью). Ответ готов, когда появилось «Copy response». Для следующего шага — кнопки «Where to
  take this next» под ответом. Ссылки и данные записей — в попапах карточек источников («Show more», затем клик по
  карточке: поля записи и `a[href]`). Кредиты месячные: один вопрос ≈ 10%.

## «Save to your tree» плодит копии — урок 03.11.2026

- **Сайт не узнаёт своих.** Мастер «Save to your tree» / «Extract info» после подтверждения совпадения создаёт
  родню заново, а не находит её в нашем дереве: за вечер на сайте появилось 72 лишних человека — копии наших людей
  (по 2–3 раза) и чужие ветки, пристёгнутые к нашим («родители», «муж», целая чужая семья). Поэтому: **совпадение подтверждать — да, «Save» — нет.**
  Новое из чужого дерева — в карточку (факт, низкая уверенность), на сайт его отвезёт `tools/mh push`.
- **Что верно, решает семья:** записи и память семьи главнее любого дерева; какие чужие деревья надёжны — в заметках
  дерева. Совпадение, которое с ними спорит, — отклонить.
- **Отклонить или подтвердить пачкой:** `rodo myheritage-match-set reject|confirm
  <наш номер>:<чужой сайт>[:<номер там>] … [--go]` — нажимает кнопки в своей вкладке (свой GraphQL-запрос сайт не
  принимает, ключ входа скрипту читать нельзя). Подтверждённое сначала снимается («Undo confirm»), потом отклоняется.
- **Найти мусор после сохранений:** `tools/mh pull` → в `from_site.md` раздел «нет карточки» — всё, что на сайте
  без карточки. Копию от нового человека отличает родня: те же имена родителей, супругов, детей.
- **Удаляет Павел** (Claude людей на сайте не удаляет): профиль → «Delete this person», **с дальнего конца
  цепочки** — человека, который связывает других с деревом, сайт удалить не даёт. Порядок «крайние сначала»
  считается по связям из снимка.
- **Перед отклонением сверять обе стороны:** один человек из чужого дерева не может совпасть с двумя нашими; дерево
  свойственника (жены брата, а не прямого потомка) — слабее. Что уже отклонено — в заметках дерева.
- **Номер чужого сайта бывает в двух видах** (в снимке один, в ссылке «Review match» — другой).
  Для `myheritage_match_set.mjs` брать номер из ссылки на странице совпадений человека.
- Сводка `fetch-matches-by-people` после удалений отстаёт: «у человека нет подтверждённых» — проверять по его
  странице совпадений (`myheritage_tree.mjs matches <номер> --status 8`), а не по сводке.
