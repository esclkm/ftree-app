## Сначала — скрипт `gwar.py` [П 03.11.2026]

С 03.11.2026 поиск, сбор по волости и адрес скана делает `rodo gwar` (команды и примеры — в его
шапке). Сертификаты Минцифры уже лежат в `tools/scripts/ca/russian_trusted_ca.pem` (корневой и промежуточный, их хватает;
отпечаток корневого SHA-256 D2:6D:2D:02…CA:8E:CF:31). Скачивать их с gu-st.ru больше не нужно. Если сайт снова закрыт
для Польши — `--proxy socks5h://IP:PORT` (раздел «Прокси»). Ручной путь через curl ниже — запасной.

- **По волости, а не по фамилии:** `gwar.py volost <Волость>` → все солдаты волости. Фамилии с числом карточек —
  `gwar.py show <файл> --surnames`, одна фамилия — `--grep <Фамилия>`. От сайта приходит в разы больше карточек, чем своей волости.
- **Губернию в запрос не добавлять, отбирать после.** С `--gubernia <Губерния>` выдача меньше, но уезды на сайте записаны
  с ошибками (одна-две буквы не те, первая буква другая) — по точному названию уезда их не отобрать. Скрипт
  отбирает по волости, уезд проверяй глазами.
- **Написания деревень:** `gwar.py places <файл> --target <Деревня>` — похожие первыми (сама деревня, «ур. <Деревня>», с опечаткой в букве).
  Деревня указана лишь в немногих карточках; на скане её бывает больше.
- **Скан:** `gwar.py page <pages_id>` (из `documents_pages`) → адрес картинки. В браузере открывается и
  `https://gwar.mil.ru/heroes/document/<documents_id>/?page_id=<pages_id>`.
- Что уже собрано по волостям этого дерева — в заметках дерева. Сайт пишет название волости по-разному (другая гласная,
  другая буква в начале) — запрос нечёткий и находит их, но строгий отбор скрипта по слову из запроса их отсеет:
  такие выдачи отбирать по уезду. Волости может не быть на сайте вовсе.

## Пошагово для исполнителя (вручную, если скрипт не справился)

Исполнитель — дешёвая сессия (Sonnet). Не угадывай: делай по порядку, на каждую развилку есть ответ.

1. **Проверь доступ.** `curl -s -o /dev/null -w "%{http_code}\n" --max-time 15 https://gwar.mil.ru/`
   - `000` (обрыв сразу, 0.4 с) — из Польши сайт закрыт [П] → шаг 2.
   - `200` — адрес уже российский (или сайт открыли) → шаг 3 (сертификат всё равно нужен, если curl ругается на сертификат).
   - `403`, `429`, страница с капчей — **стоп**, скажи Павлу, не повторяй.
2. **Нужен российский адрес — спроси Павла, не решай сам.** Напиши в чат:
   «gwar.mil.ru не открывается из Польши. Включи российский VPN и напиши "включил", либо разреши искать бесплатные российские прокси для запросов только к gwar.»
   - Павел включил VPN → повтори шаг 1. Если `200` — иди дальше. Если после VPN отвалился сам Claude — это ожидаемо [В]: Павел выключает VPN и выбирает прокси.
   - Павел разрешил прокси → раздел «Прокси» ниже [П]. Без его «да» в этой сессии списки прокси не качай: система безопасности это блокирует (30.09 заблокировала до слова Павла).
   - Павел ничего не ответил → жди. Не ищи обходов сам.
3. **Сертификат.** Сайт подписан Минцифры России; обычный curl его не знает. Один раз за сессию собери файл (в системе ничего не ставить, `-k` никогда):
   ```sh
   A=${ARCHIVES_LOCAL:-${ARCHIVES_LOCAL:-$HOME/ftree-archives}}/_tmp; mkdir -p $A; cd $A
   for n in russian_trusted_root_ca_pem russian_trusted_sub_ca_pem russian_trusted_sub_ca_2024_pem; do
     curl -s --max-time 20 https://gu-st.ru/content/lending/$n.crt | tr -d '\r' > $n.crt; echo >> $n.crt; done
   cat russian_trusted_*.crt > ca_all.pem; grep -c BEGIN ca_all.pem    # ожидаем 3
   ```
   Если `curl --cacert ca_all.pem https://gwar.mil.ru/` говорит «unable to get local issuer certificate» — нужен ещё один промежуточный сертификат: скачай с gu-st.ru или gosuslugi.ru/crt и допиши в `ca_all.pem` (так нашли «sub 2024»). Проверку сертификата не отключать — это запрещено правилами безопасности.
4. **Поиск человека** (POST, ответ — JSON). Заготовка `q.json`:
   ```python
   import json
   F="ids last_name first_name middle_name birth_place birth_place_gubernia birth_place_uezd birth_place_volost location date_birth rank data_vibitiya data_vibitiya_end event_id event_name military_unit_name event_place lazaret_name camp_name date_death award_name nomer_dokumenta data_dokumenta data_i_mesto_priziva".split()
   qf={k:'' for k in F}; qf['last_name']='<Фамилия>'          # + first_name, birth_place_gubernia='Гродненская' ...
   q={"builderType":"Heroes","queryFields":qf,"filterFields":{},"indices":["gwar"],
      "entities":["potery_doneseniya_o_poteryah","potery_gospitali","potery_spiski_zahoroneniy","potery_voennoplen","awd_nagrady","awd_kart","cmd_commander","prs_person","frc_list","uchet_katr"],
      "from":0,"size":100}
   json.dump(q,open('q.json','w'))
   ```
   Отправка: `curl -s --cacert ca_all.pem --max-time 90 [-x socks5h://IP:PORT] -A "Mozilla/5.0 (Macintosh) Chrome/128" -H "Content-Type: application/json" -H "X-Requested-With: XMLHttpRequest" -H "Referer: https://gwar.mil.ru/heroes/" --data-binary @q.json -o r.json "https://gwar.mil.ru/gt_data/?builder=Heroes"`
   Ожидаем: HTTP 200 и `{"took":..,"hits":{"total":N,"hits":[...]}}`. `total 0` при пустом ответе — это «нет такого» (так ответил сайт на первом тесте с неверным ключом, проверь заготовку), а не ошибка.
   - Ответ с битым текстом: читай `json.loads(open('r.json',errors='replace').read(), strict=False)` [П].
   - 000/503/обрыв — повтори с другим прокси, до 4 кругов. 403/429/капча — стоп.
5. **Прочитай ответ дёшево** (не открывай файл целиком):
   ```python
   d=json.loads(open('r.json',errors='replace').read(),strict=False)
   print(d['hits']['total'])
   for x in d['hits']['hits']:
       s=x['_source']; print(s.get('id'),s.get('last_name'),s.get('first_name'),s.get('middle_name'),s.get('birth_place'),s.get('military_unit_name'),s.get('event_name'),s.get('date_death') or s.get('data_vibitiya'))
   ```
   Если поля не те — выведи `list(s.keys())` одной записи и сузь. Поиск ищет и похожие фамилии: редкая фамилия без губернии дала 2093 записи [П] — всегда задавай `birth_place_gubernia` (Гродненская, Минская, Смоленская, Виленская…) или имя.
6. **Страница записи:** `https://gwar.mil.ru/heroes/<тип><id>/`, например `chelovek_donesenie13471802` (список потерь), `chelovek_gospital…`, `chelovek_plen…`, `chelovek_nagrazhdenie…` [П]. Чтобы прочитать поля уезда/волости: скачай страницу тем же curl (GET) и вытащи пары `<dt>…</dt><dd>…</dd>` питоном [П] (так нашли волость, которой не было в JSON).
7. **Скан записи.** Из `_source.documents_pages.pages_id` возьми номера страниц; запрос `builderType:"HeroesStranitsa"`, `queryFields:{"linkedPages":[…]}`, `entities:["stranitsa"]`, адрес `.../gt_data/?builder=HeroesStranitsa`; в ответе `obraz_s_oblastyami` содержит `<img src=…>` с путём [П]. Картинка: `https://gwar.mil.ru/cdn/imagesfww/<путь>.jpg`, примеры путей: `KartotekaPlennyh/00005944_M/00000641.jpg`, `KartotekaPoter/00004300_M/00002049.jpg`, `SpiskiPoter/16196/1/490/00000069.jpg`, `NagradnyeSpiski/970/3/1930/00000525.jpg` [П].
   - Ответ — HTML «технические работы» (503) — хранилище картинок спит. Повторять раз в 30 минут; 30.09 сканы пошли через несколько часов [П]. Проверка: `file x.jpg` должен сказать JPEG; иначе удали и повтори.
   - 404 — путь без `/cdn/` неверный [П].
8. **Сохрани** (раздел «Куда класть») и запиши счётчики в отчёт: сколько запросов, сколько записей, сколько сканов.

## Что это и когда

База Минобороны России по документам РГВИА (Москва): именные списки потерь по полкам (с номером полка!), карточки раненых и больных, карточки военнопленных, списки награждённых. Печатные списки потерь 1914 года (1914.svrt.ru) полка не называют — здесь он есть. Нужно, чтобы по однофамильцу из своей волости найти полк, дату ранения, плен.

Что уже нашли для этого дерева — в заметках дерева (там же ссылки на отчёты). Не прогоняй заново то же самое.

## Вход/доступ

Входа в аккаунт нет — сайт открытый. Закрыт **по стране**: из Польши соединение рвётся сразу [П]. Встроенный браузер Claude тоже не открывал gwar («navigation denied or failed») [П]. Два пути:
- **Прокси [П]:** бесплатный публичный прокси с российским адресом, только для запросов к gwar. Нашли так: список `https://raw.githubusercontent.com/proxifly/free-proxy-list/main/proxies/countries/RU/data.txt` (≈850 адресов); проверка живых `curl -x <прокси> https://ipinfo.io/country` (из 867 жили 26, российских 15, до gwar дошли 2); для каждого `curl --cacert ca_all.pem -x socks5h://… https://gwar.mil.ru/` → `200`. Прокси живут часы — список искать заново в каждой сессии. Через них не отправлять ни пароли, ни куки, ни вход на любой сайт — только открытые страницы gwar/rusneb.
- **VPN [В]:** см. скилл `vpn-browser`. Полный VPN на всём компьютере выпускает в интернет и Claude из России, откуда он заблокирован [В, не проверялось] — не включай без согласия Павла.

## Как искать

Поля поиска сайта (форма «Люди»): `last_name`, `first_name`, `middle_name`, `birth_place_gubernia`, `birth_place_uezd`, `birth_place_volost`, `military_unit_name` и др. Губернии, уезды и волости своей родни и что уже прогнано — в заметках дерева. Пишем русскую форму фамилии и варианты: -ик/-ич, -ко/-ка, «ш»/«ж», с лишним «ч» перед окончанием.

## Как читать дёшево

- Только `get_page_text`/питон-разбор, никаких снимков экрана.
- JSON — печатать 6–8 полей на запись; целиком не читать.
- Картинку (скан) читать **только помощнику**: `Agent` модель haiku/sonnet, просьба «перепиши строки про фамилию X, ответ до 20 строк». Самому — только если Павел просит это изображение.
- В разговор — счётчики и таблица кандидатов.

## Как сохранить без участия Павла

- [П] Всё, что выше, делается без Павла, кроме шага 2 (его «да»).
- Поиски и сканы идут одним потоком, с паузой; повтор — только при ошибке. Выкачивать всё подряд не нужно: качай сканы только кандидатов и «своей волости».

- Сырые ответы поиска (`*.json`, сотни КБ) и скачанные страницы: `$ARCHIVES_LOCAL/raw/gwar/<дата>/` (вне проекта; путь — `paths.ARCHIVES_LOCAL`).
- Скан и выписка о **нашем родственнике или его вероятном родственнике**: `1_sources/found/archives_online/gwar/<Фамилия_Имя_что_фонд-оп-дело>.jpg`; расшифровка — `2_transcripts/archives_online/`; факт — в карточку человека со ссылкой `https://gwar.mil.ru/heroes/…` и шифром РГВИА (ф. 16196, оп. 1, д. 487 и т. п.).
- Каталог: строка `{url, id, фонд/оп/дело, полк, дата, статус проверки}` в `3_research/archives/catalog/gwar/` (в git, без распознанного текста чужих людей).
- **Возможно, наш — полем, не текстом.** Человек из записи о нашем человеке или прямом звене получает свою карточку; боковые ветки, крёстные и поручители — строкой в отчёте или в факте записи (`card-rules`, «только у звена»). Подозреваем, что это кто-то из дерева, — в его свойства `maybe_same: "[[X]]"` + `maybe_same_id`, или `maybe_kin: "[[X]] — брат?"` + `maybe_kin_id` (кем приходится — словом с «?»); на чём держится и что докажет — строкой со ссылкой `[[X]]` в «Открытых вопросах». Обратная сторона у X появится сама. Проверили, что нет, — `rodo possible no "<карточка>" "<X>" --why "…"` (пишет `not_same`/`not_kin`, пара больше не всплывёт). Связь `father`/`spouse` — только по документу. Все пары рядом — `possible.py` → `3_research/tree/_СВЕРКА.md`. Кандидатов из дерева под запись — `tree.py find <фамилия> --for "<имя>"`: проверенные «нет» не показываются.

## Что ломалось

- **06.10.2026 [П]:** сайт сменил формат — старый запрос молча даёт `total 0` на любую фамилию. Работает: `entities` — имена типов, не групп: `chelovek_donesenie, chelovek_gospital, chelovek_zahoronenie, chelovek_plen, chelovek_nagrazhdenie, chelovek_predstavlenie, chelovek_nagradnaya_kartochka, commander, person, chelovek_posluzhnoi_spisok, chelovek_uchetnaya_kartochka`; в `queryFields` поле `birth_date` (не `date_birth`), плюс `archive_short, nomer_fonda, nomer_opisi, nomer_dela`. **JSON писать с `ensure_ascii=False`** — экранированную кириллицу (`\u0413…`) сайт не понимает и отвечает 0. Проверка формата — самая частая русская фамилия (≈100 тыс.). Из Польши поиск 06.10 шёл **без прокси** (нужен только `--cacert`). Поиск нечёткий: фамилия тянет похожие с выпавшей или лишней буквой — отбирать питоном.

- **05.10.2026 [П]:** поле `birth_place_gubernia` в записях пустое — губерния лежит в общей строке `birth_place`
  («<Губерния> губ., <Уезд> уезд, <Волость> вол.»). Фильтр `birth_place_gubernia="Смоленская"` даёт 0. Искать по
  фамилии и имени (без губернии), `entities: []`, `from` для следующей сотни, а губернию и отчество отбирать питоном по
  `json.dumps(_source)`. Прокси: из 400 российских из списка proxifly gwar ответили 53 (`curl … -o /dev/null -w %{http_code}` → 200).

- Из Польши — обрыв соединения; на `http://` прокси отдавал заглушку про «российские сертификаты» [П].
- Цепочка сертификатов: root + sub мало, нужен ещё sub 2024 [П]. curl из системы без `--cacert` — «unable to get local issuer» [П].
- Питон-модуля `socks` в системе нет; curl с `socks5h://` справляется [П].
- Бесплатные прокси: 866 из 867 не годились; сегодня работал один из двух вчерашних [П]. Сканы отдавали 503 «технические работы» часами [П].
- Ответ с испорченным текстом ломал `json.loads` — нужен `strict=False` и `errors='replace'` [П].
- `xargs` с длинным списком — «command line cannot be assembled» [П]: циклом, а не одной командой.
- Скрипты `g.sh`, `gp.sh`, `retry_scans.sh` жили во временной папке сессии и пропали. С 03.11.2026 вместо них —
  `tools/scripts/gwar.py` (curl, `--cacert`, `--proxy`, докачка с того же файла).
- **03.11.2026 [П]:** из Польши сайт открылся напрямую (02.11 был `000`). Доступ меняется день ото дня — проверять шагом 1.
- «Память народа» (pamyat-naroda.ru, Вторая мировая) 403 из-за рубежа [П по заметке плана]; через прокси проверялось, результат в сессии не подтверждён [В].

## Чужой опыт: ex-ussr-kinship-research (MIT, `references/ww1-search.md`; 04.11.2026) [В]

- **«Место рождения» в API — это место жительства или призыва.** Поля `birth_place`, `birth_place_gubernia`,
  `birth_place_volost` на форме сайта стоят в группе «Место жительства / место призыва на военную службу»

- **Две карточки пленного на одно имя** — два кандидата, пока не разрешена личность. Связь карточек, которую
  показывает сайт, — подсказка, не доказательство.
- **Пленные в Германии.** Списки русских военнопленных шли через Датский Красный Крест в Копенгагене. В архиве
