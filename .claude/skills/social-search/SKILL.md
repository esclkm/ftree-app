# Поиск родни в соцсетях

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes social-search`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed social-search 2>/dev/null || rodo skill-notes --embed social-search 2>/dev/null || true`

Проверено 05.10.2026 на одной заграничной ветви дерева: из 28 взрослых нашлись 24, на всё —
~60 заходов на страницы. [П] — проверено, [В] — предположение.

## Что важно знать сначала

- **Пересечения решают.** Однофамильцев тысячи. Наш человек отличается тем, что он **в друзьях или подписках у уже
  найденного родственника** («общий друг», «Followed by anna.kowalczyk»). Без пересечения — не выше 🟡. [П]
- **Якорь** — уже найденный родственник с открытым списком. Один его список даёт сразу десяток людей. Каждый найденный
  — новый якорь. Поиск по имени — только для тех, кого якоря не дали.
- **Несовершеннолетних не ищем** и не вносим, даже если попались в списке (`social_targets.py` помечает «мл.»). Год
  рождения из профиля проверить до внесения (пример: «может быть ребёнок» → в профиле 2006, взрослый). [П]
- **Ссылки на профили живых — только в карточке, в разделе «Контакты (не публикуются)», не на сайте.** Сборка сайта прячет их сама (`site_data/privacy.py`:
  `SOCIAL`, `social_only`; тест `tests/test_privacy_social.py`). Новую соцсеть — дописать в `SOCIAL`. [П]
- **Источник — «найдено», не «семья»:** `[[Интернет-находки (открытые источники, реестры, пресса)]], Facebook|Instagram,
  просмотрено ДД.ММ.ГГГГ`. Источник «Соцсети переписка и контакты» — это выгрузка Павла, его не подставлять.
- **Вход — только Павел**, в браузере проекта (`browser_cdp.mjs`, профиль `$ARCHIVES_LOCAL/browser-profile`,
  отдельно от его личного Chrome). Пароли не спрашивать, не читать, не импортировать за него.
- **Ничего не писать, не лайкать, не подписываться, заявки в друзья не слать.** Капча, «подозрительная активность»,
  HTTP 429 — стоп, сказать Павлу.

## Порядок (дешёвый)

```bash
B="rodo browser-cdp"; J=.claude/skills/social-search/js
```

1. **Кого ищем** — без браузера:
   `rodo social-targets list "<карточка предка>"` → таблица: поколение, год (≈ — оценка по
   братьям/родителям), «мл.», сколько соцсетей уже в карточке. Показать Павлу до поиска.
2. **Что уже есть** — без браузера: ссылки в карточках (`Ссылка:`), выгрузка Павла
   (`1_sources/family/social/social_export/*_relatives.md`; полных списков подписок там нет).
3. **Facebook: поиск людей по фамилии — один запрос на фамилию.** [П] Списки друзей почти всегда скрыты (у одного якоря
   577 друзей — видно 0), а поиск сам пишет «Друг», «N общих друзей», «Отменить запрос» (Павел уже звал в друзья).
   ```bash
   $B nav "https://www.facebook.com/search/people/?q=Kowalczyk"; sleep 6
   $B eval "$(cat $J/fb_search.js)" --out /tmp/…/fb_Kowalczyk.tsv     # имя, адрес, подпись, картинка
   ```
   Отбор: латиница + («общ» | «Друг ·» | «Отменить запрос»), остальное — шум. Пауза между фамилиями ≥10 с.
4. **Instagram: подписчики и подписки якоря — через окно, а не через API.** [П] Внутренний API (`/api/v1/friendships`,
   `web_profile_info`) на этом входе сразу отдаёт 429 — не пробовать. Прямой адрес `/followers/` окна не открывает;
   работает клик по «N followers» на странице профиля, потом медленная прокрутка (5–8 с на шаг).
   ```bash
   $B nav https://www.instagram.com/<якорь>/; sleep 8
   $B eval "$(sed "s/KIND/'followers'/" $J/ig_open_list.js)"; sleep 6
   $B eval "$(cat $J/ig_list.js)" --out /tmp/…/ig_fol.txt          # ~2–4 мин на 150 человек
   python3 $J/ig_pairs.py /tmp/…/ig_fol.txt > /tmp/…/ig_fol.tsv
   rodo social-targets match "<предок>" /tmp/…/ig_fol.tsv [--names]
   ```
   Потом то же с `following`. Читается ~85% списка — для поиска родни хватает.
5. **Профиль каждого найденного — один заход** (Facebook `/about`, у `profile.php?id=` — `&sk=about`): город, родной
   город, работа, учёба, **дата рождения** (часто полная — в карточку `born` + строка факта «рождение … — дата из
   профиля»), «в отношениях с». `$B eval "$(cat $J/fb_about.js)"`. Пауза ≥20 с, пачкой — в фоне.
6. **Фото профиля** — `$B nav https://www.facebook.com/<адрес>; $B eval "$(cat $J/fb_photo.js)"` → «подпись<TAB>адрес
   картинки». Брать **только картинку, подписанную именем человека** (`svg[aria-label=Имя]`) — иначе попадается свой
   аватар Павла или «Люди, которых вы можете знать» (так 17 из 23 первых фото оказались чужими). [П] Скачивать
   `curl` без cookie — адрес подписан и открыт. Класть в `1_sources/found/social_profiles/<Имя_карточки>_фото-профиля-
   Facebook_<дата>.jpg`. Посмотреть одним листом (PIL-коллаж), выкинуть: серый силуэт, пейзаж, еду, мультяшку, спину,
   общее фото, где не понять кто. Одно фото на двоих (пара) — один файл, строка в `media` у обоих.
7. **Google / открытые реестры — помощнику (Agent sonnet, ≤15 поисков, ответ ≤20 строк).** Даёт то, чего нет в
   профилях: LinkedIn-должность, фирма, город (пример: менеджер международной фирмы в соседней стране). Instagram и
   LinkedIn поисковик почти не видит — на нём людей не искать, только уточнять.
8. **Внести** — ссылка в `### Контакты (не публикуются)` (`check_cards.py --fix` перенесёт и сам), сведения — в «Факты (с источником)»:
   `- **Ссылка:** <url> — <на чём держится: в подписчиках у X / общий друг> — *источник: [[Интернет-находки (открытые источники, реестры, пресса)]],
   Instagram, просмотрено ДД.ММ.ГГГГ · уверенность: высокая|обычная|низкая*`
   и `- **профиль:** город; работа; учёба; …`. Источник — в `sources` свойств и в «## Источники» (происхождение:
   найдено). Фото — строкой в `media`. Потом `check_cards.py --fix`, `check_tree.py`, проверка утечки на сайт
   (выгрузить `site_data.export.write` во временную папку и поискать `facebook.com|instagram.com|linkedin.com` — 0).
9. **Павлу — одна страница на проверку** (HTML в scratchpad, `SendUserFile`): карточка на человека, ссылка, уровень,
   доводы; не уверен — 2–3 кандидата рядом. Фото в git не идут — `media.py push` только с согласия Павла.

## Уровни

✅ — пересечение + совпало что-то из рассказа (увлечение, город, семейная фирма, дата) · 🟢 — пересечение и имя ·
🟡 — имя и город без пересечения · 🟠 — только имя · ⚪ — не нашли.

## Подсказки по людям

- Имя в соцсети часто другое: уменьшительное, второе имя, инициалы (Valentina → «**Vale**», Tomás → «**Tomi**»,
  Mateo Joaquín → «**MJ**»). В имени аккаунта бывают год (`mateo198104`,
  `valentina_q75`) или имя ребёнка (`vale_madrelucia` — дочь Lucía).
- Фамилия супруга или детей, которой нет в дереве, находится по соседям в списке: несколько людей одной новой
  фамилии рядом с нашим человеком — вероятно, семья супруга.
- **Открытый список друзей у старшего родственника** — лучший якорь для всей родни, во всех странах. Проверить у
  каждого старшего: у кого открыт — читать первым. Прокрутка 14×5 с.
- Девичья фамилия у женщин — не поиск: замужние родственницы в Facebook под фамилией мужа. Искать по имени + признаку
  (город, страна, общие друзья с якорем), а не «Имя Девичья-фамилия».
- Транслит белорусских и польских фамилий — пробовать обе формы (Гаркуша/Harkusha/Garkusza); варианты —
  `SURNAME_FORMS` в `social_targets.py`, дописывать.

## Сколько это стоит

Скрипты и браузер проекта работают без модели; в разговор идёт только итог (`| head`, `--out` в файл). Картинки
модель смотрит один раз — коллажем. Самое дорогое — читать сырой текст страниц: не читать, а фильтровать скриптом.
