# Обслуживание дерева

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes tree-maintenance`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed tree-maintenance 2>/dev/null || rodo skill-notes --embed tree-maintenance 2>/dev/null || true`

**Что это.** Пять скриптов, которые держат дерево в `3_research/tree/` честным. Запускать всегда в этом
порядке — следующий опирается на результат предыдущего.

**Всё сразу:** `rodo update-all` (+ `--dossiers` — досье прямых предков, `--books` — черновики книг).
Obsidian для этого не нужен. По шагам:

```bash
rodo check-tree      # 1. ошибки связей — чинить, пока не станет 0
rodo card-doctor --fix  # 1б. дубли фото, источников, фактов — убирает сам; красные сигналы — разобрать
rodo assign-lineage  # 2. ветки lineage / lineage_by_marriage (руками не правим)
rodo texts-section   # 3. в карточках: «Рассказ» (свёрнутый раздел биографии) и «Тексты» (статьи, автобиографии)
rodo photo-catalog   # 4. 3_research/КАТАЛОГ_ФОТО.md
rodo check-links     # 5. битые ссылки во всём проекте
rodo possible        # 6. страница «Сверка» (_СВЕРКА.md): все пары «возможно, тот же / родня»
```

## Все проверки проекта — по нулям

```bash
# через tools/py: это .venv проекта (uv sync); у голого python3 нет библиотек. Всё ли установлено — tools/py tools/doctor.py
rodo check-tree    # связи, тёзки, пол родителей, фото, источники, ветки — должно быть 0
rodo check-links   # битые ссылки во всём проекте
rodo card-doctor --fix  # дубли фото/источников/фактов в карточках — убрать; красные сигналы — показать
rodo check-lifeline     # линии жизни: после смерти, внуки, события детей, рождение каждого ребёнка из карточки (--fix впишет сам) — 0 ошибок
rodo check-lifespan     # годы жизни: известны из текста, а born/died в карточке пусты — должно быть 0
rodo check-names        # имена (name): без скобок, цифр, «?», отчеств; «Unknown» без номера — должно быть 0
rodo check-bio          # биографии: один человек в файле, разделы по порядку, события по времени — 0 ошибок
rodo check-dates        # даты карточек и линий жизни — как в GEDCOM (--fix правит, что может сам) — 0
rodo myheritage-update lint  # для MyHeritage: повтор gedcom_id, непонятная дата, человек уже на сайте — 0 ошибок
rodo documents check    # документы человека (2_transcripts/documents/): вид, страницы по датам, «откуда взято», PDF свежий — 0
rodo check-cards        # карточки → JSON сайта: строка факта, источник ссылкой, уверенность, эпохи мест, разделы по образцу (--fix) — 0
rodo test  # тесты чтения карточек (пакет cards)
rodo fact-check status  # сверка фактов с источником и с биографией (журнал; идём партиями, линза О13 в self-review)
```

Перед коммитом большой правки — ещё навык `self-review` (линзы по коду, описаниям и фото — то, чего скрипты не видят).
Хуки сами: `check_tree.py` после каждой правки в `3_research/tree/`, `card_doctor.py` по карточке, `check_dates.py`, `check_lifeline.py`, `bio_ids.py --fix` — после правки карточки или биографии и перед коммитом.

## Как чинить то, что нашёл check_tree

| Сообщение | Что значит | Что делать |
|---|---|---|
| `father → [[X]], а номер … — это [[Y]]` | ссылка по имени ушла на тёзку | верить **номеру** (`*_id`): поставить ссылку на Y |
| `супруг [[X]] без пары` | связь есть только с одной стороны — обычно дописана по ошибке к тёзке | проверить по источнику; если не подтверждается — удалить с той стороны, где она лишняя (и ссылку, и номер) |
| `отец и мать перепутаны?` | MyHeritage поменял роли | поменять местами `father`/`mother` и `father_id`/`mother_id` |
| `название кончается цифрой` | новый тёзка «Мария 2» | переименовать: `Имя Фамилия (год)` или `Имя (отец X)`, ссылки обновить по всему проекту |
| `фото не найдено` | в `media` имя файла, которого нет | найти файл (`rodo moves where <старый путь>`) или убрать строку |

## Как разбирать то, что показал card_doctor

| Код | Что значит | Что делать |
|---|---|---|
| `M1–M3`, `S1`, `F1` | дубль фото, источника или факта | `--fix` убирает сам; из группы одинаковых фото остаётся реставрация (не «без-ИИ»), иначе самое полное — на месте первого (первое фото — портрет на сайте) |
| `F2` факт без источника | строка в «Факты (с источником)» без ссылки | найти источник или перенести в «Открытые вопросы» |
| `D1` даты | смерть раньше рождения, больше 110 лет | сверить с документом; стиль календаря до 1918 — не причина |
| `D2` возраст родителя | родителю меньше 13 (мать — больше 55) при рождении | обычно ребёнок привязан не к тем родителям или год рождения с ошибкой — проверить по источнику |
| `N1` отчество в названии | нарушено правило «отчеств нет» | переименовать карточку (ссылки поправит коммит) |

## Правила

- **Номер важнее имени.** Любая связь хранится дважды: `[[Имя]]` и `*_id`. При споре прав номер.
- **Подозрение — полем, не текстом.** «Возможно, тот же человек» — `maybe_same` + `maybe_same_id`; «возможно, родня» —
  `maybe_kin: "[[X]] — брат?"` + `maybe_kin_id`; проверено «нет» — `not_same` / `not_kin` (+ `_id`), почему — строкой ✅
  в «Открытых вопросах». Пишется в одну карточку, обратную сторону покажут сайт и `tree.py who`. Это не связь: ветки и
  дерево их не видят. `check_tree.py` ловит ссылку в никуда, чужой номер, ссылку на себя, пару сразу в «возможно» и
  «нет». Решения по паре — `possible.py no|yes` или `merge_cards.py` (команды — на странице `_СВЕРКА.md`).
- **Не запускать команду Charted Roots «Assign lineage»** — она считает ветки от одного человека вниз и
  испортит поля, которые считает `assign_lineage.py`.
- **Не запускать `build_book.py` ради проверки**: он безопасен (ручные правки не затирает, кладёт новое в
  `_generated/`), но это сборка книги, а не обслуживание.
- Итог сообщать числами: сколько ошибок было → стало, сколько людей в каждой ветке, сколько фото без человека.
