# Настройка рабочего места

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes setup`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed setup 2>/dev/null || rodo skill-notes --embed setup 2>/dev/null || true`

**Что это.** Дерево состоит из двух частей: **данные** (карточки, источники, биографии) и **приложение** (скрипты,
проверки, сайт). Чтобы работать, на Mac нужны программы, окружения Python и Node, файл путей, хуки git, облако для
фото и звука, входы на сайты. Что из этого включено и куда класть — записано в данных, в `setup/setup.toml`.
Команда `rodo setup` проходит по списку и сама делает всё, что можно сделать без выбора. Этот навык — для остального:
разговор, выбор и шаги, где нужен человек.

**Главное правило.** Пароли, коды и входы вводит человек сам — в терминале или в браузере. Навык их не спрашивает,
не читает, не печатает и не передаёт в команды. Проверять можно только, что запись есть (`security find-generic-password
-s <имя>` без `-w`).

## Команды

| Команда | Что делает |
|---|---|
| `sh setup/bootstrap.sh --dry-run` | чистый Mac: показать, что будет сделано, ничего не меняя |
| `sh setup/bootstrap.sh` | чистый Mac: Homebrew-программы, которых нет; приложение по `setup.toml`; потом `rodo setup` |
| `rodo setup --check` | только проверить; каждая красная строка — с командой |
| `rodo setup` | проверить и сделать, что можно; на расхождения и тяжёлое — спросит «да» |
| `rodo setup --non-interactive` | ничего не спрашивать (хуки, проверки на GitHub) |
| `rodo setup --short` | одна строка для сводки при старте сессии |

Повторный запуск безопасен: что уже есть, не трогается.

## Порядок разговора

1. **Новый Mac или починка?** Новый — шаги 2–5. Починка — сразу `rodo setup --check` и шаг 4.
2. **Что включить.** Открыть `setup/setup.toml`, раздел `[features]`, и спросить про каждое `true`, нужно ли оно на
   этом Mac. Объяснять по делу: «распознавание звука — 9 ГБ моделей, нужно, только если будете расшифровывать записи».
   Тяжёлое (`asr`, `photo_restore`, `image_model`) лучше включить потом, когда дойдёт до задачи.
3. **Куда класть.** `[app]` — откуда приложение: `path` (папка на диске, режим «разработка») или `repo` + `tag` +
   `dir` (режим «версия», для второго компьютера). `[places]` — папки этого Mac (сырьё архивов, кэш, сборка сайта).
   Не задано — значения по умолчанию. Правку `setup.toml` показать человеку до сохранения.
3а. **Где хранить медиа и куда выкладывать сайт** — это не `setup.toml`, а `ftree.toml` дерева (раздел ниже). Значений
   по умолчанию нет нарочно: приложение форкают, и чужое дерево не должно молча слать фото и сайт к нам. Спросить два
   вопроса и вписать ответ (показав правку до сохранения).
4. **Запуск.** Новый Mac — `sh setup/bootstrap.sh --dry-run`, показать план, после «да» — без `--dry-run`. Иначе —
   `rodo setup`. Вопросы «поправить? [y/N]» задаёт сам скрипт — их видит человек в терминале; из сессии Claude
   (без терминала) запускать с `--non-interactive`, а расхождения пересказать и после «да» — `rodo setup --yes`.
5. **Красные строки — по одной, простыми словами** (таблица ниже). Что чинится командой без пароля — починить и
   запустить `rodo setup --check` ещё раз. Что требует входа — дать человеку точную команду и ждать «готово».
6. **Итог** — `rodo setup --check`: в «Основном» всё ✅; в «По задаче» — то, что решили поставить.

## Что значат значки

| Значок | Значит | Что делать |
|---|---|---|
| ✅ | есть и верно | ничего |
| 🛠 | нет, но скрипт сделает сам | `rodo setup` |
| ⚠️ | расходится с `setup.toml` (другая папка, другая версия) | показать разницу, после «да» — `rodo setup --yes` |
| 📦 | тяжёлое: модели на гигабайты | спросить, нужно ли сейчас; да — `rodo setup --yes` |
| 👤 | нужен человек: вход, пароль, ключ | дать команду из строки, ждать «готово» |

## Частые красные строки

| Строка | По-простому | Кто чинит |
|---|---|---|
| нет Homebrew | менеджер программ для Mac; его установка спрашивает пароль Mac | человек, команда с brew.sh |
| `файл путей … ~/.config/ftree/env` | файл, где записано, где на этом Mac данные и приложение | `rodo setup` |
| `.venv` | своё окружение Python с нужными библиотеками | `rodo setup` (`uv sync`) |
| `хуки git` | проверки перед коммитом и выкладка сайта после | `rodo setup` |
| `web/node_modules` | библиотеки сайта | `rodo setup` (`npm ci`) |
| `команда rodo` / `~/.local/bin в PATH` | чтобы `rodo` работала из любой папки | `rodo setup`; строку в `~/.zshrc` добавляет человек |
| `медиа: пароль шифрования в Связке ключей` | без этих двух паролей звук и PDF в облаке не прочитать | человек: скопировать из приложения «Пароли» командой из строки. **Новые не придумывать** — старое облако станет нечитаемым |
| `медиа: rclone видит <имя>:` | программа облака не подключена к аккаунту, указанному в `[storage.*]` | человек: `rclone config`; для Jottacloud — `sh tools/setup/rclone_jotta.sh <имя>` (вход в браузере) |
| `медиа: <имя>: шифрует` | в `[storage.private]` написано `encrypted = true`, а remote не шифрует — звук и PDF ушли бы открыто; отправка туда стоит | завести remote вида crypt (`rclone config`) или честно `encrypted = false` |
| `сайт: вход в Cloudflare / Netlify` | без входа сайт не выложится | человек: `npx wrangler login` / `npx netlify-cli login` |
| `сайт: секрет зеркала` | зеркало передаёт основному сайту страну посетителя с секретом; без файла не выложится | команда из строки; то же значение — секрет `PROXY_KEY` основного сайта (человек, на хостинге) |
| `вход на … в Chrome проекта` | у проекта свой Chrome; вход на сайт делается в нём один раз | человек: команда из строки, войти и отметить «запомнить меня» |
| `Телеграм: ключи` / `вход` | ключи приложения с my.telegram.org и код из Телеграма | человек |
| `звук …`, `фото …`, `ollama: модель` | тяжёлые модели | после «да»: `rodo setup --yes` |
| `приложение на <тег>` ⚠️ | приложение другой версии, чем записано в данных | после «да»: `rodo setup --yes` |
| `версия приложения … — дереву нужна …` | данные записали, с какой версией приложения работают (`[app] version`); это приложение старее или другой серии | старее — обновить приложение; новее — `rodo check`, потом поднять `[app] version` |
| `CLAUDE.md дерева подключает правила приложения` | строка `@<приложение>/tools/CLAUDE.app.md` — общие правила для Claude | `rodo setup` (путь — из `[app]`) |
| `плагин ftree@ftree-app объявлен в .claude/settings.json` | откуда Claude Code берёт навыки и что включить | `rodo setup` |
| `навыки Claude: плагин ftree@ftree-app` | сами навыки-методы; ставятся на каждый Mac | человек — шаги ниже |

## Навыки Claude: плагин и заметки дерева

Навыки-методы (как работать с архивом, писать карточку, биографию) лежат в приложении и подключаются плагином
`ftree@ftree-app`. Что именно искали в этом дереве — **заметки дерева** (`[skills] notes_dir` в `ftree.toml`). В
начале каждого навыка стоит строка подгрузки — восклицательный знак и команда в обратных кавычках: `${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed ИМЯ || rodo skill-notes --embed ИМЯ || true` (папка плагина — это само приложение; запасной путь — `rodo` из PATH): при вызове навыка Claude Code сам
выполняет её и вклеивает заметки. Нет заметок — пусто.

Шаги человека (один раз на Mac):

1. Из папки данных: `claude plugin install ftree@ftree-app --scope project`. Разработка (правишь навыки в приложении) —
   вместо этого запускать `claude --plugin-dir <папка приложения>`: навыки берутся прямо из папки.
2. Открыть новую сессию Claude в папке данных. Claude Code один раз спросит, можно ли подключить внешний файл
   `@~/…/ftree-app/tools/CLAUDE.app.md` из `CLAUDE.md`, — разрешить.
3. Проверить: вызвать навык, например `/ftree:archive-gaso`, и увидеть в нём раздел «Заметки этого дерева» со своими
   заметками. Не видно — `rodo skill-notes archive-gaso` в терминале: если там заметки есть, значит Claude Code не
   выполнил строку (разрешение на `rodo skill-notes` — в `.claude/settings.json` дерева, его пишет `rodo setup`). Пример
   такой строки в тексте навыка писать только без восклицательного знака перед обратной кавычкой: иначе Claude Code
   попробует её выполнить.
4. Одноимённые навыки в `.claude/skills/` дерева и в плагине грузятся оба — в дереве оставлять только свои (не методы).

## Где хранить медиа и куда выкладывать сайт (`ftree.toml` дерева)

Читает `tools/scripts/destinations.py`. Не задано — `rodo media push` и `rodo site publish` ничего никуда не шлют и
пишут, что вписать; хуки git тоже молчат.

**Вопрос 1. «Где хранить копии фото, звука и PDF?»** Варианты: облако через rclone (Jottacloud, Google Drive, S3/R2 —
любое, что знает rclone), папка на диске (внешний диск, NAS), нигде (только на этом Mac — потеря Mac = потеря файлов).
Два хранилища: открытое `[storage.media]` (фото; родне можно дать посмотреть) и закрытое `[storage.private]` (звук, PDF,
документы живых — лучше шифровать: `encrypted = true` и remote rclone вида crypt).

```toml
[storage]
push_after_commit = true       # после коммита новое уходит само, в фоне
[storage.media]
kind = "rclone"                # rclone | local | none
address = "cloud:Семья/"       # пример
[storage.private]
kind = "rclone"
address = "cloud-crypt:"       # пример
encrypted = true
```

**Вопрос 2. «Куда выкладывать сайт для родни?»** Основной — Cloudflare Pages (`kind = "cloudflare-pages"`: только
там работают пароль и закрытые файлы) или папка (`kind = "folder"`, `path = …` — для любого хостинга статики, без
пароля). Зеркала для стран, где режут Cloudflare, — `netlify` (`site = <Site ID>` — номер из настроек сайта Netlify; по имени не находит) и `cloudflare-worker` (`name = …`): они
пересылают на основной. `manual = true` — выкладывать только по имени (`rodo site mirror <имя>`).

```toml
[site]
publish_after_push = true      # после push в основную ветку сайт выкладывается сам
[[site.target]]
kind = "cloudflare-pages"
project = "my-family"          # пример
url = "https://my-family.example"
```

Потом — `rodo setup --check`: строки «медиа: …» и «сайт: …» проверяют ровно то, что вписано.

## Где что

- Описание — `setup/setup.toml` данных (только имена записей Связки ключей, без паролей).
- Скрипт — `tools/scripts/setup.py` приложения; `tools/doctor.py` — переходник на `rodo setup --check`.
- Первый запуск — `setup/bootstrap.sh` данных; установщики тяжёлого — `tools/setup/*.sh` приложения.
- Порядок настроек (что сильнее): ключ команды > переменная окружения > `~/.config/ftree/env` > `ftree.toml` >
  значение по умолчанию. Папка данных: переменная `FTREE_ROOT` > дерево, внутри которого стоишь > `FTREE_ROOT` из
  файла env (`tools/scripts/paths.py`).
- Подробно для человека — `INSTALL.md`.
