# Сайт для родни

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes site`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed site 2>/dev/null || rodo skill-notes --embed site 2>/dev/null || true`

**Что это.** Сайт для родни: дерево, карта, люди, места, источники, заметки; языки RU / PL / ES / EN, русский —
основной, переводы биографий — по запросу (навык `bio-translate`). После push в master хук сам выгружает, собирает и
выкладывает сайт (в фоне, `rodo site all`).

## Как устроено — два шага

1. **Выгрузка** (движок, читает карточки): `rodo site export` (`tools/scripts/site_export.py`) →
   `4_outputs/site_export/`: `data/*.json` по схемам `web/schema/`, `media/` (уменьшенные фото), `files/` (PDF),
   `site.json` (что только по паролю, срок и страны открытого входа, куда выкладывать). **Всё скрытие личного — здесь.**
   `--data` — только `data/*.json` (так на GitHub, там нет фото).
2. **Сборка и выкладка** (сборщик, карточек не видит): `rodo site build` / `rodo site publish` (`web/scripts/site.mjs`) —
   берёт только папку выгрузки, приложение `web/src/app` (`npm run build:app`) и `web/site_assets/functions/`
   (проверка входа) → `4_outputs/site/`; `publish` — на основные цели, `rodo site mirror` — зеркала (цели — `[[site.target]]` в `ftree.toml`; нет целей — только сборка).
   `rodo build-site` — оба шага подряд (старое имя; `build_site.py` — переходник).

- Все страницы рисует **приложение** (`web/src/app`, React; адреса `/<язык>/people/<slug>`, `/<язык>/docs/<номер>` …).
  HTML из Python больше нет (с 05.11.2026): заметки проекта (расшифровки, находки, тексты документов) — `data/docs/<номер>.json`
  и страница `/<язык>/docs/<номер>`; номер — как у прежней `docs/<номер>.html`, старые адреса открывают её же, а старый
  адрес источника или биографии ведёт на их страницу. Ссылка на заметку в тексте — `[подпись](doc:<номер>)`.
- **Скрипты — слоями:** `tools/scripts/cards/` читает карточки в объекты и называет каждую запись не по правилам;
  `tools/scripts/site_data/` — имена на языках, адреса страниц, годы жизни, очистка от адресов и контактов, выгрузка
  JSON (`export.py`); `site_export.py` — биографии, фото, альбомы, заметки (стык `SiteExtras`). Новое, что видит
  посетитель, — через выгрузку и схему `web/schema/` (типы — `npm run schema`). Выгрузка останавливается на ошибках
  `check_cards.py`; тесты `web/` проверяют каждый JSON схемой; `tests/test_site_build.py` — сайт из выгрузки вымышленного
  дерева с `FTREE_ROOT` на несуществующую папку.
- Новый JS/CSS — только в `web/src/`; библиотеки — через npm. Карта кода и раскладка (почему `web/` целиком уедет в `site/`
  приложения) — `web/README.md`.
- Надписи интерфейса — таблица `I18N_ROWS` в `site_export.py` (ключ|ru|pl|es|en) → `data/ui.json`.
- Ни выгрузка, ни сборщик папку не стирают, а обновляют по файлам: стёртая папка в iCloud возвращается копией «people 2».
  Сборщик копирует только изменившееся — выкладка не грузит заново то, что не менялось.
- Где порядок виден человеку — `dict.fromkeys(…)`, не `set`: иначе две сборки одних данных не сравнить.

## Приватность

- Номера домов и квартир, телефоны, почта — вычищаются (`site_data/privacy.py`); дом с `address_public: true` — с номером; PDF с ними и сканы документов
  живых — только по паролю.
- **Контакты — отдельным разделом карточки** `### Контакты (не публикуются)` (с 05.10.2026): телефоны, почта, профили в
  соцсетях, нынешние адреса живых. Его не читает `cards/facts.py` (JSON) и не берёт выгрузка сайта. Вторая линия —
  `no_contacts`: профили соцсетей → «[профиль скрыт]», аргентинские адреса «<улица> <номер>, CABA» — без номера
  (`AR_ADDRESS`); тесты — `tests/test_privacy_social.py`. Проверка после выгрузки: в `4_outputs/site_export` нет
  `facebook.com/…`, `instagram.com/…`, `linkedin.com/…`.
- **Записи разговоров в семье — на сайт только описание.** У источника со звуком в `media` (Аудио 01–07) — название,
  кто рассказывает, о ком; ни текста расшифровки, ни звука, ни страниц из `2_transcripts/audio/` (`privacy.py`:
  `audio_source`, `unpublished`; одно правило для страниц и JSON).
- Возможные связи (`maybe_*`) — блок «Возможно, связан» в профиле; причина проходит ту же очистку.

## Хроника и дома

«Хроника» (`/<язык>/gallery`, `pages/Gallery.tsx`) — три вкладки: Места (альбомы мест), Дома (`/gallery/houses`,
дома по городам, каждый — ссылка на страницу дома), События (`/gallery/events`). Альбом событий — **история одного человека или одной семьи**, не тема и не папка:
`3_research/tree/albums.toml` (название, лица, «о ком и про что» на 4 языках; снимки — по куску имени файла `files`,
лишнее — `skip`, вся папка — `folders`). В альбом — только то, что названо в источниках: та модель паровоза или машины,
то место; «похожее вообще» — в `skip`. Снимок без альбома на сайт не идёт, сборка печатает его имя. На карте
домов нет (старый адрес `/map/houses` ведёт во вкладку). Страница дома — «Кто жил в доме» по годам на одной шкале; у
человека — «Дома, где жил(а)». Данные — `house` и `residents` в `data/places/<id>.json`, `homes` у человека,
`type`/`parent`/`house` в `index.json`; считает `cards/houses.py`. Как заводить дом — навык `card-rules`, раздел «Дом».

На карте и на странице места у человека — не только «работа», а годы и суть: `who[].events` (дата и первая фраза
описания события, `export._gist`). Событие без описания покажет только годы — значит, описание надо дописать в карточку.

## Цвета, тема и фото мест

Палитра и шрифты (PT Serif / PT Sans / PT Mono) — `web/src/styles/_tokens.scss`, со страницы «Деревни предков по годам»:
светлая и тёмная тема (по системе; «Настройки» — тема и «Дерево всегда светлое», `app/theme.ts`). Цвет в SCSS — только
переменной (`var(--…)`), иначе он не сменится в тёмной теме. Фото мест у места, у человека («Фото мест из жизни») и в альбоме —
лента по срезам лет (`app/PhotoTimeline.tsx`): слева годы и государство, справа снимки; метка золотая «наше» или красная
«≈ не наше» (навык `photos`, «Не наше, но похожее»).

## Документы в профиле

Раздел «Документы» (`Documents` в `pages/PersonParts.tsx`, `documents` в `data/people/<id>.json`; собирает
`site_export.person_documents`): у каждого документа из `2_transcripts/documents/<Имя>/` — плитка с первой страницей, вид и
годы, «PDF» (весь документ) и «Текст» (страница с описанием и расшифровкой). `access: closed` — не выводится вовсе. Документ
живого или с номером дома, почтой, телефоном в тексте — без обложки, PDF по паролю (`PRIVATE_FILES`); остальные PDF —
открыты.

## Страница «Сверка»

«Источники → Сверка» (`/<язык>/sources/review`, `data/review.json`, схема `web/schema/review.schema.json`): пары
карточек, отмеченные в карточках (`maybe_*`), и найденные автоматически (`possible.auto`: одно имя с церковными и
польскими формами, та же фамилия или место рождения, годы не спорят). Карточки рядом и команды решений — сайт ничего
не меняет, решает владелец дерева командой (`possible.py maybe|yes|no`, `merge_cards.py`). То же локально — `possible.py` →
`3_research/tree/_СВЕРКА.md`.

## «Состояние дерева» и «Что нового»

`/<язык>/progress` и `/<язык>/news` (`pages/Progress.tsx`, `data/progress.json`, считает `site_data/progress.py`). Цифры по
каждому роду из `ftree.toml`: люди по крови и по браку, поколений вглубь над корнем, самый ранний предок, чем подтверждены
рождения и смерти предков (правила `coverage.py`), рост по дням. Лента — сравнение снимков дерева по последнему коммиту
каждого дня (`git archive` → `cards.load`), **не тексты коммитов**: в них бывает то, что на сайт не выносим. Снимки —
кэш `tools/.cache/progress/<коммит>.json`; первый проход по истории ~1,5 мин, потом секунды. Поменял поля снимка —
поднять `SNAP`.

## Заметки с сайта

Владелец дерева собирает правки прямо на сайте (кнопка «Заметки» на широком экране, `web/src/app/notes/`) и вставляет их
текстом «# Заметки к родословной — …» — на языке страницы, где их собирали: «# Notatki do drzewa genealogicznego — …»,
«# Notas para el árbol genealógico — …», «# Family tree notes — …». Подписи разделов — на том же языке, а куски данных
(строка, факт) и имена людей и мест — как в карточке, по-русски. Надписи заметок — `n_*`, `nv_*`, `nk_*`, `nw_*`, `nr_*` в `I18N_ROWS`. Каждая — человек/место по `cr_id`, файл биографии, кусок как был на сайте,
его слова. Разбирать как обычную правку: исходник → карточка → биография (правка владельца — молча); фото — по имени
файла в `media` и `1_sources/`; «найти лучше» — искать замену.

## Проверить на собранном сайте

- `rodo site export`, потом `preview_start` с именем `app` (`.claude/launch.json`, `npm run app` — данные из выгрузки
  → http://localhost:5173/ru/people/<slug>).
- Человека искать **по номеру** (`cr_id` → `slug` в `data/people/<cr_id>.json`), не по заголовку: у тёзок две
  страницы (`ivan-tkachuk`, `ivan-tkachuk-abc`).
- После правки структуры биографии — открыть **все вкладки языков** RU / PL / ES: перевод повторяет структуру, и то,
  что сайт прячет в русском, может торчать в переводе.
- Написал биографию — открыть профиль и убедиться, что текст там и строки «Линии жизни» на месте (файл, который
  начинается с `# Имя` и «**В дереве:**», раньше прятал линию жизни — `site_export.own_head`).
