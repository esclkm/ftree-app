# Восстановление фотографии

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes photo-restore`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed photo-restore 2>/dev/null || rodo skill-notes --embed photo-restore 2>/dev/null || true`

Пайплайн: **обрезка/выпрямление → царапины → цветокоррекция → ИИ (лица + апскейл) → раскраска (копией)**.
Скрипты: `tools/scripts/photo_restore.py`, `tools/scripts/photo_colorize.py`; окружение — `tools/setup/photo.sh`.

## 0. Один раз — поставить ИИ-окружение
```bash
bash tools/setup/photo.sh        # создаёт ~/.relatives_ai_venv + качает веса (~5 ГБ, долго: архив BOPBTL 2 ГБ, из него берётся детектор)
```
Дальше всегда запускать через `~/.relatives_ai_venv/bin/python`.
Тяжёлый шаг лучше пускать в фоне (nohup) и дождаться «сторожем» (run_in_background bash, ждущим маркер в логе).

## 1. Обрезка/выпрямление (если нужно)
- **Прочитай изображение** (Read), чтобы увидеть его. Если фото снято под углом / лежит на фоне
  (стол, ноутбук, рука) — определи **4 угла самой фотографии** в пикселях ПОЛНОГО разрешения
  (учти масштаб превью Read: обычно превью шириной 768 или 1092 — умножь координаты на
  `реальная_ширина / ширина_превью`).
- Передай углы (в любом порядке) как `--corners "x1,y1;x2,y2;x3,y3;x4,y4"`.
- Либо `--auto` (контурный детект; надёжно только на контрастном фоне — на светлом часто промахивается).
- Если обрезка не нужна — не указывай ни `--corners`, ни `--auto`.
- **Проверь результат** через Read; не подрезаны ли люди по краям — при необходимости расширь углы и повтори.

## 2. Запуск
```bash
~/.relatives_ai_venv/bin/python tools/scripts/photo_restore.py \
  --in /путь/исходник.jpg \
  --out 2_transcripts/photos_processed/restored/I<ID>_NN_Имя_описание.jpg \
  --corners "60,586;184,1744;1376,1724;1324,580" \
  --engine codeformer --fidelity 0.7 --scratches --save-mask --colorize
# опции: --auto | --no-color | --no-ai | --engine gfpgan|codeformer | --fidelity 0..1
#        --scratches [--scratch-scale 256,512,768 --scratch-thr 0.2 --scratch-grow 3 --save-mask]
#        --folds [--fold-strength 1.42]
#        --colorize [--color-engine flux|ddcolor --color-strength 2.2]
```
- ИИ-этап: апскейл ×2 + восстановление лиц.
- **`--engine codeformer`** (по умолчанию) — естественнее на старых/групповых фото; `--fidelity` 0..1 (выше = ближе к оригиналу, ниже = сильнее «дорисовывает»). `--engine gfpgan` — альтернатива.
- На Mac CodeFormer форсится на CPU (иначе конфликт MPS).
- Без `--corners/--auto` обрабатывается весь кадр.

## 2а. Царапины, заломы, трещины — `--scratches`
- Детектор из Microsoft «Bringing Old Photos Back to Life» (MIT) находит дефекты и строит маску. Модель LaMa
  закрашивает **только пиксели маски**. Остальное остаётся как в исходнике: проба 23.11.2026 — средняя разница
  вне маски 0,05 из 255, то есть шум JPEG.
- Шаг идёт **до** цвета и лиц. Иначе модель лиц приняла бы царапину на щеке за черту лица.
- `--save-mask` кладёт рядом `<out>_маска.png`. Посмотреть её — обязательно (через помощника, не в главной сессии).
- Настройка: `--scratch-scale 256,512,768` (по умолчанию; маски нескольких масштабов складываются: 256 ловит грубые
  заломы, 768 — тонкие царапины, 1024 почти ничего не видит), `--scratch-thr 0.2` (на 0.4 залом через лицо остаётся
  рваным; на 0.1 в маску попадают край плеча и завиток волос), `--scratch-grow 3` (расширить маску на N пикселей).
- Сетку мелких трещин на коже детектор не видит ни на каком пороге. Это ограничение модели.
- Если маска закрывает больше 15% снимка, скрипт предупредит: детектор принял за дефект узор или текст.
- Детектор путает с царапинами рамку, края кадра и надписи. На фото-документе (удостоверение, подпись)
  проверять маску особенно.
- Время: LaMa работает только на процессоре (на графике Mac падает) — около 20 с на кусок 1000×1000; снимок
  3300×4700 — около 4 минут. Тяжёлый прогон — в фоне.
- Одиночное пятно, которое детектор не видит: маска по цвету (пятно ≠ цвет ткани, напр. `R−B`) + `inpaint_lama()`.
  Не трогать содержимое сверх дефекта (фото историческое).

## 2а′. Длинный залом через весь снимок — `--folds`
- Сгиб бумаги тонкий (3–6 px), рваный, то светлее, то темнее соседей. Детектор царапин его почти не видит.
- `--folds` ищет один самый «линейный» путь через весь снимок — горизонтальный и вертикальный. Путь жёсткий,
  как сгиб, и ищется по карте, размытой вдоль линии. Иначе на лице он соскальзывает на контур подбородка.
- Путь считается заломом, если выделяется на `--fold-strength 1.42` (по умолчанию). Проба 23.11.2026, портрет 1910-х:
  залом 1,46, ложный вертикальный путь 1,38 — запас маленький, подобран на одном снимке.
  **Маску смотреть обязательно** (`--save-mask`). Ложный путь — поднять порог; залом не найден — опустить.
- Маска залома: сплошная полоса ±4 px по пути + сильные «линейные» пиксели в ±10 px. Складывается с маской царапин.
- Можно вместе: `--scratches --folds`.
- **Пока экспериментально, по умолчанию не включать.** На групповом снимке у хаты (1930-е)
  путь силой 2,07 прошёл сверху вниз по пиджакам и щели между людьми — ложный залом сильнее настоящего (1,46).
  Порогом их не развести. Включать только на снимке с явным сгибом через весь кадр и всегда смотреть маску.

## 2б. Раскраска — `--colorize`
- Пишет **отдельный файл** `<out>_раскраска.jpg`; чёрно-белая реставрация остаётся.
- **Почему без искажений:** от модели берётся только цвет (каналы a/b в Lab), а яркость — все контуры, лица,
  складки — из исходника пиксель в пиксель. Что модель дорисовала в чертах лица, на снимок не попадает.
- **Движок `flux` (по умолчанию)** — FLUX.3 klein edit через mflux, локально: ~7 минут, ~8 ГБ памяти.
  Различает кожу, губы, волосы, одежду. Сама картинка FLUX слегка перерисовывает лицо (моложе, другой рот) —
  поэтому она идёт только донором цвета, цвет слегка размыт. `--seed N` в photo_colorize.py — другой вариант цветов.
- **Движок `ddcolor`** — ~20 с, но на студийном портрете 1910-х залил всё одной охрой (как сепия; проба 23.11.2026).
  Годится, где на снимке явные предметы: улица, природа, интерьер.
- **Цвет — догадка модели, не факт.** Цвет глаз, платья, обоев из фото не узнать. Раскраску подписывать
  «раскрашено ИИ, цвета предположительные» и первой в `media` не ставить.
- `--color-strength`: по умолчанию 2.2 для flux (цвет со старой бумаги бледный; выбрано 23.11.2026), 1.0 для ddcolor.
- Чернила и штампы на документах модель красит наугад. Для фото-документа лучше раскрашивать вырезанный портрет.
- Отдельно, на любом готовом снимке: `~/.relatives_ai_venv/bin/python tools/scripts/photo_colorize.py --in BW.jpg --out C.jpg [--engine ddcolor]`.

## 2в. Точечные правки (опыт 23.11.2026: пляж 1930-х, семья у хаты)
- **Ч/б снимок обрабатывается в сером** сам (по насыщенности; `--bw` / `--color-photo` — явно). Иначе модель лиц
  дорисовывает цвет: у всех 10 человек у хаты вышли одинаковые голубые глаза.
- **Мелкие лица (< `--min-face 160` px) модель не трогает** — возвращает как были. На ~100 px CodeFormer рисует
  чужие глаза (у пожилой женщины: один закрыт, другой выпучен). Крупное лицо (≥ 260 px): `--fidelity 0.85`;
  на 0.5 модель «украсила» портрет — узкий нос, тонкие брови, чужой подбородок. Сверять с другими фото человека.
- `--erase x1,y1,x2,y2` — палец/чужой цветной предмет на ч/б карточке (по насыщенности). Если он у края — лучше
  обрезать `--corners` за ним: закраска у края оставляет тёмное пятно.
- `--stains` — рыжие/жёлтые пятна (ржавчина, подтёки) на ч/б карточке, по насыщенности (`--stain-sat 60`).
- `--lift x1,y1,x2,y2` — проявить фигуру в тени (местный контраст). Черт, которых нет, не появится.
- Раскраска: `--color-hint "…"` — подсказка по-английски, что известно (волосы, вода, одежда); `--color-unify` —
  участки одного забора одним цветом; `--color-recolor "рамка@образец[!]"` — синее (или всё, с «!») в рамке цветом
  образца (нога малыша — цветом его ступни); в photo_colorize.py ещё `--soften "рамка*0.7"` (розовые лица) и
  `--donor <out>_донор.png` — перекрасить без повтора FLUX (секунды вместо 7 минут).
- Тёмное (волосы, тени) раскраска сама держит почти без цвета и без синевы; цвет не выше 32 — иначе кожа «варёная».
- **Дорисовка** (призрачная фигура, глаз под пятном) — FLUX edit на вырезке, обратно вклеивается только рамка с
  мягким краем. Это реконструкция: файл с пометкой, в профиль — не как подлинное фото. Место фигуры сначала
  найти по сетке координат: первая попытка у хаты дорисовывала пустой проём на 100 px мимо.
- Проверять глазами помощника (Agent sonnet) после каждого прогона: лица крупно рядом с оригиналом.

## 3. Привязать к дереву
- Имя файла: `2_transcripts/photos_processed/restored/I<номер>_NN_Имя_описание.jpg` (NN — порядковый, чтобы не затирать).
  Оригинал не трогаем: он остаётся на этаже 1 (`1_sources/…`), реставрация — копия на этаже 2.
- Добавь снимок в поле `media` карточки человека (`3_research/tree/people/<Имя>.md`): `- "[[имя_файла.jpg]]"`.
  Первое фото в списке — портрет на схеме; реставрацию ставь первой, только если она лучше оригинала.
- Затем `rodo photo-catalog` — каталог `3_research/КАТАЛОГ_ФОТО.md` обновится.
- Порядок хранения фото — в `START_HERE.md`, раздел «Фото».
