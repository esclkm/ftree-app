## Пошагово для исполнителя (читай это первым)

### Свой Chrome — главный способ (с 02.10.2026, задача B1) [П]

Отдельный Chrome с профилем `$ARCHIVES_LOCAL/browser-profile` (вне проекта, git и облака). Владелец дерева вошёл в нём
один раз, Chrome сам хранит вход и пароли; вход пережил два перезапуска Chrome подряд [П 02.10]. Управляет скрипт, не
модель: в разговор приходит только итог. Панель браузера приложения — только чтобы владелец посмотрел глазами.
Этот раздел главнее слов «в панели браузера» ниже: там — как было раньше, а признаки страниц и адреса верны и сейчас.

```bash
B="rodo browser-cdp"
$B start                      # уже запущен — ничего не сделает
$B login-check gaso           # «вошёл» → дальше; «не вошёл» — открыл вход в окне Chrome: владелец входит (пароль
                              # подставит Chrome), Claude ждёт «вошёл»; код 3 и «✋» — капча или лимит: стоп, сказать владельцу
$B nav <url>; $B text 3000    # открыть и прочитать текст (вместо navigate + get_page_text)
$B eval '<js>'                # сниппеты ниже — как есть; длинный ответ уходит в файл
$B stop                       # в конце работы: пока Chrome открыт, его порт доступен любой программе на этом Mac
```
Перезапускать Chrome без спроса нельзя: 02.10 так потеряли вход ГАСО (тогда ещё без «Продолжить с того же места» —
теперь `start` включает это в профиле сам). cookie, хранилище и пароли скрипт читать отказывается — не обходить.

Сканы качает `gaso_download.py` (ниже) — без браузера; Chrome нужен только для описи, кабинета и адресов картинок.

Правила, которые нельзя нарушать:
- **Пароли, cookie, токены сессии — никогда не просить у владельца и не копировать из страницы** в `curl`, файлы или чат. Входит владелец сам, в своём Chrome проекта (раздел выше).
- Вход ГАСО живёт до закрытия браузера. В своём Chrome он переживает перезапуск только с «Продолжить с того же места» (`start` включает сам) [П 02.10]; в панели приложения слетал (01.10). Всегда `login-check gaso`, а не надейся.
- Капча — стоп, скажи владельцу. Ответ 401/403/429 — стоп, не повторять.
- Скачивать сканы **только пока абонемент действует** (иначе это обход оплаты). Один поток, пауза.

## Что это и когда
ГАСО — архив в Смоленске. На портале выложены сканы метрических книг церквей (рождения, браки, смерти), консисторских копий и исповедных ведомостей. Нужен для предков из Смоленской губернии. Фонд 48 — Смоленская духовная консистория [П].

Нужен ли, если можно письмом: архив отвечает на запрос по e-mail (адрес «для запросов» — на gaso-smolensk.ru/kontakty/); черновики писем — в `<папка поиска>/requests/`. Записям больше 100 лет, доступ не ограничен [П из текста письма].

## Вход
- Портал — «Находка-СФЕРА», кабинет по e-mail и паролю. **Входит только владелец дерева**, в своём Chrome проекта (Claude вводить пароль не вправе даже по просьбе) [П].
- Регистрация требует **российский номер телефона** [П 30.09]. Данные кабинета не менять, чужие данные в проект не писать.
- Абонемент «Удалённое использование», **52 руб. за час**, покупает владелец [П]. Появился в кабинете не сразу: купили 30.09 вечером, виден был 01.10 утром [П]. Проверка: «Личный кабинет → Мои абонементы / Журнал заказов».
- В просмотрщике сканов есть обратный отсчёт «Осталось ЧЧ:ММ:СС». Идёт ли отсчёт, пока просмотрщик закрыт, — см. строку ниже.
- [П косвенно, 09.10] Отсчёт идёт только в просмотрщике: 01.10 за час скачали `curl` 8 119 разворотов, а 09.10 в «Мои абонементы» осталось 00:46:46. Значит, прямые адреса картинок время не тратят; просмотрщик открывать только чтобы узнать шаблон адреса нового дела — и сразу закрыть. Качать — только пока абонемент в кабинете есть (остаток > 0). Фонд 10 (ревизские сказки) — шаблон адреса ещё не известен.

## Как ходить по описи (вход не нужен)
Адреса `https://portal.gaso-smolensk.ru/page/portal/opisView.jsf?id=<ID описи>` (ID — выше). Страница на JSF: кнопки — ссылки, не адреса. Список дел — вкладка «Единицы хранения».
Рабочий скрипт для `mcp__Claude_Browser__javascript_tool` (после `navigate`): открыть вкладку, показать по 200 строк, перейти на 3-ю страницу, найти дело 526 и открыть его:
```js
const w=ms=>new Promise(r=>setTimeout(r,ms)); [...document.querySelectorAll('a')].find(a=>a.textContent.trim()==='Единицы хранения').click(); await w(2500); const s=document.getElementById('form:j_idt223:data-table:j_id19'); s.value='200'; s.dispatchEvent(new Event('change',{bubbles:true})); await w(3500); [...document.querySelectorAll('.ui-paginator-page')].find(a=>a.textContent.trim()==='3').click(); await w(3500); setTimeout(()=>[...document.querySelectorAll('table tbody tr')].find(tr=>/Д\. 526\./.test(tr.innerText)).querySelector('a').click(),100); 'ok'
```
Заметки: id `form:j_idt223:data-table:j_id19` сгенерирован сайтом и может смениться — найди `select` через `find` («записей на странице») и подставь. Номер страницы пагинатора (3) зависит от дела; список всех строк оп.6: замени последнюю часть на `.map(tr=>tr.innerText.replace(/\s+/g,' ')).join('\n')` [П].
После клика откроется `…/page/sources/sourceInfo.jsf`: там «Ф. 48. Оп. 6. Д. 523.», «Количество листов: 218», кнопка «Просмотр сканов». (Клик, не `find`: кнопка рисуется с задержкой — сначала `await w(3500)`.)
Уже снятые выписки описей — `1_sources/found/archives_online/gaso_smolensk/ГАСО_ф48_описи_*_выписка_*.txt` — **сначала смотри их**, в портал идти не надо.

## Как читать дёшево
- **Скачанные книги читать и искать в них людей — только по навыку `metric-search`** (Manuscript-OCR на Mac один раз, поиск по тексту, вырезки владельцу). Ниже — история; путь через `gaso_flow.py` и qwen3-vl устарел.
- **Скачанные сканы не читать глазами в чате.** 01.10 сессия «ГАСО Смоленск»: 378 шагов, до 559 тыс. токенов контекста, ≈74 $ [из журнала оркестрации]. Главные траты: сотни картинок 1000×2400 в чат, `xargs -P 12–16`, повторные чтения, помощники без лимита.
- Порядок: (1) список «что ищем» (`rodo tree targets`); (2) карта книги — `rodo gaso-index catalog --book 517`, `sample`, `probe`, `locate --year 1894 --section births` (год/раздел/месяц на выбранных развёртках, локальная модель qwen3-vl через ollama; модель предлагает опоры, не доказывает); (3) `rodo gaso-flow init … run … review` — локальный поиск имён по выбранным файлам с журналом, лимит 20 страниц за запуск; (4) только найденное — одну картинку обрезкой (колонка имён) показать владельцу или прочитать самому.

- Метрика ведётся по старому стилю (−12 дней в XIX веке, −13 с 1900 г.) — в запись факта писать «ст. ст.».

## Как скачать без участия владельца
- [П] **Рецепт, который работал 01.10:** картинка по прямому адресу `curl -s --max-time 90 -o файл.part -w "%{http_code}" "<адрес>"`, без cookie; 200 → переименовать `.part`, иначе удалить. Таким способом за один час абонемента скачали 25 книг, 8119 разворотов ≈2,7–2,9 ГБ (фонд 48: оп.6 д.516–526, 581–583, 596–601; оп.3 д.320; оп.4 д.241, 242, 867, 868).
- Нужен владелец для: входа, покупки абонемента, подтверждения, что абонемент идёт. Дальше — без него.
- **Рецепт теперь** — `gaso_download.py`: один поток, пауза, продолжение, манифест. Параметры: `--kind l|l867|page|gen|custom`, `--opis`, `--delo`, `--first/--last`, `--out`, `--pause 1.5`, `--max-miss 8` (подряд 404 = конец книги), `--retry-missing`, `--dry-run`, `--subscription-active` (без него сеть не трогается). Манифест `manifest.jsonl` рядом с картинками: номер, адрес, статус, размер, sha256, время. Уже скачанное и записанные 404 пропускаются. Останавливается на 401/403/429 и если пришло не JPEG (скорее всего, абонемент кончился / страница входа).
- Скорость: ≈1,5–2 с на разворот → книга в 500 разворотов ≈ 15 мин, 25 книг за час **не успеть** одним потоком [В]. Поэтому приоритет: сначала дела, нужные «что ищем» (см. таблицу дел в 00_ОПИСЬ), остальное — со следующим абонементом. Идея [В]: два-три потока разных дел с паузой 2 с (не 12–16, как было), если сервер ответит спокойно.
- [В] Если картинка однажды потребует вход (сейчас не требует): качать внутри страницы через `fetch` в `javascript_tool` и сохранять через `<a download>` (приём — скилл `archive-familysearch`), по одной странице и с паузой. Cookie из страницы в `curl` или файлы не переносить; если и так не выходит — стоп и вопрос владельцу.

### Абонемент кончился — просмотрщик притворяется «оцифровки нет» (из vdov, CC BY 4.0) [В — у нас не случалось]
Когда лимит выбран, просмотрщик отдаёт `302` на страницу подписки для **любого** дела, а вместо JPEG приходит HTML-заглушка
около **1,3 КБ**. Массовая проверка в этот момент даёт ложное «оцифровано 3 дела из 118» (у vdov после оплаты тех же дел
оказалось около 60).
- **Перед любой массовой проверкой убедиться, что доступ жив:** один запрос на заведомо оцифрованном деле (например, из уже
  скачанных) — `200` и JPEG, а не `302`/заглушка.
- Файлы меньше 5 КБ — заглушки: `find <папка> -name '*.jpg' -size -5k -delete`. `gaso_download.py` это делает сам: останавливается
  на `302`/401/403/429 и на ответе не-JPEG или меньше 5 КБ, а заглушку, оставшуюся от прежнего запуска (в том числе от `curl`-
  цикла), удаляет и качает заново — раньше считал её скачанной страницей (исправлено 03.11.2026, тест `test_gaso_download.py`).

### Дело, поделённое по алфавиту селений — карта «кадр → селение» (из vdov, CC BY 4.0) [В]
Дело на две-три тысячи разворотов без внутренней описи не охватить сплошным просмотром. Выкачать **каждый сотый кадр**
(шапки), склеить верхние полосы в одну картинку и прочитать — получится соответствие «кадр → селение». Шаг по плотности: 100 — дело
в тысячи кадров; 20 — поймать границу конкретной сказки; 5–10 — когда участок уже найден и нужен первый лист. У нас это то же,
что `ocr_folder.py --top 0.22 --only $(seq -s, 20 5 240)` в разделе про ревизские сказки ниже; тот же приём находит границы
приходов внутри сборной книги метрик.
- **Дело может быть томом, а не делом целиком:** ревизии и метрики уезда делят по алфавиту селений («А–П» — один номер, «С–Я» —
  другой, во втором заголовок описи часто пустой). Не нашёл селение — проверить, не обрывается ли дело на букве (конец подшивки
  виден по листу-заверителю): селение на «У» тогда лежит в другом томе.
- **Формула «кадр ↔ лист» плавает внутри одного дела** (вставки, вклейки, литерные листы): у vdov на одном деле замеренный сдвиг
  дал пять разных формул с разбросом в 55 кадров. Пересчитывать **на каждом новом участке** по карандашной пагинации в углу кадра.

## Сторонние указатели описей: то, чего нет в поиске самого архива (из vdov, CC BY 4.0) [В — у нас не открывали]
Рядом с официальным каталогом живут указатели, набранные исследователями вручную с тех же описей. Они ищут по подстроке в
заголовке дела, показывают дела **независимо от оцифровки** (портал ГАСО показывает только оцифрованное и потому отвечает
«нет», когда дело есть, но лежит бумажным). Искать **по селу прихода, а не по своей деревне** — в заголовок попадает церковь
и её село.
- **genindex.ru** — указатель пользовательских индексов: кто какой источник уже расписал по персонам; фильтр по региону, типу
  документа и годам. Перед тем как читать книгу сами — посмотреть, не расписана ли она. Открыт отовсюду. Для Familio — см. там.
- **inv.velikie.org** — набранные волонтёрами заголовки описей и книг ЗАГС; берёт фонды, до которых официальный поиск не
  дотягивается. Открыт отовсюду.
- Поля формы снимаются разметкой: `curl -sS <адрес> | grep -oE 'name="[^"]+"' | sort -u` — это и есть документация запроса.

## Мёртвый домен — через Wayback CDX (из vdov, CC BY 4.0) [В]
Сайт краеведов из списка (у vdov — `smoltree.ru` с мещанскими управами Смоленской губернии и `forum.smolkg.ru`, оба не
разрешаются в DNS) — **не тупик**: файлы часто сохранил веб-архив.
```bash
curl "http://web.archive.org/cdx/search/cdx?url=<домен>&matchType=domain&output=text&fl=original,timestamp,statuscode&collapse=urlkey&filter=statuscode:200&limit=2000"
curl -L "https://web.archive.org/web/<timestamp>id_/<url>" -o файл.pdf     # id_ — оригинал без обёртки
```
CDX иногда отвечает 504 — повторить. **Качать по одному файлу, пауза 2–3 с** (четыре потока получают бан и половину ошибок).
Уникальные копии сразу класть в постоянную папку проекта, не во временную (она пропадает между сессиями).

## Ревизские сказки (ф. 10) — читать по алфавиту, а не подряд [П 13.10]

**Как устроено дело.** Разворот 1 — карточка архива, 2 — титул, 3 — первая сказка. На 4–5 — **алфавит общества**:
«№ — деревня — лист — душ муж. — жен.». Потом сказки по деревням в порядке алфавита. После последней деревни —
алфавит следующего общества. Одно дело может держать 3–4 общества (д. 1242: Лопинское, Спасское, Рачевское, Боровское).
**Д. 1242 и 1244 — копии** тех же сказок (их писали в нескольких экземплярах), но другой рукой. Машина читает разные
почерки по-разному: во втором экземпляре «Ѳомы сынъ Лаврентій» прочиталось, в первом вышло бессмыслицей.

**Порядок (≈15 разворотов на общество вместо сотен):**
1. `ocr_folder.py <дело> --only 1-6` — алфавит первого общества.
2. Сдвиг: прочитать один разворот в середине, найти в шапке «деревни X», сравнить с листом X по алфавиту
   (д. 1241: разворот ≈ лист + 3…4; д. 1242: ≈ лист + 7).
3. Нужная деревня — `--only <лист+сдвиг−2>-<лист+сдвиг+6>`. Проверка, что деревня целая: «Итого мужескаго пола
   на лицо» по разворотам в сумме = число душ из алфавита (пример: 7+5+13+9 = 34).
4. Следующее общество: его алфавит стоит на развороте ≈ последний лист + сдвиг + 1…3.
5. Если сдвиг сбился: `--top 0.3 --only $(seq -s, A 4 B)` — шапки каждого 4-го разворота как оглавление.
   Шапка только в 1,7 раза быстрее полного разворота (6,4 с против 10,9 с), поэтому она годится для поиска, а не
   вместо полного чтения.
6. Каждую деревню-цель прочитать **во всех экземплярах** (например 1241 + 1242 + 1244).

порядке. Возрасты на 1816 и 1834 г.
**Сказка 1850 г. (ф. 10, оп. 3, д. 210) — без алфавита** [П 13.10]: деревни идут подряд.

## Яндекс «Поиск по архивам» — проверить первым
Бесплатно, из Польши открывается без входа [П: `curl` без cookie и прокси 30.09]. Ищет по распознанному тексту метрик, исповедных, ревизских сказок московских и других архивов (≈22 млн листов, понимает дореформенное «ѣ/ъ»). Смоленского архива (ГАСО) там нет [П].
Как искать (рабочий скрипт, ничего не пишет на диск, кроме вывода):
```python
import urllib.parse,subprocess,re,json,html
def search(q,extra=''):
    url="https://yandex.ru/archive/search?text="+urllib.parse.quote(q)+extra
    h=subprocess.run(['curl','-sL','-m','60','-A','Mozilla/5.0 (Macintosh)',url],capture_output=True,text=True).stdout
    m=re.search(r'<script id="__NEXT_DATA__"[^>]*>(.*?)</script>',h,re.S)
    d=json.loads(m.group(1))['props']['pageProps']
    print(q,'всего',d.get('totalDocs'))
    for it in d.get('items',[])[:15]:
        print(it['id'],it['parentId'],it['namepath'],it['sheetPageNumber'],it['snippet'][:300])
search("Анна Лесовская")
```
Страница скана: `https://yandex.ru/archive/catalog/<id документа>/<номер скана>` (там тот же `__NEXT_DATA__` с текстом). Запросы писать по-старому: «Лесовскій», «Нилъ». Фильтр по разделу «Периодические издания» через адрес не включился [П] — руками в браузере. Не знаем, как сайт отнесётся к частым запросам [В]: пауза 3 с, без параллели; капча — стоп.
Риск: распознавание машинное, год и имена проверять по скану (ссылка на него в каждой записи).
**14.10.2026 — поиск «на паузе»** [П]: страница поиска уводит на главную, там объявление о работах в дата-центре; в
`__NEXT_DATA__` пусто, `_next/data/…/search.json` отвечает 307. Проверять раз в несколько дней, скрипт выше — как было.
**01.11.2026 — поиск только со входом** [П]: без cookie страница поиска и каталог уводят на главную, в `__NEXT_DATA__` — только `isAuthenticated`, `loginUrl`.
