# Самопроверка — линзы

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes self-review`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed self-review 2>/dev/null || rodo skill-notes --embed self-review 2>/dev/null || true`

> Скрипты проверки доказывают, что файл **правильно устроен**: ссылка ведёт куда надо, у факта есть источник,
> линия жизни не заходит за смерть. Они не могут доказать, что **источник действительно это говорит**, что сайт
> **покажет** правку родне, что снимок **не выдаёт** лишнего. Линзы — только эта вторая половина.

## Зачем

Каждая строка раздела «Ошибки, которые уже были» в `CLAUDE.md` прошла все проверки с нулём ошибок. Биография
не встала в профиль, но ссылка была цела. Тёзка получил чужую биографию, но связь была взаимной. Скрипт в коммите
не компилировался, но на диске был исправен. «Пётр рос с ними» — у факта был источник, только источник этого не
говорил. Общее у всех промахов одно: проверяли **файл, который правили**, а не **то, что из него выходит** —
страницу у родственника, соседнюю карточку, коммит, картинку в интернете.

Линза — один вопрос, который заставляет выйти за пределы правленого файла.

---

## Порядок

1. **База — сначала.** Все проверки из `CLAUDE.md` («Проверки»; пояснения — навык `tree-maintenance`) — по нулям; правил код сайта — ещё
   `cd web && npm run build` (типы → тесты → сборка). Не ноль — сначала чинить: линзы считают базу зелёной.
2. **Что проверяем.** `git status --short` — какие файлы тронуты, и по ним — какие семейства линз нужны:

   | Тронуто | Семейство |
   |---|---|
   | `tools/**/*.py`, `*.sh`, `*.mjs`, `web/site_assets/`, `web/src/`, `.claude/`, хуки git | **К** — код |
   | `.md` на этажах 2–4 (карточки, биографии, расшифровки, анкеты, переводы, описи) | **О** — описания |
   | картинки где угодно, строки `media` / `photos` / `found_photos`, `00_ОПИСЬ_*` | **Ф** — фото |

   Полная проверка проекта («проверь всё») — все три семейства по всему проекту, не только по правке.
3. **Каждая линза нужного семейства — обязательна.** Нечего проверять — «Н/П» с причиной; молча пропущенная
   линза читается как пройденная.
4. **Вердикт:** ✅ ПРОЙДЕНО · ❌ ОШИБКА · ❓ НЕЯСНО. «Неясно» — показать владельцу дерева: что смотрел, что увидел, почему
   не решить самому. Неясное в пройденное не превращать.
5. **Доказательство — вывод команды или строка файла** (`путь:строка`), а не «должно работать».

# К — код (`tools/`, `web/`)

## К1 — Кто ещё пишет этот файл?

Скрипты правят файлы, которые правит и человек: карточки, биографии, каталог. Правка, которая сегодня верна,
завтра может быть затёрта автоматикой — или сама затрёт ручное.

1. Какие файлы код **пишет**? Для каждого — кто ещё его пишет. Уже есть такие писатели:
   хук после правки (`hook.py` → `card_doctor --fix`, `check_lifeline --fix` — дети в линиях жизни родителей),
   перед коммитом (`sync.py pre-commit`: `anchors fix-staged`, `assign_lineage`, `texts_section`, `photo_catalog`,
   `check_lifeline --fix`, `moves.py fix-staged`), перед push — `tools/ci.sh` и сборка web/ на чистой копии коммита, при push в master в фоне
   (`bio_autotranslate` → отдельный коммит, потом `publish_site.sh`).
2. Пишет файл, который правит и человек, — есть ли защита (`safe_output.safe_open`, свой раздел «руками не правим»,
   правка только своей строки)? Нет — ❌.
3. **Запустить дважды.** Второй запуск не должен менять ничего: `rodo <скрипт> && git diff --stat`
   → ещё раз → тот же `diff`. Меняет — скрипт не устойчив, каждый коммит будет «шуметь».
4. Порядок: если два писателя трогают один файл в одном коммите (pre-commit), кто последний — тот и прав. Выписать.

Было: сборщик вернул ошибку, исправленную руками (отсюда `safe_output`); `card_facts` сам дописывал
ссылку на биографию — снято.

## К2 — Тёзки: найдёт ли код того самого человека?

В дереве сотни людей и много тёзок (два человека с одним именем и фамилией, два «дяди Коли», пять Марий). Любой поиск по
имени рано или поздно попадёт на чужого.

1. В правке найти каждое место, где человек, место или файл ищутся **по имени или его куску**: `grep -n "stem\|name\|startswith\|\[:4\]\|in text" <файл>`.
2. Для каждого: что будет, если имён два? Правильный ключ — `cr_id` (`father_id`, `children_id`); имя — только
   подпись. Сравнение имён — целым словом, не по первым буквам.
3. Прогнать на настоящих тёзках своего дерева: два человека с одним именем (по `cr_id`), похожие имена (`Мария` / `Марианна`), `Мария (2007)`.

Было: человек получил биографию другого, с похожим именем, — сравнивали 4 первые буквы; у 30 событий `person`
вёл на однофамильца; 25 связей ушли на тёзок.

## К3 — Что увидит родственник?

Правка в коде существует ради страницы на сайте. Пройти путь до конца:
**карточка / биография → `site_export.py` → данные → `web/src` → страница → каждый язык → телефон.**

1. Собрать: `rodo build-site`. Число в итоговой строке («людей …, без биографии …, фото …») —
   сравнить с прошлым запуском: неожиданно упало — ❌.
2. Открыть страницу человека, которого правка касается, — **по номеру** (`cr_id` → адрес), не по заголовку.
3. Посмотреть **все** вкладки языков RU / PL / ES / EN: переводы повторяют структуру, и то, что русский прячет,
   в переводе может торчать.
4. Найти **все** места, где показывается изменённое поле: `grep -rn "<поле>" tools/scripts/site_export.py web/src`.
   Обычно ломается не то место, которое делали, а соседнее (галерея, карта, «Места и эпохи», дерево).
5. Узкий экран (телефон) — если менялась вёрстка или стили.

Было: биография не встала в профиль (строка «Биография (такая-то ветвь):» вместо «Биография:»); заголовок
«# Имя» + «В дереве» прятал линию жизни (`own_head`); линия жизни дублировалась в тексте.

## К4 — Что уходит в интернет?

Сайт в интернете, и сейчас он **открыт без пароля** (до `open_until` в `ftree.toml`, `[site]`; сборка вписывает его в `functions/_middleware.js`).
Всё, что попало в `4_outputs/site/`, видит любой.

1. Правка добавляет на сайт новое поле, файл или раздел? Выписать, **что в нём может оказаться** о живых людях:
   телефон, почта, адрес с номером дома, номер документа, дата рождения живого, болезни, конфликты в семье.
2. Защита на сайте — только текстовая: `no_contacts` (телефон с кодом страны, почта), `no_address` (номер дома),
   `lock_files_with_contacts` (PDF с такими строками — по паролю), `doc_scans_of_living` (снимок документа живого из
   галереи — по паролю, по словам в имени файла). Номер свидетельства или паспорта **в тексте** и снимок документа,
   в имени которого нет слова «паспорт», «свидетельство»… — она **не видит**. Если новое может их нести — ❌, пока не
   решено, как прятать.
3. Секреты: `netlify.toml`, `PROXY_KEY`, пароли `USER_*` — не в git, не в собранном сайте:
   `git diff --cached | grep -iE "(key|secret|password|token)\s*[:=]\s*['\"][^'\"]{6,}"` — пусто (имя секрета,
   `env.PROXY_KEY`, в коде быть может; значения — нет).

## К5 — Где это запустится?

Код проекта работает не только в терминале владельца дерева.

- **Git-хук без nvm:** у `pre-commit` / `pre-push` другой `PATH` — `npm`, `node`, `claude` может не быть (см. `site_export.npm()`).
- **Фон после push:** `publish_site.sh` идёт в фоне; упал — никто не увидит, кроме лога. Ошибку видно?
- **Страна родни:** в некоторых странах (например, в Беларуси) `*.pages.dev` и `*.workers.dev` режут провайдеры;
  внешние серверы (карты OSM) требуют `Referer`. Новый внешний адрес в правке — проверить, откроется ли оттуда.
- **Пределы:** файл больше 25 МБ Cloudflare не примет (`MAX_FILE`); ИИ-перевод — модель и её лимиты.
- **Нет сети / нет Pillow / нет `pdftotext`** — скрипт падает или тихо делает не то? Тихо не то — ❌.

## К6 — Правда ли написано в шапке?

У скриптов проекта подробные шапки, а правила — в `CLAUDE.md`, `START_HERE.md`, `web/README.md`, в скиллах.
Каждое предложение там — обещание.

1. Каждую новую или изменённую фразу в шапке, комментарии, сообщении об ошибке, `CLAUDE.md`, скилле — проверить
   по коду: найти строку, которая делает её правдой, или исправить фразу.
2. Слова-сигналы: *всегда, никогда, само, сам, руками не правим, только, все, не трогает*.
3. Поменял поведение — где ещё оно описано? `grep -rn "<имя скрипта или поля>" CLAUDE.md START_HERE.md .claude/ tools/scripts/*.py`.
   Старое описание, которое врёт, хуже, чем никакого.

## К7 — Поймает ли проверка ошибку?

1. **Тесты сайта** (`web/test`, Vitest): для каждого нового теста назвать правдоподобную поломку кода, которую
   он **не** заметит (перепутанный `&&`/`||`, обратная сортировка, пропущенный тёзка). Заметная поломка — добавить
   пример, который её ловит. Проверить сам тест: сломать код, увидеть красный, вернуть.
2. **Python-скрипты без тестов** (их большинство): доказательство — прогон на настоящем дереве **до и после**
   с числами («check_lifeline: 0 ошибок → 0», «на сайте людей 504 → 504, без биографии 31 → 30»).
3. **Новая проверка** (`check_*`): подложить ей заведомо плохой пример — ловит? Не ловит — она ничего не проверяет.

## К8 — Соберётся ли то, что уходит в коммит?

На диске — одно, в коммите — другое.

1. Добавлял файл кусками или в нём чужие правки — проверить **подготовленную** версию:
   `git show :tools/scripts/x.py > /tmp/x.py && python3 -m py_compile /tmp/x.py` (был случай: коммит не компилировался).
2. Новые файлы и папки — добавлены? `git status --short | grep '^??'`.
3. `pre-commit` сам добавит производное (ветки, «Рассказ», каталог фото) — посмотреть `git show --stat HEAD` после
   коммита: нет ли там чужого или неожиданного.

# О — файлы описаний (карточки, биографии, расшифровки, анкеты, переводы)

## О1 — Источник правда это говорит?

`card_doctor` проверяет, что у факта **есть** ссылка на источник (F2). Что источник говорит **именно это** — не
проверяет никто.

1. Для каждой новой или изменённой строки факта и каждого нового предложения биографии — открыть источник на
   указанном месте (страница, `мм:сс` в расшифровке) и сравнить **дословно**.
2. Вывод из двух фактов («значит, он жил с ними», «рос под одной крышей») — это вывод проекта, а не слова источника.
   Такое — `уверенность: низкая` и на чём держится, или убрать.
3. Прежде чем поставить двух людей в одно предложение — сверить их годы: могло ли это быть?

Было: «Пётр рос с ними под одной крышей» — ему было пять, источник этого не говорил.

## О2 — Уверенность соответствует происхождению?

Порядок доверия: `семья` > `найдено` > `чужое дерево` > `вывод проекта`.

1. Факт только из чужого дерева (MyHeritage) — подсказка, не выше `уверенность: низкая`, пока не подтверждён.
2. Догадка помечена: выведенная фамилия — `surname_inferred`; предположение — `низкая` + основание.
3. Здравый смысл по датам: мать младше 13 при рождении ребёнка, ребёнок старше родителя, человек за 110 —
   сразу вынести и проверить (ребёнок «1934» при матери 1925 г. р.).
4. «Папа думает, что…» — это мнение (`по словам …`), а не установленный факт.

## О3 — Даты: какой календарь и какой возраст?

1. **До 14.02.1918** — два календаря. Разница двух дат одного события в 12 дней (XIX век) или 13 (с марта 1900) —
   сначала проверить стиль, это не противоречие. В строке факта — «ст. ст.» / «н. ст.».
2. **Оговорка пожилого:** «умер в 93-м… двух месяцев не дожил до 90» — верен возраст. Год-оговорку не выносить
   в тексты и карточки (в расшифровке остаётся).
3. **Год из возраста** — сразу в `born` / `died` карточки, промежутком: `died: BET 2005 AND 2006` (все виды дат — навык `dates`, «Даты — как в GEDCOM»).
4. Дата против истории места: Брестчина 1921–1939 — Польша; событие, которое противоречит власти того года, — ❓.

## О4 — Одна правда во всех местах

Один факт живёт в нескольких местах: карточка, биография, поля дерева (`born`, `died`, места), событие дерева,
анкета `ВОПРОСЫ_*`, «Открытые вопросы».

1. Для каждого изменённого значения — найти **старое** везде: `grep -rn "<старое значение>" 3_research 4_outputs`.
   Исправил в одном месте — исправь во всех (кроме расшифровки: там слово в слово).
2. Закрыл вопрос разговором или находкой — зачеркнуть (✅) и в биографии, и в анкете `ВОПРОСЫ_*`, где он задан.
3. Новый вопрос из разговора — есть в «Открытых вопросах» человека?
4. Новый человек из рассказа — есть карточка или строка в списке людей из записей, которых ещё внести в дерево?

## О5 — Про того ли человека этот текст?

Правила из `CLAUDE.md`, навыков `biography`, `dates`, `card-rules`, `photos`, `site` и `00_ИНДЕКС.md`, которые скрипты проверяют лишь частично:

- **линия жизни — только своя**: `check_lifeline` ловит даты за смертью и ссылки на внуков, но не событие
  ребёнка, записанное **словами** без ссылки;
- **«Семья»** — не перечень родни (его показывает карточка), а то, чего в карточке нет;
- **не про наши задачи**: цели самого исследования (заявления, документы для властей, «годится ли для заявления») —
  только в отдельном файле задач, ни в биографиях, ни в карточках (`grep` по их словам в `biographies/` и `people/` — пусто);
- **правка — молча**: `grep -rn "<имя владельца> \(уточн\|исправ\|поправ\|сказал\)" 3_research` — пусто;
- **имена — как сказано** (домашние и диалектные формы — как в записи), отчеств в карточках нет;
- один человек в файле, порядок разделов, время, рассказ — отдельные линзы О9–О12 ниже.

## О6 — Можно ли это показать тем, о ком написано?

Биографии уходят на сайт, сайт читают родственники — в том числе те, о ком текст.

1. Живые люди: номер паспорта или свидетельства, запись ЗАГС, точная дата рождения, болезни, долги — нужно ли это
   на сайте? Скрыть номер документа сайт не умеет (К4) — значит, не писать его в текст, который туда уходит.
2. Больное в семье (конфликт о доме, обиды, этничность, болезнь) — смягчено, без оценок, без «кто виноват»?
   Если сомнение — ❓ и спросить владельца дерева.
3. Слова о человеке — чьи? «Был жадным» без «по словам …» — это приговор от имени проекта.

## О7 — Расшифровка осталась расшифровкой?

1. Текст источника — **слово в слово**, с оговорками и ошибками речи. Выводы — только в «Примечании проекта».
2. У каждого куска — таймкод (аудио) или страница (архив): без него О1 невозможно проверить.
3. Сомнительное место — `[?]` или `[неразборчиво]`, а не угаданное слово.

## О8 — Встанет ли текст на своё место на сайте?

Сайт берёт текст по жёстким меткам. Сломанная метка — рассказ молча исчезает.

1. В карточке — строка **ровно** `**Биография:** [[файл.md]]` (без уточнений в скобках, без `#раздела` для своего файла).
2. Переименовал заголовок — `rodo anchors check` = 0; поправлены ссылки `[[…#Заголовок]]`.
3. Под «Линией жизни» — сразу таблица, без абзацев.
4. Менял структуру (таблицы, заголовки) биографии с переводом — открыть на сайте RU / ES / PL (К3, п. 3):
   старый перевод повторяет старую структуру, пока автоперевод его не догонит.
5. Новая страна или место без `parent_place` — раздел «## Государства по годам», подписи — в `ERA_TR`.

## Биография: устройство (О9–О12; родители и дети — О14)

Четыре линзы — для каждой правленой биографии, и для новой, и для старой. Скрипт `check_bio.py` (сам — после правки
биографии, хук) ловит механическое: сколько людей, в каком порядке заголовки, по порядку ли даты в таблице и в
заголовках. Всё остальное — глазами: скрипт видит заголовки и даты, но не видит смысла.

База: `rodo check-bio --file <биография>` — 0 ошибок. Старый файл рода (список `LEGACY` в
скрипте) предупреждает «разнести» — это долг, а не пропуск: взялся за человека из такого файла — выноси его в свой.

## О9 — В файле ровно один человек?

1. Одна строка «**В дереве:**» на файл (скрипт). Разнёс человека из файла рода — убрать файл из `LEGACY`, когда
   в нём остался один.
2. **Глазами — чужая жизнь абзацами.** Скрипт считает только разделы со строкой «В дереве». Три абзаца о жизни сына
   внутри раздела отца — это биография сына без заголовка. Её место — в файле сына, у отца — одна фраза и ссылка.
3. Про другого человека в тексте — только то, **что меняет жизнь этого**: «сын уехал в Минск — и отец остался один
   на хуторе», а не где сын учился и на ком женился.
4. Общее для рода («Историческая канва», «Сводка по линии») — не в биографии человека: в файле исторического фона
   или в индексе ветки. У человека остаётся то, что с ним самим из этой истории случилось.

Было: муж, жена и пятеро детей в одном файле — в профиле мужа встали жена и дети; в файле деда внутри были
его дети — разнесены по своим файлам.

## О10 — События идут по времени?

1. **Линия жизни** — строки от ранних к поздним (скрипт). Строка-период («1941–1946 — всё это время в колонне») —
   на месте своего **начала**, а не после последнего года. Приблизительная дата («1950-е», «ок. 1945») скрипту
   даёт запас — глазами проверить, что она стоит там, где читатель её ждёт.
2. **Разделы о жизни** — от детства к старости (скрипт — только по году в заголовке). Раздел без года в заголовке
   («Паркет», «Хранительница рассказов») — глазами: к какому времени он относится и стоит ли он там.
3. **Внутри раздела** — абзацы тоже по времени. Воспоминание из будущего («потом, в 1970-х, он скажет…») — можно,
   но словами показать, что это забегание вперёд.
4. «Каким он был», «Расхождения», «Открытые вопросы» — не по времени, а по смыслу: скрипт их не проверяет.

## О11 — Это рассказ, а не конспект?

Биография — связный текст, который родственник прочтёт как историю. Скрипт предупреждает, когда в разделе
о жизни больше половины строк — списком или таблицей. Остальное — глазами, каждый изменённый раздел:

1. **Абзацы, а не пункты.** Список — только там, где он и есть список (награды, адреса); жизнь — абзацами, с
   переходами «после войны…», «через два года…», «потому что…».
2. **О нём, а не о нас.** Нет «мы выяснили», «в записи 05 папа сказал», «поиск показал», «для книги», «вывод».
   Откуда сведение — одной строкой курсивом в начале раздела (`*А05, 20:33–22:55.*`), дальше — просто рассказ.
3. **Без служебных знаков в тексте**: ⭐, `[вывод]`, `[?]` посреди фразы, таймкоды внутри предложений. Сомнение —
   словами («кажется, это было в 1936-м — точнее папа не помнит»).
4. **Заголовок — по теме жизни** («Война, 1944–1945», «Дом на Садовой»), не по источнику или нашей задаче
   («Что добавила пятая запись», «Три сюжета для книги») — скрипт предупреждает.
5. **Прочитать вслух первые две фразы каждого раздела.** Если без предыдущего раздела непонятно, о ком и о каком
   времени речь, — дописать связку.

## О12 — Разделы в одном порядке, как у всех?

Порядок один для всех биографий (`00_ИНДЕКС.md`, «Как устроена биография»):
**шапка → Линия жизни → жизнь по темам → Семья → Каким был → Награды → Расхождения → Открытые вопросы → Источники.**

1. Скрипт сверяет порядок по названиям заголовков: «Семья» / «Жена и дети» / «Братья…», «Каким он был» /
   «Какой она была», «Награды», «Расхождения», «Открытые вопросы», «Источники»; всё прочее считает «жизнью по темам».
2. **Глазами — заголовок, который скрипт не узнал.** «Характер» — это «Каким он был», но скрипт посчитает его темой
   жизни и порядок не проверит. Переименовать в принятое название.
3. «Открытые вопросы» — у каждого, даже из одного пункта (скрипт — ошибка).
4. Новое сведение — в раздел по теме, а не новым разделом в конце. Переименовал заголовок — `anchors.py check` = 0.

Было: в одной биографии «Награды» стояли после «Расхождений»; в другой раздел о жизни — после «Каким он был».

## О13 — Каждый факт: источник говорит это, биография это рассказывает

Факт в карточке — середина цепочки **источник → факт → биография**. Скрипты проверяют, что у факта есть ссылка
на источник, — и всё. Говорит ли источник **именно это** и рассказан ли факт в **биографии** — не проверяет никто.
Линза О1 — для фактов, которые правил сейчас; О13 — для **всех**, по журналу, пока не будут сверены все.

Фактов 1400+, за раз не прочесть. Идём партиями — человек целиком или одна расшифровка:

```bash
rodo fact-check status                    # сверено / не сверено / ❌ — долг
rodo fact-check next --person "Иван Ткачук" -n 40   # человек целиком
rodo fact-check next --source "Аудио 06" -n 30        # одна расшифровка — она уже в голове
rodo fact-check mark <ключ> source=✅ bio=➕ note="дописал в «Переезд»"
```

`next` кладёт рядом с фактом отрывок расшифровки **с указанного места** (по минутам записи или странице) и строку
биографии, где факт, похоже, рассказан. Это подсказка для чтения, а не вердикт.

**Источник** (`source=`):
1. Читать отрывок. Строка без «?» — с указанного места; с «?» — найдена поиском в другом месте файла. Факт стоит
   не там, где сказано, — исправить место в карточке (минуту, страницу), а потом отметить заново: ключ сменится.
2. ✅ — только если отрывок говорит **именно это**: число, имя, место, чьи слова. Вывод из двух фраз («значит,
   жили вместе») — не ✅: уверенность `низкая` и основание (О1). Цитата в факте — сверить слово в слово.
3. Расшифровки нет («Свидетельства семьи», «Интернет-находки», CEMLA) — открыть заметку-источник, для
   находки в сети — страницу по адресу. Нечем проверить — ❓, не ✅.
4. Более сильный источник говорит другое (пересказ дальней родни против первых уст — «всех перевёз дядя» против
   рассказа очевидца) — понизить уверенность, основание — в скобках, обе версии — в «Расхождения» (или закрытым
   вопросом) и карточки, и биографии. Источник факта неверен — ❌, и исправить карточку.

**Биография** (`bio=`):
1. Строка «БИОГРАФИЯ» в выдаче — лучшее совпадение по словам, не доказательство. Найти место, где факт рассказан.
   «В биографии нет чисел факта» — решить, нужны ли они рассказу (год — да, номер паспорта — нет).
2. Не рассказан — дописать (➕) в раздел по теме и по времени (О10), рассказом (О11), с местом в источнике курсивом.
3. Биография говорит другое — ❌, и исправить ту сторону, которая расходится с источником.
4. `—` (не для биографии) — только с причиной в `note`: номер документа, отчество-подтверждение, опознание файла.
   «Не успел» — не причина.
5. Событие после смерти — в текст, не в линию жизни; про жизнь другого человека — в его биографию (О9).

Готово по человеку — `next --person` пишет «несверенных нет», в `status` нет его ❌. После любой правки карточки
или биографии — прогнать базу (`check_cards`, `check_bio`, `check_lifeline`).

Было (один человек, 39 фактов): версия из пересказа стояла с уверенностью «обычная» против первых уст;
«ходил в церковь» — на 12:05, а сказано на 10:55; 9 фактов не были рассказаны в биографии.
И нашлась ошибка разбора: у 85 фактов пакет `cards`
читал только первое из нескольких мест в источнике («02:20; 24:56–25:30» → «02:20»).

## О14 — Родители и дети: один и тот же человек во всех местах?

Добавил ребёнка, поправил его даты, выяснил, кто чей, — это меняет **пять мест**, а правил, скорее всего, одно.
Механическое догоняет само: `check_lifeline.py --fix` дописывает строку `Родился сын [[Карточка\|Имя]]` (и «Умерла
дочь …», если ребёнок умер при жизни родителя) в линии жизни **обоих** родителей. Он работает в хуке после правки
карточки (`--kin`: сам человек и его родители), после правки биографии и в pre-commit. Смысл — глазами:

1. **Связь в обе стороны.** У ребёнка `father`/`mother` + `_id`, у каждого родителя — `children` + `children_id`
   (`check_tree.py` = 0). Второй родитель не забыт: мать без карточки — `Unknown …`, а не пусто.
2. **Дата рождения ребёнка — в карточке.** Без `born` строку не поставить: `check_lifeline` предупреждает
   «без даты рождения — оценить born». Оценить по братьям и сёстрам (`EST 1925`), а не оставлять пусто.
3. **Строка, которую вписал скрипт, — не дубль и не спор.** В линии уже была своя строка, которую скрипт не узнал
   («умерли дочь **Аня** и младший сын» — а карточка «Анечка Ковальчук»): удалить вписанную и дать своей строке
   ссылку `[[Карточка\|Аня]]`, домашнее имя — в `home_names` карточки. Дата в карточке спорная (Аня: 1937 в
   карточке, «ок. 1934» в тексте) — строку писать промежутком, как в тексте, с пометкой «год спорный», а не
   точной датой из карточки.
4. **У каждого ребёнка — своя строка.** «1961–1973 — Прохор, Ульяна, Савва» или «умерли дочь и сын» проверка
   за рождение (смерть) не считает и вписывает отдельные строки; общую — убрать руками. Спорная дата у одного из
   детей — у него промежуток и «год спорный», а не общий промежуток на двоих.
5. **Место строки.** Скрипт ставит строку по времени; если в таблице порядок уже сбит («после 1945» ниже 1949-го), —
   поправить порядок (О10), а не оставлять новую строку не там.
6. **У самого ребёнка** — своя линия жизни (если есть биография) начинается с его рождения; родители названы в
   шапке или первой строке, а не перечнем в «Семье» (сайт показывает их карточкой).
7. **Ребёнок в тексте родителя** — одна-две фразы там, где его рождение меняет жизнь родителя («из-за младшего сына
   мать ушла с работы»), без пересказа его жизни (О9).
8. **Пасынки, приёмные, умершие без карточки** («двое умерли при рождении») — скрипт их не видит: проверить, что они
   есть в линии жизни того, кто их растил или потерял, строкой из источника.
9. **Таблица не разваливается.** Ссылка с подписью внутри таблицы — только `[[Карточка\|Имя]]`: голый «|» делит
   ячейку, и на сайте видно `Родилась дочь [[Мария Ткачук`. Скрипт ловит и чинит (`--fix`), но после ручной правки
   таблицы — посмотреть строку на сайте.

База: `rodo check-lifeline` — 0 ошибок; предупреждения «без даты рождения» — список долга.

Было: у 12 человек в линиях жизни не хватало 24 строк о детях — у одной матери все восемь; в одной линии
пять ссылок без `\|` — на сайте строки о жене и детях разваливались.

# Ф — хранение фото

Сначала — замеры: `rodo review-photos --changed` (по правке) или без ключа (весь проект).
Он считает копии, снимки без хозяина, документы живых в галереях и снимки с координатами. Остальное — глазами.

## Ф1 — Одно фото — одно место, и то, где ему положено

1. **Этаж по происхождению:** дала семья — `1_sources/family/`; найдено в сети — `1_sources/found/` (никогда не в
   `family/`); из чужого дерева — `1_sources/others_trees/`; не разобрано — `1_sources/inbox/`.
2. **Оригинал не тронут:** не переименован, не обрезан, не пересохранён. Обрезка, реставрация, уменьшенная копия —
   в `2_transcripts/photos_processed/`, и по имени понятно, из какого оригинала.
3. **Копий нет:** байт-в-байт копия — удалить сразу, ссылки перевести на оставшуюся; копия macOS «… 2.jpg» — то же.
   Исключение одно — присланный оригинал с именем мессенджера в `_originals/` рядом с переименованной копией:
   тогда в описи папки должно быть сказано, какой оригинал какой копии. Не сказано — ❌.
4. **Новая папка на этаже 1 добавлена в git** (`git status --short | grep '^?? 1_sources'`).

## Ф2 — Имя файла говорит, что на снимке

Сайт **читает подпись, год и источник из имени файла**, если снимка нет в описи
(`Место_что-снято_1930_pastvu-123.jpg`). Плохое имя = неправильная подпись и год на сайте.

1. Семейное: `Кто_что_дата-№` (`Иван-Ткачук_портрет_до1944-03.jpg`). Имя мессенджера (`IMG-2026…-WA0016`)
   у снимка, который висит у человека в галерее, — ❌.
2. Найденное: место, что снято, год (или `1930е`, `до1944`), источник и его номер (`commons-…`, `pastvu-…`, `waralbum…`).
3. Номер дома в имени — можно (сайт его прячет, `no_address_name`), но проверить, что на сайте файл назван без него.

## Ф3 — Кто на снимке — тот ли это человек?

1. Снимок привязан строкой в `media` карточки **того самого** человека — проверено по номеру (`cr_id`), не по
   имени (тёзки, К2).
2. Одно фото — одна строка: копия, обрезка того же снимка, реставрация рядом с оригиналом — дубли (`card_doctor`
   ловит пиксельные; «тот же снимок, другой скан» — глазами). Лицо, вырезанное из общего фото, — портрет, оставить.
3. Семейный снимок без хозяина (замер Ф3) — либо привязать, либо он в описи как «кого опознать». Просто лежит — ❌.
4. На групповом снимке — кто есть кто, записано в описи или подписи; иначе через год это никто не вспомнит.

## Ф4 — Откуда снимок и честно ли подписан?

1. Найденное — в описи `00_ОПИСЬ_*.md` своей папки: откуда (адрес страницы), автор и лицензия, год, что снято.
2. Иллюстрация «как там было» не выдаётся за фото родных: в подписи не должно быть «дом Ткачуков», если это
   просто улица того времени.
3. Снимок из чужого дерева — происхождение `чужое дерево`, даже если это портрет нашего предка.

## Ф5 — Что снимок выдаёт сверх того, что на нём видно?

Фильтры сайта читают **текст**. Картинку паспорта с номером, серией и адресом они не видят.

1. **Документы живых в галерее** (замер Ф5 — «документы живых»): сайт закрывает их паролем, узнавая документ **по
   имени файла** (`site_export.DOC_SCAN`). После сборки сайта у каждого — 🔒; «! ОТКРЫТ» — ❌. Документ, в имени
   которого нет такого слова («IMG-…», «стр2-3»), фильтр пропустит — переименовать копию или дописать слово в оба списка
   (`DOC_SCAN` и `review_photos.DOC_WORDS`).
2. **Координаты (GPS):** сайт пересохраняет фото и служебные данные теряет — проверить, что новый путь на сайт
   идёт через `photo()` / `thumb()`, а не копированием файла как есть.
3. **Что в кадре:** номер машины, адрес на табличке, документ на столе, лицо ребёнка, который не просил, — у
   живых людей.

## Ф6 — Замена снимка дойдёт до сайта?

`site_export.photo()` не пересобирает уменьшенную копию, если она уже есть (`if not dst.exists()`), а имя копии —
по имени файла без папки.

1. Заменил снимок новой реставрацией **под тем же именем** — удалить его копию в папке `media` собранного сайта (`4_outputs/site`) и
   собрать заново; иначе на сайте останется старый.
2. Два разных снимка с **одинаковым именем** в разных папках — на сайте окажется один из них (`media_index` по
   имени). Новое имя, которое уже есть где-то ещё, — ❌.

## Ф7 — Переживёт ли архив поломку ноутбука?

Оригиналы — единственное, чего нельзя пересобрать. Проверить: размер `.git` и `1_sources`, есть ли у репозитория
удалённая копия (`git remote -v`), куда уходят медиа (`[storage]` в `ftree.toml`).

1. Правка добавляет большие файлы (> 10 МБ: аудио, PDF, архивы)? Git хранит каждый навсегда, даже удалённый.
2. Где вторая копия новых оригиналов (облако, диск)? Не знаешь — ❓ владельцу дерева, не ✅.
