# Базы и справочники Беларуси

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes archive-belarus-db`). Прочитать перед работой.

**Что это.** Список белорусских сайтов, которые Павлу посоветовали 04.10.2026. Каждый проверен вживую: что в нём есть,
пускает ли без входа, как спрашивать. Что уже нашли для этого дерева и где выписки — в заметках дерева.

**Главное правило — запросы редко.** По одному, пауза ≥3 с, без параллельных помощников на один сайт. Капча или
403/429 — стоп и позвать Павла. Иначе заблокируют (Павел, 04.10.2026).

## Какой сайт когда

| Нужно | Сайт |
|---|---|
| Точная дата смерти (умер в Беларуси после ~1976) | **enotary.by** |
| Все упоминания фамилии или деревни сразу (метрики, солдаты, беженцы, репрессии) | **db.zhnivo.com** |
| Погиб во Вторую мировую, где похоронен | **memory.mil.by**; карточка — «Память народа» (`vpn-browser`) |
| Был ли партизаном | **partizany.by** |
| Номер архивного дела для письма | **sodd.by**, **archiveskarb.by**, указатели **archives.gov.by** |
| Текст старых газет, ведомостей, описей | **hryc.by** (платно) — запросы копить в очередь (файл — в заметках дерева) |
| В каких деревнях жила фамилия | **helper.archonline.by** — только браузер Павла |
| Воевал и награждён во Вторую мировую; где лечился | **moypolk.ru**, **podvignaroda.ru**, **soldat.ru** — раздел «Базы солдат» ниже |

## Сайты

### enotary.by — нотариальный справочник [проверено]
- Раздел «Наследственные дела». Даёт **ФИО с отчеством, точную дату смерти и нотариуса**. Без входа, бесплатно.
- Прямой запрос (работает и из `curl`/python, без браузера):
  `GET https://enotary.by/portal/public/legacy/search?testator=<Фамилия Имя>` → JSON `data[]: testatorName, deathDate, notary.name`.
- **Точное совпадение фамилии и имени.** Женщину искать и под девичьей, и под фамилией мужа.
- Есть только те, по кому открывали наследственное дело. Самые ранние даты — 1976–1979 («Гос. архив»), основная
  масса — 1980-е и позже. Нет дела — нет человека.
- **Свой ли человек — по отчеству** (= имя отца в карточке) и фамилии мужа; тёзок много (частое имя с фамилией — до 50 строк).
  Один подходящий — «обычная»; два и больше — оба в карточку с «низкая» и вопрос родне.
- **Нотариус = где жил (вероятно).** Наследство оформляют по последнему месту жительства. «НК <Название> района»,
  «Ленинского района г. Бреста» — район виден сразу; личный нотариус («Марчук Н. И.») — в ответе есть
  `notary.link` на belnotary.by, там адрес конторы. В факт: «дело у нотариуса в г. …, вероятно, жил(а) там»,
  уверенность низкая. «Нотариальный архив … округа» — только область (дело старое, сдано в архив).
- Скрипт-образец прохода с паузами — сессия 04.10.2026 (`en2.py` в scratchpad): список из карточек → запрос → сверка
  отчества.

### db.zhnivo.com — «Жніва» [проверено]
- Сводный указатель ~14 млн записей: указатель FamilySearch (метрики), «Память народа», gwar (Первая мировая),
  беженцы 1916, призывники, репрессированные (openlist), партизаны, акты ЧГК. Бесплатно, без входа.
- Поиск: страница `https://db.zhnivo.com/by/belarus-genealogical-databases/`, поля фамилия, имя, отчество, **населённый
  пункт**, район, губерния. Ищет и по одной деревне без фамилии (одна деревня — сотни строк; одноимённых деревень бывает несколько — фильтровать
  по району).
- Из `curl` не работает (одноразовый ключ только браузеру). Во встроенном браузере — функция `zq(фамилия, деревня,
  район)` из сессии 04.10: заполняет форму, ждёт 6 с, отдаёт строки таблицы `jQuery('table').DataTable().rows().data()`.
  Поле `sdb` — база-источник (`pam` — «Память народа», `fsh` — FamilySearch, `hgw` — gwar, `har` — беженцы 1916,
  `par` — партизаны, `ope/opb` — репрессированные, `prk` — акты ЧГК, `p26` — перепись 1926 по БССР, НАРБ ф. 30;
  распознают добровольцы, охват частичный), `link` — адрес записи там.
- Фильтр типа «П26» в выпадающем списке (31.10.2026) даёт 0 даже там, где строки переписи есть. Не верить: искать по
  всем типам и отбирать `sdb = p26`. Маска «<начало фамилии>*» в поле фамилии тоже дала 0 при 710 строках самой фамилии — варианты
  писать списком через «|». Выдача — по 100 строк: листать `DataTable().page(n).draw('page')`. Перепись 1926 — только для восточной Беларуси: западные уезды (Брест и др.) тогда в Польше.
- После ~5 запросов подряд — капча «Вы шукаеце часта». Капчу проходит **только Павел**.
- [П 02.11.2026] db.zhnivo.com не отвечал больше недели у всех (isitdownrightnow.com), zhnivo.com — ошибка «нет места
  на диске». Сначала проверить, жив ли сайт, а не искать прокси: это не блокировка Польши.
- **«Шуфлядка» и проверка «вы чалавек» [П 05.11.2026].** 04.11 — ~110 запросов за час → reCAPTCHA. Утром 05.11
  (через ~16 ч покоя) проверка встала уже на **первом** запросе. Павел прошёл её — сайт отдал одну страницу. Следующий
  запрос (через 60 с) — снова проверка; пауза не помогает. Значит: после такого перебора адрес на подозрении больше суток,
  и одна пройденная проверка = один запрос. Как не попадать: (1) за заход — не больше ~20–25 запросов, потом
  перерыв на сутки; (2) запросы сразу узкие (фамилия + деревня/уезд, раздел галочкой, годы), чтобы выдача была в 1–2
  страницы — листать 39 страниц выдачи нельзя; (3) страницы и запросы — в той же вкладке через форму и
  кнопки (`a.page-link`, `data-p`), без перезагрузки; (4) после перебора — не заходить минимум 2–3 дня. Решает сервер
  (`403`, `kind: captcha` в ответе POST), код страницы ничего не считает. Выдача «Шуфлядки» отсортирована по названию
  источника (последние страницы выдачи по фамилии — описи НАРБ). Порядок листов на страницах между заходами не меняется.
- Это указатель: факт — после того, как открыли саму запись (FamilySearch — `archive-familysearch`; «Память
  народа» — `vpn-browser`).

### memory.mil.by — «Книга памяти Республики Беларусь» [проверено]
- Погибшие и пропавшие во Вторую мировую: год рождения, район, дата смерти, место захоронения, часть. Без входа.
- `GET https://memory.mil.by/poisk-pogibshikh/?search=Y&last_name=…&first_name=…&birth_year=…` — таблица в HTML.
  Ещё `/poisk-zakhoroneniy/`.

### partizany.by — «Партизаны Беларуси» (НАРБ) [проверено]
- 82 тыс. карточек партизан и подпольщиков. `GET https://partizany.by/search/?is_ajax=y&q=<Фамилия>&PAGEN_1=<n>`,
  по 20 на страницу, поиск нечёткий (приходят фамилии, отличные на букву) — отбирать глазами.

### sodd.by — СОДД, каталог архивов РБ [проверено]
- Фонды, описи, дела всех госархивов. Бесплатно. `POST https://sodd.by/api/v1/search`, JSON
  `{"sentence_search":"<деревня>","archive_codes":["010"]}` (010 — НИАБ Гродно); поля `fund_code`, `inventory_code`,
  `year_from`.
- ⚠️ Деревню сверять по **уезду**: одноимённые деревни бывают в соседних уездах — дело про тёзку-деревню легко принять за своё.

### archiveskarb.by — «Скарб» [проверено]
- ~525 тыс. имён из архивных дел с шифрами. `GET https://archiveskarb.by/db/?filter=yes&surname=…` (маска `*` —
  с `ext=on`). Без входа.
- [П 02.11.2026] Звёздочка в конце («<Фамилия>*») даёт 0 — писать фамилию целиком, `ext=on` сам ищет по началу
  (фамилия → и та же фамилия с окончаниями -ов, -евич). Выдача — по 50 строк, дальше `&PAGEN_1=2`. Шифр, годы и число листов — только
  на странице записи `/db/?ELEMENT_ID=<n>` (номера — из ссылок в выдаче). Года рождения и места у призывников нет.

### represii.net — «Віртуальны музей савецкіх рэпрэсій у Беларусі» [проверено 03.11.2026]
- Арестованные в БССР 1920–1950-х: год и деревня рождения, работа, дата ареста, статья, приговор и **номер дела**
  (КГБ РБ, УКГБ Брестской обл. — с ним можно писать в архив). `GET https://represii.net/repressed?search=<фамилия>`,
  без входа, curl отдаёт HTML; число — «Знойдзена: N», записи — после «Вынікі пошуку».
- **Фамилию писать по-белорусски:** «-ік» вместо «-ик», «і» вместо «и». По-русски бывает 0, хотя люди есть.

### archives.gov.by — Архивы Беларуси, раздел «Генеалогия» [проверено]
- Указатели: метрические книги церквей НИАБ Гродно — `wp-content/uploads/files/ukaz_tserkov.xlsx` (годы по
  приходам), костёлы — `ukaz_kostel.xlsx`; ревизские сказки
  (`?page_id=299937`); документы Брестского архива (`?page_id=828430`). Фондовый каталог — fk.archives.gov.by.
- **Описи выложены постранично** — перечни `/fondi<от>-<до>` (шаг 100): таблица «Фонд № | Опись № | Скачать», ссылка ведёт на
  облачный диск (`drive.google.com/uc?export=download&id=<ID>`). Часть описей — машинописные с текстовым слоем:
  `pdftotext -layout опись.pdf - | grep -i <деревня или фамилия>` находит дело среди тысяч за минуту; остальные — одни образы.
  Опись большого фонда разбита на тома, диапазон дел напечатан на титуле тома — искать по титулам, а не подряд. У части
  фондов заказывают по **делопроизводственному** номеру, а не по порядковому: в описи две колонки, в шифре — вторая.
  [В] взято из vdov (CC BY 4.0); у нас перечни `/fondi…` не открывали.
- **Фондовый каталог ищет через POST** (поле `search=<слово>`): прямой GET с `%20` в адресе даёт **403** — это не закрытый
  сайт, а способ запроса. Ищет названия фондов и аннотации, не людей. Полный список фондов берётся листанием
  `/catalogue/<N>/`, `/catalogue/<N>/2/`, … — перечни описей дают только номера. [В] взято из vdov (CC BY 4.0); адрес
  каталога у vdov — на archives.gov.by, наш `fk.archives.gov.by` — тот же ли, не сверено.
- **Два экземпляра метрической книги — «записи нет» по одному ещё не результат.** Приходской экземпляр оставался в церкви,
  после революции шёл в ЗАГС и оттуда в **районный** архив (часто соседней области — границы перекраивали); консисторский
  уходил в духовную консисторию и в областной архив. Консисторский переписывали с приходского, в нём бывают пропуски, а
  приходской иногда единственный уцелевший за год. Перед «не найдено» проверить оба экземпляра (пример: смоленские метрики в ГАСО ф. 48 — консисторские копии; приходские
  экземпляры искать в районном архиве или ЗАГС). [В] взято из vdov (CC BY 4.0).
- **Дом и читальный зал — разные базы.** Из дома в АИС архива может не быть картотек, алфавитных книг ЗАГС и сведений о
  выдаче: «в архиве этого нет», сказанное из дома, проверяется только на месте. [В] взято из vdov (CC BY 4.0).

### ru.openlist.wiki — «Открытый список» через MediaWiki [В]
Замена закрытым доменам memo.ru: у сайта есть `api.php` (стандартный MediaWiki) — самый лёгкий способ спрашивать
программой вместо листания страниц. Часть адресов из-за рубежа даёт 403 — это страна, а не отсутствие данных. Взято из vdov
(CC BY 4.0); у нас «Открытый список» смотрели руками (30.09.2026).

### hryc.by — «Грыц» [проверено, платно]
- **Где открывать (решение Павла 14.10.2026).** «Грыц» — **только во встроенном браузере** приложения. Вход —
  сам Павел в панели. Из выдачи собрать **пакет задач** (плёнки, кадры, дела, страницы газет) и показать Павлу. Ссылки
  на FamilySearch — во внешнем Chrome проекта, но только после подтверждения пакета. Самому «Грыц» в Chrome проекта
  не открывать: там одна вкладка на все сессии.
- Полнотекстовый поиск по распознанным делам, газетам, книгам (губернские и епархиальные ведомости, описи, метрики
  НИАБ). Павел зарегистрирован, но без оплаты текст строк закрыт («оплатить тариф Базовый или
  выполнить задачку»). Не платить и не делать «задачки» без Павла.
- Запрос: `GET /search?R.Q=<запрос>&R.Page=1&R.Sources=<все hryc-id через запятую>&R.SearchInRecords=True` — без
  `R.Sources` выдача пустая; список `hryc-id` — атрибуты чекбоксов на странице поиска.
- Все запросы — в очередь (файл очереди — в заметках дерева), проход — один, после оплаты.
- **Лимит — 250 запросов в сутки** (так ответили Павлу 10.10.2026; блок снимают на следующий день). Считать
  каждый запрос: страница поиска, переход `/document`, пробный запрос. Бюджет прохода — до 200, запас 50.
- **Как упёрлись (10.10.2026).** Оплата «Базовый» 1 день, вход ≈11:20. Запросы по одному с паузой 4–5 с:
  ≈280 страниц поиска + ≈80 переходов `/document` (они тоже считаются) за ≈30 мин → около 11:50 ответ **429** и страница
  `/Errors/TooManyRequests` («Вы слишком часто обращаетесь к сайту… напишите на support@hryc.by»). Блок **не снят и через
  8 часов** (проверка в 19:39) — оплаченный день сгорел наполовину. Признак, что блок уже включился: запрос «отвечает» 0
  строк за секунду — такие нули **не считать пустотой**, проверять `r.status`.
  **Как надо:** до 100 запросов в час — пауза ≥15–20 с, `/document` не перебирать пачкой (номер плёнки FamilySearch
  брать у одной строки на дело; страница «Грыца» = номер снимка), каждый ответ проверять на 200 и при первом 429 —
  стоп и письмо в поддержку (Telegram t.me/hryc_by или support@hryc.by), не повторять. Самое важное — делать первым.
- **12.10.2026 — 429 уже на ≈100 запросах за день** (≈45 утром + 53 днём, пауза 15 с, запросы по 4–10 страниц
  выдачи). Значит, 250 — не гарантия: планировать **до 80 запросов в день**, широкие запросы из двух слов (`<Фамилия>
  <губернии>` → 50 стр.) листать не дальше 3–4 страниц — дальше идёт мусор.
- **Повтор 11.10.2026 — как вышло без отказа:** 54 запроса за ≈25 мин, пауза 15 с, из встроенного браузера (вход Павла),
  `fetch` внутри страницы. Листание — `R.Page=N` (ссылки страниц — `searchPageClick(N)`, видно до 50). Латиница
  (польские написания с маской `*`) в гродненских метриках даёт 0 — польские написания там не проверить. Частое
  слово или фамилию сужать вторым словом без кавычек (`<Фамилия> <уезда>` — 6 стр. вместо 50+); маска работает
  только в запросе из одного слова. «Гродненские губернские ведомости» (`hcid1_5_3`) — «Профи», в «Базовом» не открыть.
  `/document` ведёт на FamilySearch — `fetch` падает (CORS), адрес плёнки брать, открыв ссылку во второй вкладке.
- **Уровень «Эксперт» (11.10–18.10.2026, дали Павлу).** Виден в `/Identity/Account/Manage` («Эксперт: <дата>»).
  Открывает «Профи»/«Эксперт»-документы, газеты, документ по шифру, первый кадр дела и прихода на FamilySearch,

### Запрос в ЗАГС — просить «все иные сведения, содержащиеся в записи» (из vdov, CC BY 4.0) [В]
Акты ХХ века перенесены в электронный реестр **без графы «иные сведения»** (место жительства, занятие, семейное положение,
причина смерти, срок проживания, иногда национальность) — их переносили не все. Обычная справка вернёт то, что и так
известно; остальное лежит в бумажной актовой книге.
1. Просить именно **«все иные сведения, содержащиеся в записи»** (и внести их в реестр — по такому заявлению поднимают
   бумажную книгу). Перечисление нужных полей сужает ответ ровно до перечисленного.
2. Бланк ответа проверить: в каждом пункте текст или прочерк. **Пустой пункт — не смотрели**, основание просить доработку.
3. Выяснить, где лежит книга: реестр называет орган регистрации, а бумажные книги могли уйти в общее хранилище — письмо в
   прежний отдел уйдёт в пустоту.
Приём годится для любого запроса в архив: просить полный состав записи, пустое поле считать непроверенным, не отсутствующим.
Путь запроса из-за границы и готовые письма этого дерева — в заметках дерева.
