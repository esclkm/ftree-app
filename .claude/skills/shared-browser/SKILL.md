# Общий Chrome: каждой сессии — своя вкладка

> **Заметки этого дерева** вклеиваются ниже сами, при вызове навыка (нет заметок — пусто; вручную — `rodo skill-notes shared-browser`). Прочитать перед работой.

!`${CLAUDE_PLUGIN_ROOT}/tools/rodo skill-notes --embed shared-browser 2>/dev/null || rodo skill-notes --embed shared-browser 2>/dev/null || true`

## Что это и зачем

Chrome проекта один (`rodo browser-cdp start`, профиль `$ARCHIVES_LOCAL/browser-profile`).
В нём один вход Павла на все сайты. Раньше все скрипты брали «первую вкладку». Две сессии сразу — и одна открывала
FamilySearch, а другая через секунду уводила ту же вкладку на MyHeritage. Каждая читала чужую страницу
(31.10.2026).

С 31.10.2026 у каждой сессии своя вкладка. Сессию узнают по номеру `CLAUDE_CODE_SESSION_ID` — он есть у каждой
сессии Claude сам. Реестр «номер сессии → номер вкладки» — `$ARCHIVES_LOCAL/browser-tabs.json`
(вне проекта; закрытые вкладки из него выпадают сами). Код — `tools/scripts/cdp_tab.mjs`.

## Пошагово

1. **Кто сейчас в браузере:** `rodo browser-cdp status` — у каждой вкладки «чья» (первые 8 знаков
   номера сессии, «эта сессия» — твоя, «ничья» — открыл Павел или старый скрипт).
2. **Работай командами `nav`, `text`, `eval`, `shot`, `download`, `fs-frames`** — они сами берут твою вкладку.
   Первая команда сессии откроет новую вкладку; закрылась — следующая команда откроет новую.
3. **В конце работы** — `rodo browser-cdp release` (закрыть свою вкладку). `stop` закрывает весь
   Chrome — **только если в `status` нет чужих вкладок**.
4. Своё имя в `status` вместо номера: `CDP_LABEL="FS каталог" rodo browser-cdp nav …`.
   Павлу в терминале номер не нужен: без него команды берут «ничью» вкладку.

## Что параллельно можно, а что по очереди

| Действие | Две сессии сразу? |
|---|---|
| Читать разные сайты в своих вкладках | да |
| Один сайт из двух сессий | можно, но запросы к сайту складываются: правило «запросы — редко, с паузами» на двоих. Тяжёлое (пачка кадров, 40+ запросов) — по очереди |
| `login-check` — вход Павла | открывает вход в **твоей** вкладке; вход общий для всех вкладок. Не выходить из аккаунта и не перезапускать Chrome, пока работают другие |
| `start` | безопасно: запущен — ничего не делает |
| `stop`, перезапуск Chrome | **нет**, если в `status` есть вкладки других сессий — они потеряют работу |
| `download`/`batch`/`fs-frames` | папка загрузок у Chrome одна. Две пачки сразу — файлы могут попасть в чужую папку. Пачки — по очереди; сайт без входа — `batch --isolated` (своё окно, своя папка) |

Сомневаешься, что занято, — `status`; работает чужая сессия на том же сайте — подожди её или спроси её через
`SendMessage` (номер — в «Linked sessions»).

## Какие скрипты уже знают про свои вкладки

- `browser_cdp.mjs` — все команды [П 31.10].
- `myheritage_dna.mjs` — да [П: синтаксис; живого прогона нет].
- `myheritage_tree.mjs` — открывает свою временную вкладку и закрывает её — безопасен.
- `myheritage_web.mjs` (`tools/mh`) — берёт **любую** вкладку с деревом MyHeritage. Если две сессии работают
  с MyHeritage сразу, может взять чужую. Пока — `tools/mh` только из одной сессии за раз.
- `myheritage_record.mjs` — подключается ко **всем** вкладкам MyHeritage (слушает ответы сайта): только читает,
  но видит и ответы чужих вкладок.
- Свои однодневные скрипты к порту 9333 — не брать `pages[0]`, а `import { ownTab } from './cdp_tab.mjs'`.
