## Пошагово для исполнителя (читай первым)

### Свой Chrome — главный способ (с 02.10.2026, задача B1) [П]

Отдельный Chrome с профилем `$ARCHIVES_LOCAL/browser-profile` (вне проекта, git и облака). Павел вошёл в нём
один раз, Chrome сам хранит вход и пароли; вход пережил два перезапуска Chrome подряд [П 02.10]. Управляет скрипт, не
модель: в разговор приходит только итог. Панель браузера приложения — только чтобы Павел посмотрел глазами.
Этот раздел главнее слов «в панели браузера» ниже: там — как было раньше, а признаки страниц и адреса верны и сейчас.

```bash
B="rodo browser-cdp"   # своя вкладка у каждой сессии; другие сессии рядом — навык shared-browser
$B start                      # уже запущен — ничего не сделает
$B login-check familysearch   # «вошёл» → дальше; «не вошёл» — открыл вход в окне Chrome: Павел входит (пароль

$B nav <url>; $B text 3000    # открыть и прочитать текст (вместо navigate + get_page_text)

$B fs-frames $ARCHIVES_LOCAL/raw/familysearch/<плёнка> кадры.tsv
                              # кадры пачкой: строки «3Q9M-…<TAB>имя__3Q9M-….jpg», пауза 3 с, сразу в папку (не в «Загрузки»),
                              # уже скачанные пропускает; 401/403/429 → стоп (403 02.10 = не вошёл)
$B release                    # в конце работы: закрыть свою вкладку; stop — только если в status нет чужих
```

### Одной командой — `familysearch.py` (с 04.11.2026) [П]

Вместо сниппетов в `eval` — готовая команда. Она шлёт запросы из своей вкладки Chrome проекта, а ответ разбирает
сама. В разговор приходит короткая таблица: дата и событие, кто, родня в записи с ролями, место, плёнка и кадр,
ссылка на запись.

```bash
F="rodo familysearch"
$F records --surname Гаркуша --given Остап --born 1885-1900   # указатель метрик (по умолчанию коллекция Гродно 4166194)
$F records --surname Ковальчук --father Тарас --collection all # все коллекции; --exact — без Ковальчик и прочих созвучий
$F records --film 007700000 --surname Гаркуша                  # одна плёнка: с фамилией сайт фильтр плёнки выкидывает — отбирает скрипт
$F tree --surname Гаркуша --born 1850-1900                      # общее дерево FS (созвучных вроде Harkness отсеивает; --loose — не отсеивать)
$F fulltext "Подгай" --years 1880-1900                          # текст страниц (автоматическая расшифровка сайта)
$F catalog 700000                                               # дело каталога: места, годы, плёнки по томам
$F film 007700000 --frames 590-600                              # что на плёнке и id кадров по номерам
$F frames 007700000 596-600 $ARCHIVES_LOCAL/raw/familysearch/<папка> --name Подгай_1893  # скачать (≤40)
$F record 1:1:XXXX-XXXX                                         # одна запись текстом (страница записи)
$F limit                                                        # сколько запросов осталось в этот час
```

- **Лимиты встроены.** Запросы идут по одному, с паузой 5 секунд, не больше 150 поисков в час. Счёт общий для
  всех сессий: `$ARCHIVES_LOCAL/familysearch_rate.json`. После ответа 429 стоп на 15 минут, тоже для всех.
- **Журнал ведёт сам.** Если такой же запрос уже был, команда покажет прошлый итог и искать не станет (`--force` —
  искать заново). После поиска сама допишет строку в `ИСКАЛИ_журнал.tsv` (`--no-log` — не писать). `frames`
  пропускает кадры, которые уже читали или уже скачали. В журнал идёт и поле «состояние» (нашлось / пусто /
  частично / не дошло / закрыто). Заход «не дошло» или «закрыто» не считается прочитанным: повторить можно
  без `--force`. Все незакрытые заходы — `searched.py open familysearch`.
- **Итог — с состоянием**, словами:
  - «нашлось N»;
  - «пусто: указатель ответил, записей нет» — это не «нет в архиве»: указатель покрывает не все плёнки, охват
    проверить командой `film`;
  - «не дошло: 429 / 401 / 403» — это вообще не результат, повторить позже.
- **Свой отбор.** По имени и годам рождения сайт отбирает нестрого: на «Остап, 1885–1900» он отдал 136 записей
  одной фамилии. Скрипт оставляет тех, у кого имя начинается так же и год рождения в промежутке, — осталась одна. Две копии
  одной записи из двух проходов индексации он склеивает в одну строку «×2». Посмотреть всё, как отдаёт сайт, —
  `--loose`.
- **Чего нет.** Адреса `/platform/…` (официальный API) без токена отвечают 401. Читать токен скрипт не станет:
  это правило «cookie не трогать» (решение Павла, 04.11.2026). Поэтому одну запись `record` читает со страницы, а не
  через API.
- Чужие серверы для Claude (MCP) с FamilySearch разобраны 04.11.2026, ставить их не стали: одним нужен ключ
  разработчика, которого у нас нет, другие копируют вход из браузера в файл. Адреса `/service/…` для команды взяты
  из protonspy/familysearch-mcp (MIT).

Перезапускать Chrome без спроса нельзя: 02.10 так потеряли вход ГАСО (тогда ещё без «Продолжить с того же места» —
теперь `start` включает это в профиле сам). cookie, хранилище и пароли скрипт читать отказывается — не обходить.

**FamilySearch — всегда во внешнем браузере** (свой Chrome проекта, `browser_cdp.mjs`). Встроенный браузер
приложения для FamilySearch не использовать — ни для чтения, ни для перехода по ссылкам «Грыца» `/ArchiveDB/Records/FP/…`
(решение Павла 11.10.2026). Свой Chrome не запускается — стоп, сказать Павлу. Никаких `curl` с cookie.

**Железные правила**
- Пароль, cookie, токены сессии у Павла **не просим**, из страницы **не копируем** (ни в `curl`, ни в файл, ни в чат). Скачивать с входом можно только `fetch` **внутри страницы** — браузер сам подставляет вход.
- Вход делает **сам Павел** в панели браузера. [П] В 4d72bfa5 новая панель снова потребовала вход, и Павел входил заново. Что вход переживает перезапуск приложения или новый день — [В], не рассчитывай: сначала проверь шагом 1.
- Только страницы про наших людей, не подряд. Между скачиваниями пауза ≥3 с. Не больше ~40 снимков за заход без вопроса Павлу.

**Шаги**
1. `navigate` → `https://www.familysearch.org/search/record/results?q.surname=Гаркуша&f.collectionId=4166194&count=10` (кириллица, закодированная как в URL), затем `get_page_text` (max_chars 4000).
   - Видишь «Sign in» / «Войти» / форму входа → скажи Павлу: «Войди в панели справа и напиши "вошёл"», **жди**, потом повтори. Не вводи ничего сам.
   - Видишь капчу, «Are you a robot», «unusual activity» → **стоп**, сообщи Павлу, ничего не повторяй.
   - Ответ 403 / 429 / «Something Went Wrong» два раза подряд → **стоп**, пауза ≥10 минут, спроси Павла.
   - Видишь «Historical Record Filtered Search Results (N)» и список → нормально, иди дальше.
2. Нужна запись → `find` с текстом имени (вернёт `href="/ark:/61903/1:1:XXXX-XXX"`). Открой `navigate https://www.familysearch.org/ark:/61903/1:1:XXXX-XXX?lang=en`, `get_page_text` (max 3000): там имя, события, родители, номер плёнки.
3. Снимок записи: на странице записи `find` → `View Original Document`, его `href` содержит ark кадра `3:1:3Q9M-…`. Открой этот `href` (`navigate`). Это просмотрщик.
4. Прочитать индекс кадра без картинки: в просмотрщике — сниппет `go/grab` ниже (раздел «Индекс кадра»).
5. Скачать кадр — сниппет «Скачать» ниже, **одним вызовом `javascript_tool`**. Ожидаемый ответ: строки `<байты> <имя>` (обычно 0,9–1,6 МБ на кадр). Строка `401 …` / `ERR …` → не вошёл или кадр недоступен: не повторять в цикле, сообщить.
6. Файл приземляется в `~/Downloads/<имя>.jpg` **без диалога** [П]. Переложи: `Bash` → `mv ~/Downloads/*__3Q9M-*.jpg $ARCHIVES_LOCAL/raw/familysearch/<плёнка>/` (создай папку). Посчитай, что пришло столько, сколько просили; недостающее докачай по одному.
7. Читать картинку самому дорого. Нужно прочитать текст кадра — отдай файл **помощнику** (`Agent`, haiku/sonnet, ответ ≤20 строк) или скрипту распознавания. **Пачку кадров** (десятки и сотни) — только локально и бесплатно: навык `metric-search` (`metric_review.py book fs_<плёнка>`; не строится шаблон — `ocr_folder.py --src <папка плёнки> --only <кадры>` и `grep`). Модели — на найденные места и на польский текст. Найденное — в карточку человека как факт с источником (см. «Куда класть»).

## Что это и когда

FamilySearch — бесплатная база сканов метрических книг (записи о крещении, браке, смерти) от церкви Мормонов. Для нас главное:
- **Коллекция 4166194** — «Беларусь, Гродно. Метрические книги, 1649–1915». Внутри — православные, католические и униатские книги приходов бывшей губернии; какие наши фамилии и приходы там нашлись — в заметках дерева.
- **Указатель** (индекс) — имена, кто-то вписал руками. Он неполный и с ошибками; настоящее доказательство — **сам кадр**.
  Чужой опыт с украинскими метриками (chytalnia, `materials/kanaly.md`, 2026): указатель **дописывает отчество**, которого
  на скане нет (дважды — женщине); **тип документа ставит машина** и врёт (251 из 300 православных крестьян села помечены
  «еврейская книга»); год XVIII века в выдаче бывает возрастом, а не датой; место приведено к нынешнему названию — смотреть
  место, как в оригинале (под верным названием часто чужое село того же имени); ноль — «нет в указателе», не «нет в архиве».
- **Кадр** (image, снимок) — скан одной страницы книги, адрес вида `ark:/61903/3:1:3Q9M-XXXX-XXXX` (буквы и цифры — свои у каждого кадра).
- **Плёнка** (film, DGS) — целая книга/лента кадров, адрес `/search/film/<DGS>`, внутри `?i=<номер кадра>`.
- **Каталог** — описание книг по месту. Номера каталогов в старых наших файлах были выдуманы (8 из 8 неверны) — **любой номер проверять** (см. ниже).

Метод: сначала указатель → нашёл запись → открыл кадр → прочитал сам → скачал нужное. Либо листание плёнки по датам (книги идут по годам: зная месяц крещения, хватило 37 кадров вместо тысяч) [П].

## Как искать (URL-шаблоны)

Все URL — без пробелов, кириллица кодируется (`encodeURIComponent`). Основа: `https://www.familysearch.org/search/…`

| Что | URL | Заметки |
|---|---|---|
| Записи по фамилии | `/search/record/results?q.surname=Гаркуша&q.surname.exact=on&f.collectionId=4166194&count=100` | `.exact=on` — без вариантов |
| С именем, отцом, годами | `…&q.givenName=Остап&q.fatherGivenName=Тарас&q.birthLikeDate.from=1850&q.birthLikeDate.to=1883` | также `q.motherGivenName`, `q.spouseSurname`, `q.deathLikeDate.from/to` |
| Маска | `q.surname=Ковальч*&q.surname.exact=on` | |
| Только в одной плёнке | `q.filmNumber=7700000` (в JSON-запросе) | |
| Полнотекст | `/search/full-text/results?q.text=Подгай` | часто «Something Went Wrong» [П] |
| Каталог по ключу | `/search/catalog/results?count=20&q.keywords=(Подгайский)` | вернул 0 [П]; каталог по месту скриптом не ищется |
| Карточка каталога | `/search/catalog/<номер>` | проверять географию |
| Что есть по месту | `/en/search/catalog/results?q.keywords=<место латиницей с диакритикой>` | поиск по-русски («… благочиние») — часто 0, латиницей с диакритикой (польское написание) — работает. Смотреть, каких книг нет вовсе (православные, ревизские сказки, люстрации) — тогда искать в архиве, а не на FS |
| Плёнка | `/search/film/007700000?i=300` | `i` — номер кадра |
| Запись | `/ark:/61903/1:1:XXXX-XXXX?lang=en` | |
| Кадр с индексом | `/ark:/61903/3:1:3Q9M-XXXX-XXXX-X?view=index&personArk=%2Fark%3A%2F61903%2F1%3A1%3AXXXX-XXXX&action=view&cc=4166194&lang=en` | |

Названия приходов в каталоге FamilySearch — **по-русски в транслитерации ALA-LC** (латинская запись русских названий), поэтому поиск по
русскому слову или по польскому написанию может промахнуться. Искать **по уезду и одному слову**, не по полному названию; фильтры по стране и месту часто не работают. Взято из vdov (CC BY 4.0) [В];
пример — местечко находится по латинице с диакритикой, польским написанием (строка таблицы выше).

Правила поиска: фамилии на -ик и на -ич — **разные** (Ковальчик ≠ Ковальчич); FS подмешивает их как фонетический вариант — отсеивать. Искать кириллицей. Фильтры по датам нестрогие — отбирать глазами.
Тёзки по названию церкви/годам дают мусор: **всегда сверять географию** (у кого уезд/приход) прежде чем принять номер.

### Быстрый поиск JSON (внутри страницы FamilySearch; работает) [П]
Открой любую страницу familysearch.org (вошёл), затем `javascript_tool`:
```js
window.imgOf = e=>{const s=JSON.stringify(e.content.gedcomx); return ((s.match(/FS_DIGITAL_FILM_NBR[^}]*?"text":"([^"]+)"/)||[])[1]||'');};
window.arkOf = e=>{const s=JSON.stringify(e.content.gedcomx); return (s.match(/3:1:[A-Z0-9-]+/)||[''])[0];};
window.big = async (params, max)=>{const offs=[]; for(let o=0;o<max;o+=50) offs.push(o); const res=await Promise.all(offs.map(o=>fetch('/service/search/hr/v2/personas?'+params+'&count=50&offset='+o,{headers:{accept:'application/json'}}).then(r=>r.ok?r.json():{entries:[]}).catch(()=>({entries:[]})))); return res.flatMap(d=>d.entries||[]);};
window.line = e=>{const g=e.content.gedcomx; const nm=p=>(p.names?.[0]?.nameForms?.[0]?.fullText)||'?'; const pr=g.persons.find(p=>p.principal)||g.persons[0]; const f=(pr.facts||[]).map(f=>f.type.split('/').pop()[0]+':'+(f.date?.original||'')).join(','); const oth=g.persons.filter(p=>p!==pr).map(p=>nm(p)+((p.facts||[]).length?'('+p.facts.map(x=>x.date?.original||'').join(',')+')':'')).join('; '); return imgOf(e).slice(0,13)+' | '+nm(pr)+' '+f+' | '+oth;};
const E=await big('q.surname=Гаркуша&f.collectionId=4166194',150);
[...new Set(E.map(line))].sort().join('\n')
```
Вывод — по строке на человека: `номер плёнки_кадр | имя события:дата | другие участники`. `f.collectionId=4166194` обязателен. Параметры — те же, что в URL поиска. Выводи в ответ **коротко** (фильтруй до своих), без всего массива.
**Падало:** одна строка в ответе сайта была испорчена, первый прогон по одной фамилии упал [П]; парсинг оборачивай в `try/catch`, `.catch(()=>…)` как выше.

## Как смотреть страницу без лишних токенов

- Страницы поиска и записей — `get_page_text` с `max_chars` 3000–6000, имя человека — `find` (даёт `href` с ark).
- **Не** делать `computer screenshot`/`zoom` на полный экран: `zoom` по области в панели **не работает** (возвращает весь экран) [П]; снимок ~800×966 каждый раз кладёт картинку в разговор.
- Прочитать кадр: скачать (ниже) → отдать файл помощнику/скрипту. В сессиях Claude читал кадры сам (Read картинок 1700×2750 по одному) — дорого: десятки кадров = сотни тысяч токенов.
- `javascript_tool`: вывод — короткая строка/JSON; длинное — класть в `window.X` и забирать частями.
- Индекс кадра без картинки [П] (в просмотрщике кадра):
```js
window.go=async function(n){const inp=document.querySelector('input'); const set=Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set; inp.focus(); set.call(inp,String(n)); inp.dispatchEvent(new Event('input',{bubbles:true})); inp.dispatchEvent(new Event('change',{bubbles:true})); inp.blur(); await new Promise(r=>setTimeout(r,2500));};
```

Листает кадры по номеру и выписывает, что проиндексировано (`This image has not been indexed` — индекса нет, смотреть глазами). Пауза 2,5 с между кадрами уже внутри; не листай сотни подряд.

## Как скачать нужную страницу без участия Павла

### Рабочий рецепт [П]: `fetch` внутри страницы + `<a download>`
Сессии 30.09 скачали так ~60 кадров без единого клика Павла. Браузер сохраняет файл прямо в `~/Downloads` **без диалога**; имя берётся из `a.download`.

1. Открыть любую страницу familysearch.org (адрес `https://www.familysearch.org/…`, **с `www`** — иначе `fetch` с `credentials` не пройдёт; хост `sg30p0.familysearch.org` из страницы даёт `401`/`Failed to fetch`) [П].
2. Один вызов `javascript_tool` (≥3 с между файлами; при 0,7 с один из 17 не сохранился [П]):
```js
const list={
 '3Q9M-XXXX-XXX1':'Подгай_1893_брак_Остап_Гаркуша',   // id кадра : читаемое имя
 '3Q9M-XXXX-XXX2':'Подгай_1878_брак_Тарас_Заруба'};
let o=[]; for(const [id,name] of Object.entries(list)){
 try{ const r=await fetch('/service/records/storage/deepzoomcloud/dz/v1/3:1:'+id+'/dist.jpg',{credentials:'include'});
  const b=await r.blob(); if(!r.ok){o.push(r.status+' '+name);continue;}
  const a=document.createElement('a'); a.href=URL.createObjectURL(b); a.download=name+'__'+id+'.jpg';
  document.body.appendChild(a); a.click(); a.remove(); o.push(b.size+' '+name);
  await new Promise(z=>setTimeout(z,3000));
 }catch(e){o.push('ERR '+name+' '+e.message)} }
o.join('\n')
```
3. `Bash`: `mv ~/Downloads/*__3Q9M-*.jpg $ARCHIVES_LOCAL/raw/familysearch/<плёнка-или-дело>/` (сначала `mkdir -p`). Имя заканчивается на `__<id кадра>` — по этому суффиксу и ловится (и не путается с чужими файлами в Загрузках).
4. Сверить число файлов с запросом; недостающее — отдельным коротким вызовом.

Размер кадра ≈ 0,9–1,6 МБ (≈1700×2750 при листании, 4000+ px у «Скачать»). Кнопка «Download» (`find` → `button "Download"`) на странице кадра тоже сохраняет в `~/Downloads` сразу [П], но один кадр за клик — для пачки хуже.

### Как получить список кадров плёнки [П]
Из страницы `/search/film/<DGS>` (нужно, чтобы адрес был нужной плёнки; `cat` — из адреса):
```js
const r=await fetch('/search/filmdatainfo/film-data',{method:'POST',headers:{'content-type':'application/json',accept:'application/json'},body:JSON.stringify({type:'film-data',args:{dgsNum:'<DGS плёнки>',state:{i:'190',cat:'<номер каталога>'},locale:'en'}})});
const j=await r.json(); window.FD=j; window.SH=FD.images.map(u=>u.match(/3:1:[A-Z0-9-]+/)[0]); SH.length
```
**`film_note` — весь каталог, не одна плёнка [П 11.10]:** там все тома всего фонда (сотни строк). Нужное — строки,
где `digital_film_no` = номер плёнки: `for(const c of j.catalogs)for(const f of c.data.film_note)` → `f.digital_film_no`,
`f.items`, `f.text` («Volume 919-2/34 Births 1884 …»). Так за один запрос видно, на какой плёнке какой год и где
ряд кончается. Указатель записей покрывает не все плёнки: часть лет бывает не проиндексирована.
Дальше `SH[n-1]` — id кадра номер `n`. Так прошли 88 кадров одной плёнки подряд. Метаданные плёнки (что внутри, какие годы) — `FD.catalogs[].data.film_note`.

### Проверка номера каталога [П]
В странице FS: `fetch('/service/search/catalog/item/<id>',{headers:{accept:'application/json'}})` → смотри `source.subject[].text` (география) и `available_online`; DGS плёнок — в JSON (`dgs`, `film_number`). Не принимай номер, пока география не совпала (нужный уезд, а не одноимённое место в другой губернии).

### Идеи [В] (не проверены)
- **Локальный приёмник** на `http://127.0.0.1:8765` (Python, пишет присланные blob'ы в папку сырья): страница шлёт `fetch(url,{method:'POST',body:blob})`. Нужны ответы `Access-Control-Allow-Origin: https://www.familysearch.org`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Allow-Private-Network: true` на OPTIONS. В сессиях код приёмника написан дважды, **ни разу не запущен**: первый раз система безопасности отклонила («Expose Local Services»), второй раз выбрали `<a download>` [П]. Выигрыш — файлы сразу в нужной папке, без `mv`; но `<a download>` уже работает, так что приёмник нужен только если Загрузки недоступны. Запуск потребует отдельного согласия Павла.
- **Один кадр = один запрос полного размера.** Кадры в панели грузятся плиткой (`image_files/<z>/<x>_<y>.jpg`, `image.xml`) — для обычных страниц `dist.jpg` хватает; плитки [В].
- Автосохранение в нужную папку через `chrome.downloads` — недоступно из страницы.

## Куда класть

**Перед скачиванием — журнал поиска.** `rodo searched frames <плёнка> <кадры>` покажет, какие
кадры уже читали (и что вышло) и какие уже лежат в сырье; качать и читать — только «новые». После захода — строка
`searched.py add familysearch "плёнка <DGS> (<приход, дело, годы>)" "<кадры>" "<кого, с cr_id>" "<как>" "<итог>" <отчёт>`.
Указатель FamilySearch **деревни не хранит** (только имена, даты, роли — проверено 14.10.2026): «все из деревни» —
только по тексту «Грыца» (`R.Fund=<фонд>`), потом кадры.

**Перед записью — сверка со старым.** Указатель FamilySearch мы уже выгружали (30.09–08.10, отчёты `findings/_familysearch_*`):
почти любой человек из него уже где-то описан. По каждому — `rodo known "<имя> <отчество>|<вариант>"`;
в отчёт — таблица «было раньше / новое сегодня». Указатель путает фамилии (первая буква, окончание: «Гаркуша» → «Варкуша», «Гаркушин»;
чужая фамилия вместо нашей) — искать и по отчеству отца.

| Что | Где |
|---|---|
| Сырьё: сканы кадров | `$ARCHIVES_LOCAL/raw/familysearch/<плёнка-или-дело>/<церковь>_<год>_<вид>_<кто>__<id кадра>.jpg` — вне проекта и iCloud |
| Кадр с находкой о нашем родственнике | копия в `1_sources/found/archives_online/familysearch/` (рядом — выписка `.txt`: расшифровка слово в слово + `Просмотрено под логином Павла <дата>`), строка в `media` карточки |
| Каталог: что открыто, какая плёнка, какой кадр, что найдено | `3_research/archives/catalog/familysearch/` (см. `3_research/<папка поиска>/проект/ХРАНЕНИЕ.md`) |
| Сводка находок, что искали и не нашли | `<папка поиска>/findings/`, план — `ПОИСК_ДАЛЬШЕ.md` |

Вывод «нет в этом кадре» тоже записать (иначе вернёмся повторно).
- **Возможно, наш — полем, не текстом.** Человек из записи о нашем человеке или прямом звене получает свою карточку; боковые ветки, крёстные и поручители — строкой в отчёте или в факте записи (`card-rules`, «только у звена»). Подозреваем, что это кто-то из дерева, — в его свойства `maybe_same: "[[X]]"` + `maybe_same_id`, или `maybe_kin: "[[X]] — брат?"` + `maybe_kin_id` (кем приходится — словом с «?»); на чём держится и что докажет — строкой со ссылкой `[[X]]` в «Открытых вопросах». Обратная сторона у X появится сама. Проверили, что нет, — `rodo possible no "<карточка>" "<X>" --why "…"` (пишет `not_same`/`not_kin`, пара больше не всплывёт). Связь `father`/`spouse` — только по документу. Все пары рядом — `possible.py` → `3_research/tree/_СВЕРКА.md`. Кандидатов из дерева под запись — `tree.py find <фамилия> --for "<имя>"`: проверенные «нет» не показываются.

| Беда | Что делать |

### Чужой опыт: ex-ussr-kinship-research (MIT) — ловушки, у нас ещё не проверенные [В]

Взято 04.11.2026 из навыка DenisSergeevitch/ex-ussr-kinship-research (`references/field-lessons.md`,
`familysearch-indexes.md`, `search-result-validation.md`). Там это наблюдения одного автора, нами не проверены.
Подтвердится у нас — снять метку [В].

- **На одной плёнке бывает несколько дел.** Табличка с шифром в начале называет одно дело, табличка в середине —
  следующее, со своим заголовком. Старые выписки числили всю плёнку за первым делом. `familysearch.py film`
  предупредит, если в описании плёнки несколько строк.
- **Одно село в каталоге заведено 3–4 раза:** по империи, по СССР и по нынешней стране. Поиск каталога по месту
  подчинённые места не включает. Искать под каждым названием. Пример — одно и то же местечко записано
  под Россией, Польшей и Беларусью.
- **Пусто новым способом — сделать контрольный запрос** на запись, которая точно есть в том же указателе
  (любая, уже найденная раньше; наша контрольная — в заметках дерева). Не нашлась и она — сломан запрос, а не «нет записей».
- **«Image Restricted» закрывает один снимок, а не всю коллекцию.** Текст сообщения сохранить в выписку.
- **Проверять скачанный кадр.** Адрес и номер кадра меняются раньше картинки. Ответ 200 может оказаться страницей
  входа. Склеенный из плиток кадр может не доходить до правого края. Перед чтением сверить снимок с номером.

## Ограничения и условия сайта

- **Не качать массово.** Условия FamilySearch запрещают автоматическую выгрузку/«scraping» в больших объёмах и использование для не-личных целей. Качаем **только кадры про наших родственников** и ровно те, которые собираемся читать, с паузой ≥3 с, заходами по ~10–40 кадров. Не листать плёнку целиком «на всякий случай» (исключение — только по решению Павла, например приход, где жил род).
- Сканы — для личного семейного исследования; публиковать на сайт родни только крупицы с явным указанием источника. Живых людей не публикуем.
- Часть плёнок «вне просмотра» или «только в центре семейной истории» — тогда `401/403`; не обходить.
- Снимок и индекс могут расходиться: опираться на кадр, помечать «по указателю» отдельно.
- Дата в метриках до 1918 г. — старый стиль (±12–13 дней); писать, как в документе.

## Где нужен Павел

1. **Вход в FamilySearch** — пароль, 2FA, капча: только он, в своём Chrome проекта; ждать «вошёл». Нужно, только если `login-check familysearch` ответил «не вошёл».

## Проверить перед первым запуском в новой папке проекта
- Работает ли `<a download>` в **новой** версии панели (раньше — да, Downloads, без диалога) — проверить на одном кадре, посмотреть `ls -lt ~/Downloads | head -3`.
- Путь `$ARCHIVES_LOCAL` существует и берётся из `paths.ARCHIVES_LOCAL`.

- **31.10.2026 [П]: лютеране Гродненской, Минской, Виленской губ.** — в **Курляндской** консистории, не в Петербургской.
  Коллекция 1469151 («дубликаты лютеранских книг 1833–1885») этих губерний не содержит вовсе. Курляндские дубликаты
  1834–1917 — каталог 821062 (НИАБ Минск, ф. 1952); плёнки приходов проиндексированы в коллекции **4158550**
  «Беларусь, Минск, метрические книги»: искать `f.collectionId=4158550&q.surname=…`. Какие плёнки нужны нашему
  дереву — в заметках дерева. Фильтр `q.filmNumber` работает **только один** — вместе с фамилией сайт его
  молча выкидывает и ищет по всем коллекциям.
