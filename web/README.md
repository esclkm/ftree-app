# Сайт родословной: приложение и сборщик

Что это. Всё, что видит родня: приложение в браузере (React, `src/app`) — люди, места, дерево, карта, «кем вам
приходится», хроника, заметки — и **сборщик сайта** (`scripts/site.mjs`), который кладёт приложение и данные в готовую
папку сайта и выкладывает её. Данных дерева здесь нет и карточек сборщик не читает: он берёт одну папку **выгрузки**,
которую делает движок (`rodo site export`, `tools/scripts/site_export.py`; всё скрытие личного — там).

```
выгрузка (4_outputs/site_export)          сборщик (web/)                           сайт (4_outputs/site)
  data/*.json  — по schema/*.schema.json  ─┐                                         data/  media/  files/
  media/  files/                           ├─ scripts/site.mjs build ──────────────▶ index.html  assets/
  site.json    — закрытые файлы, вход,    ─┘   + dist-app/ (npm run build:app)       functions/_middleware.js
                 куда выкладывать              + site_assets/functions/
```

```sh
rodo site export   # движок: карточки → выгрузка (--data — только data/*.json)
rodo site build    # сборщик: выгрузка → сайт; то же: node scripts/site.mjs build --data <выгрузка> --out <сайт>
rodo site publish  # собрать и выложить на Cloudflare Pages (проект — site.json, deploy.project)
rodo site mirror   # зеркало для Беларуси на Netlify (секрет — ~/.config/ftree/<дерево>/proxy_key)
rodo site all      # выгрузка + сборка + выкладка — это делает хук после push в master

npm ci             # один раз — библиотеки
npm run build      # типы → линтер заметок → тесты → сборка приложения в dist-app/
npm test           # только тесты (на вымышленном образце: test/sampleSite.mjs)
npm run app        # сервер разработки на данных выгрузки: http://localhost:5173/ru/
```

**Раскладка — под переезд.** Всё, что относится к сайту, лежит в `web/`: приложение (`src/`), схемы данных (`schema/` —
договор с движком), сборщик и проверка данных (`scripts/site.mjs`, `scripts/check-data.mjs`), то, что идёт на хостинг
как есть (`site_assets/`: `functions/` — проверка входа Cloudflare; `netlify/`, `worker/` — зеркала для Беларуси).
Снаружи `web/` о сайте знает только движок: он пишет выгрузку по `schema/`. Поэтому в приложении `ftree-app` папка
`web/` целиком становится `site/` одним переносом (`git mv web site`), а движок продолжит звать `site/scripts/site.mjs`.

| Где | Что |
|---|---|
| `scripts/site.mjs` | сборщик: `build` (выгрузка → сайт, по файлам: неизменившиеся не копирует), `publish` (wrangler), `mirror` (Netlify) |
| `site_assets/` | `functions/_middleware.js` — пароль и закрытые файлы (список — из `site.json`); `netlify/`, `worker/` — зеркала |
| `schema/` | форма каждого файла выгрузки; `site.schema.json` — `site.json`, `doc.schema.json` — заметки `data/docs/` |
| `src/data.ts` | данные для дерева, карты и родства (их передаёт `main.tsx` из `index.json`) |
| `src/i18n.ts` | язык, перевод надписей, даты, «Поделиться» |
| `src/kin/` | родство: `terms.ts` — названия на 4 языках, `graph.ts` — расчёт (без страницы, его проверяют тесты) |
| `src/me.ts` | «я»: кто выбран, хранится в браузере; `useMe()` — для компонентов |
| `src/components/` | общие компоненты React: `KinLine` (кем приходится и через кого), `PersonSearch` (поиск с фото), `Popover`, `Icon` |
| `src/tree/` | дерево: `TreeApp` — панель и состояние, `FamilyTree` — схема, `card.ts` — карточка, `links.ts` и `path.ts` — линии браков и путь родства |
| `src/styles/` | SCSS: `main.scss` собирает части; телефон — миксин `phone` |
| `test/` | Vitest; `kin.test.ts` — выдуманная семья, у каждого известно родство; `path.test.ts` — какие линии подсветить |

Добавить надпись интерфейса — строка в `I18N_ROWS` в `tools/scripts/site_export.py` (уходит в `data/ui.json`) (русский | польский | испанский | английский),
в коде — `t('ключ')`. Новое родственное слово — `src/kin/terms.ts` и строка в `test/kin.test.ts`.

## Переход на приложение: адреса на наших хостингах (проверено 28.09.2026)

Сайт лежит на Cloudflare Pages; адрес для Беларуси (Netlify) и воркер только пересылают любой путь туда как есть.
У Pages нет `404.html` — значит, на любой адрес без файла он отдаёт главную (`/people/кто-угодно` → 200) — маршруты
приложения работают на всех трёх адресах. Чтобы так и осталось:

- **Не класть `404.html` в корень сайта** — с ним Pages выключает этот режим.
- **Пути к файлам — от корня** (`/assets/…`, `/data/…`, в Vite `base: '/'`), не `../`: страница может быть на любой глубине.
- **Старые ссылки `people/<slug>.html`** уже разосланы родне — маршрут принимает и `slug`, и `slug.html`.
- **Нет файла — тоже 200 и главная.** `/data/people/<опечатка>.json` вернёт HTML, а не 404: приложение считает
  не-JSON ошибкой «не найдено».
- **Переадресации — без имени сайта** (`Location: /…`): полный адрес увёл бы через Netlify на `pages.dev`, а его в
  Беларуси режут.
- **Каждый запрос проходит проверку входа** (`functions/_middleware.js`) и идёт в дневной лимит бесплатного тарифа
  Cloudflare Workers — так и сейчас; приложение запросов не прибавляет: после первого входа на страницу человека
  приходит один маленький JSON вместо всей страницы.
- JSON меняется при каждой сборке — ссылка на него с меткой сборки (`?v=` из `index.json`), иначе браузер покажет старый.

## Приложение (выложено 29.09.2026; последние страницы Python — заметки `docs/` — перенесены 05.11.2026)

Одна страница на все адреса — `/<язык>/people/<slug>`, `/<язык>/places/<slug>`, `/<язык>/sources/<slug>`,
`/<язык>/docs/<номер>` (заметка проекта: расшифровка, находка, текст документа; номер — как у прежней `docs/<номер>.html`,
старый адрес источника или биографии ведёт на их страницу); данные — `data/*.json` (схема — `schema/`, типы —
`src/data/schema.gen.ts`, их делает `npm run schema`).

| Где | Что |
|---|---|
| `src/app/main.tsx` | вход: сначала `data/ui.json` и `data/index.json` → `data.ts` (`provide`), потом само приложение |
| `src/app/App.tsx` | маршруты (React Router), хранилище |
| `src/app/store.ts`, `ui.ts` | Redux Toolkit: язык (из `?lang=`, запоминается в браузере) |
| `src/app/api.ts` | RTK Query: `index.json`, `people/<id>.json`, `gallery.json` …; «не JSON» — «нет такого» (хостинг отдаёт главную) |
| `src/app/useIndex.ts`, `fromIndex.ts` | общий список: поиск по номеру и адресу; данные для дерева, карты и «кем приходится» |
| `src/app/Md.tsx`, `BioMd.tsx` | текст фактов и биографий: `[подпись](person:<id>)`, `(doc:<номер>)` → ссылка; HTML не вставляется |
| `src/app/Houses.tsx` | дома: раздел «Дома» на карте (`/ru/map/houses`, список по городам), «Кто жил в доме» по годам на странице дома, «Дома, где жил(а)» у человека |
| `src/app/PhotoTimeline.tsx`, `theme.ts` | лента фото мест по срезам лет с метками «наше / ≈ не наше»; тема: как в системе, светлая, тёмная, «дерево всегда светлое» |
| `src/app/Lightbox.tsx`, `PersonMap.tsx`, `Badges.tsx` | окно просмотра фото, карта мест человека, значки «сколько материала» |
| `src/app/LangRoot.tsx` | язык — первая часть адреса (`/ru/…`); старые адреса без языка (`people/x.html`, `?lang=es`) — перенаправление |
| `src/app/pages/` | человек, место, источник, главная, «Люди», источники, «Что ещё искать» (`/ru/sources/next`, `data/research.json`), галерея, карта (`MapPage.tsx`), дерево (`Legacy.tsx`), линии жизни на одной шкале (`Lifelines.tsx`, `/ru/lifelines?p=slug1,slug2`) |
| `src/app/notes/` | **заметки для Claude** — только на широком экране (от 1024 точек), без параметров в адресе; `?notes=off` скрывает её в этом браузере, `?notes` — возвращает. Кнопка в шапке открывает панель справа; пока она открыта, у строк линии жизни, фактов, фото, абзацев — «＋», у выделенного текста — «Цитата в заметку»; у фото — меню «убрать / найти лучше / не то место …»; `/ru/review` — разбор всех найденных фото клавишами 1–6. Заметки хранятся в браузере (`localStorage`); «Скопировать для Claude» — текст по людям с номерами и файлами (`model.ts`, `toMarkdown`) |
| `test/app.test.tsx`, `test/schema.test.ts` | разбор текста, загрузка, язык; каждый JSON — по схеме |

Дерево, карта и «кем приходится» получают данные из `index.json`. Биографии, фото, «Места и эпохи», галерею, тексты
источников и заметки считает движок (`site_export.py`, стык `SiteExtras` → `site_data/export.py`, класс `Extras`).
Ни выгрузка, ни сборщик папки не стирают, а обновляют по файлам: стёртую и тут же созданную папку iCloud превращает
в «people 2».
