# Схема данных сайта

Сайт читает данные из JSON: один файл — одна сущность. Эти схемы описывают, какой формы файлы обязаны быть. Выгрузка
(`tools/scripts/site_export.py`) пишет по ним каждый файл, сборщик сайта (`web/scripts/site.mjs`) их читает; тесты `web/` проверяют: не та форма — сборка стоп, с именем карточки и строкой.
Из этих же схем получаются типы TypeScript для `web/src/`, так Python и браузер понимают данные одинаково.

| Файл | Что | Схема |
|---|---|---|
| `data/index.json` | лёгкий список всех: поиск, дерево, «кем приходится», карта | `index.schema.json` |
| `data/people/<id>.json` | один человек: факты, связи, биография по языкам, фото | `person.schema.json` |
| `data/places/<id>.json` | одно место: названия, координаты, государства по годам | `place.schema.json` |
| `data/sources/<id>.json` | один источник: откуда, чей, расшифровка | `source.schema.json` |
| `data/research.json` | «Что ещё искать»: план поиска по предкам (`<папка поиска>/ПОИСК_ДАЛЬШЕ.md` + `ПОИСК_ОНЛАЙН`, `ПОИСК_ОФФЛАЙН`, `ПОИСК_СДЕЛАНО`) | `research.schema.json` |
| `data/progress.json` | «Состояние дерева» (цифры по родам) и «Что нового» (правки по дням — сравнением снимков дерева из git, не из текстов коммитов) | `progress.schema.json` |
| — | общие части: дата, факт, ссылка на источник, фото | `common.schema.json` |

Сканы и PDF — по-прежнему отдельными файлами: проверка входа (`functions/_middleware.js`) закрывает их поштучно,
в JSON у такого файла `private: true`.

## Не изобретали — взяли готовое

| Откуда | Что взяли |
|---|---|
| **GEDCOM X** (FamilySearch, JSON-стандарт, жив) | связи отдельными записями (`parent-child`, `couple`), развод — у пары; у факта `sources` + `confidence`; ссылка на источник с местом в нём (`locator`); лицо на фото — доли `[x1, y1, x2, y2]`; `identifiers` |
| **GEDCOM 7** (FamilySearch, текстовый формат) | даты — ровно как в карточках (`ABT`, `CAL`, `EST`, `BEF`, `AFT`, `BET … AND`, `FROM … TO`); слова источника рядом с датой (`words`, в GEDCOM — `PHRASE`); старый стиль (`calendar: julian`). В GEDCOM X этого нет — поэтому даты не из него |
| **Gramps** и **Wikidata** | место — одна запись, а смена государств — список «годы → государство», а не копия места на каждую эпоху |
| **family-chart** (рисует дерево) | в `index.json` у человека `parents` / `spouses` / `children` — как ждёт библиотека |

Готовой JSON Schema ни у GEDCOM X, ни у GEDCOM 7 нет (общественная схема GEDCOM X брошена в 2018), поэтому схема
своя, с их названиями полей. Упрощения: значения короткие (`high`, а не `http://gedcomx.org/High`), имена по языкам —
одним объектом `{ru, pl, es, en}`.

Своё, чего нет в стандартах: `provenance` (семья / найдено / чужое дерево / вывод проекта) и `reasoning` (на чём
держится вывод) у каждого факта; биография по языкам с пометками «перевод ИИ» и «устарел»; «Линия жизни»; `research`
(приоритет P1–P4, ветки); `stays` — где жил и какое государство там было тогда.

## Откуда берётся каждое поле

| В JSON | В карточке |
|---|---|
| `id` | `cr_id` |
| `identifiers.gedcom_id` | `gedcom_id` без `@` |
| `names.display.ru` / `home` / `aliases` | `name` / `home_names` / `aliases` |
| `sex` | `sex`: `male` → `M`, `female` → `F` |
| `born`, `died` | `born` + `birth_place`, `died` + `death_place` |
| `relationships` | `father_id`, `mother_id`, `spouse_id`, `children_id` (номера, не имена) |
| `research` | `research_priority`, `lineage`, `lineage_by_marriage`, тег `Прямой-предок` |
| `facts[]` | строки «Факты (с источником)»: `- **что:** значение — *источник: [[…]], место · уверенность: …*` |
| `facts[].confidence` / `reasoning` | слово уверенности / текст в скобках после него |
| `facts[].provenance` | `origin` карточки источника; «вывод проекта» в скобках — `inference` |
| `places.states` | раздел «## Государства по годам» карточки места |
| `sources.provenance` | `origin` карточки источника |
